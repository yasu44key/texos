# V1.3.9 閲覧と安全策設計（ダブルクリックの統一・CASライフサイクル・正規化）

検討日: 2026-06-20 / ユーザーとの合意。対象リビジョン **v1.3.9**（現行 1.3.8）。
位置づけ: **オートメーション（v1.5系）に入る前にインターフェイスを固める**ための大型改修。
方針: **制限を先に・緩めるのは後で**（ラチェット）。一度ユーザーが頼った緩さを後から締めると
互換を壊すため、テキスト編集すら明示化からスタートする。ここで妥協しない。

---

## 0. 解決したい不統一

現状、ダブルクリックの意味が「軽い動作」と「重い動作」に割れている:

- 通常ファイルの仮身: ダブルクリック → コミット/マテリアライズ → 実身（編集可能）
- 画像の仮身: ダブルクリック → インラインプレビュー（仮身のまま）
- 動画/PDF の仮身: ダブルクリック → 自動実身化
- フィルタカード: ダブルクリック → 実行

加えて、閲覧のたびに CAS へ再スナップ（旧 `refresh_origin_snapshot`）するため **CAS が肥大**し、
プレビューは画像だけが特別扱いになっている。本改修でこれを一本の原則に畳む。

---

## 1. 貫く原則：ダブルクリック＝閲覧（非破壊）

> **ダブルクリックは、そのカードが「何であるか」を、状態を変えずに覗く。
> 重い動詞（編集／実行）は常に明示。**

- 書類にとっての「何であるか」＝中身 → **インラインプレビュー**
- フィルタにとっての「何であるか」＝定義 → **設定画面**
- いずれも副作用ゼロ・仮身のまま・CAS を太らせない・勝手に実身化しない

### メニューの形（全カード共通の2階建て）

**先頭＝ダブルクリックの動作（覗く）、2番目＝そのカードの重い動詞。**

| カード種別 | ダブルクリック（=メニュー先頭） | 明示の動詞（メニュー2番目） |
|---|---|---|
| 書類（テキスト/画像/PDF/動画/音声/未知） | 閲覧（インラインPV、無ければ一時的閲覧で読取専用） | 編集（コミット→実身） |
| フィルタ/コマンド | 設定を開く | 実行 |
| URL | 開く | 編集（URL変更） |
| プロジェクト📁 | 入る | — |
| 付箋（注釈・例外） | 編集（直接編集を維持） | — |

補足:
- **フィルタカードの面に小さな ▶実行 ボタン**を置く。実行はフィルタの存在理由なのでメニュー奥
  だと遠い。「ダブルクリックでは誤爆しない／面のボタンで一発」を両立する。
  副次効果として gcc 等が誤ダブルクリックで走らない安全性も得られる。
- **インラインの「閲覧→編集」遷移＝コミット（実身化）の瞬間**に全種別で統一する。
  既定は読取専用プレビュー、「編集」ボタンでマテリアライズして編集モードへ。
- **テキストも最初は明示編集**（既存の InlineTextEditor を既定読取専用化＋「編集」ボタン）。
  緩めるのは後でいつでもできる。
- **付箋は実身/仮身の対象でない一級市民の注釈**なので、直接編集の例外を維持する。
  ここまで明示化すると軽さが死ぬ。

### 「統一」の正直な範囲

「同一コード経路」ではなく **「ダブルクリックは決して副作用を起こさない・勝手に実身化しない」**
というレベルで通す。付箋＝編集・URL＝開く・プロジェクト＝入る、は非破壊の自然な「開く」として
妥当な例外であり、ここを曖昧にしない。

### 一時的閲覧の安全策（黙殺しない）

インラインPVが無い種別は **一時的閲覧**（OS一時フォルダにライブ内容を読取専用で開く）にフォールバック。
閉じる時に temp の mtime/ハッシュが変わっていたら **黙って捨てず**、
**「閲覧中に編集されました → コミットして実身にしますか／破棄しますか」** を提示し、
実身化フローに合流させる。事故をデータ喪失でなく実身化に変える。

## 2. CAS ライフサイクル：「仮身あたりブロブ1個・閲覧は書かない」

> **仮身が持つ CAS ブロブは常に最大1個。閲覧では絶対に書き込まない。
> 実身化のときだけ“差し替える”。**

「スナップショット一つに限定」＝**累積しない（追記でなく置換）**。古いブロブは参照ゼロになり、
正規化コマンドが掃く。

### 解決順（閲覧・実身化・消失）

| 状況 | 何を映す／何をするか | CASへの書き込み |
|---|---|---|
| 閲覧（ダブルクリック） | まず origin_path のライブを読む。無ければCASブロブ。 | **なし**（肥大しない） |
| 元データ消失・CASも無い | 「窓喪失」表示（薄赤）。割り切り。 | なし |
| 実身化（明示） | ライブが生きていれば**その時点を1個コピー**してCAS差し替え→実身化。消えていればCASブロブから実身化。 | 1個（古いのは孤児化） |
| 閲覧中に外部編集して閉じた | 黙殺せず「コミットして実身に？」を提示＝実身化に合流 | 提示後のみ |

### スナップ取得タイミング：**モデルA（取り込み時スナップ・サイズゲート）** 採用

- **小さいファイル**: ドロップ時点で1個スナップ（最初から保険あり）。
- **大きい動画/3D/画像（閾値超）**: **窓のみ**で取り込み、実身化で初めてスナップ。
  → 割り切り（元データ消失＝喪失）は **大物に限定**される。
- 閾値は **サイズ既定 ＋ カード個別オーバーライド**（「この仮身は常に保持／保持しない」）。
  サイズでは測れない価値（編集中の小さめ3D等）を逃がせる。

### 副作用：薄赤の意味が変わる

閉じるたび再スナップ（旧 `refresh_origin_snapshot`）を**やめる**ので、
薄赤＝「最後に見た状態」→ **「取り込み／最後の実身化時点」** に変わる。
CAS フォールバック表示時は **「元ファイル消失：◯◯時点の内容」** と日時を明示し、
古いコピーを最新と誤認して実身化するのを防ぐ。

## 3. 正規化コマンド：プロジェクトを「今の最新」で確定し不要物を捨てる

> **改訂（2026-06-26・`docs/共有とモジュール設計.md §3.2`）**: 本節の重い正規化は **GC に縮退**
> （後方互換が踏襲されてきたため大移行＝リフレッシュ・履歴手放しは実運用上不要と判断）。
> 残すのは **孤児CAS／不要キャッシュの掃除のみ**。以下は当初設計（履歴）として残す。

単なる孤児GCではなく **「最新へ確定 → 履歴を手放す → 孤児を回収」** の封印操作。
**このコマンドは元に戻せない。**

### なぜ「最新へ確定（リフレッシュ）」を含めるか

リフレッシュ無しで掃くと「最新は origin にしか無く、CAS には古いスナップが残る」状態を
“正規化済み”と誤認しかねない。**先に全仮身を最新に取り直すから、その後で掃くものが
本当に死んでいると保証できる。** これはGCの正しさの前提条件であって、便利機能ではない。

### 4ステップ（順番が重要：リフレッシュは必ず最初）

リフレッシュは古いスナップを孤児化するので、掃き出しの**後**にやると掃いた直後に新ゴミが出る。
よって先頭に置く。

1. **リフレッシュ（全仮身を一度閲覧した状態に）**
   各仮身 → ライブ origin を読み、変化があれば CAS に1個取り直して差し替え。
   - **サイズ閾値を尊重**（大物は既定スキップ＝窓のまま）。CAS肥大の出戻りを防ぐ。
   - origin が変わっていなければ CAS 重複排除で**新ブロブもゴミも出ない**（無変化プロジェクトでは実質タダ）。
   - **origin 消失の仮身はスキップして既存スナップを保持**。レポートに
     「◯件は元データ消失のため取り込み時点のまま」。
2. **ゴミ箱を空に**（X日より古い／全部）
3. **UNDO/REDO履歴を切り詰め**（ここで過去の編集が物理的に手放される）
4. **孤児CASをまとめて掃く**（1〜3で解放された全ブロブを一括回収）

### 到達可能性（=残す）：GCが壊してはならない参照

孤児判定は「参照ゼロ」だが、以下を **到達可能（生存）** として数えること。
特に UNDO スタックと trash は『復活の呪文』の土台なので、ここを誤ると復元が壊れる。
逆に言えば、正規化こそが UNDO履歴とゴミ箱を**本当に手放す唯一の場所**。

- 生きた仮身の `cas_hash`、コミット済み実身
- **フォーク解決チェーン（fork_source_cas／親）**
- **UNDOスタック（`meta.ui_undo_stack`）が指すブロブ**
- **trash 内（`deleted_at` / `.texos/trash`）のブロブ**

### 安全策（破壊的だからこそ）

- **dry-run 必須**（既存 `commit_all` と同方式）。「解放サイズ／失う復元ポイント数」を提示。
- **どの仮身が“内容が変わる”か（origin が現スナップと差分あり）を一覧表示**。
  意図しない上流の変更が恒久的に焼き込まれる前に、ユーザーが見られるようにする。
- **「先にフォークして退避する」ボタン**を1クリックで提供。
  フォークは構造＋CASを丸ごと現状コピー＝完全な“元に戻す”。民間伝承にせず明示する。
- **各ステップはチェックボックスで個別ON/OFF**（リフレッシュだけ・掃除だけ、を選べる）。
  既定は全部ONの「最新で確定」。
- **大物の実体化はオプトイン**：「重いファイルも実体に取り込む（自己完結化）」を別チェックで。
  プロジェクトをフォルダごと配布・退避するアーカイブ用途のときだけ使う。
- **自動実行はしない・プロジェクト単位**。CAS は `.texos/cas` でプロジェクト閉域なので掃除も閉域。

## 4. 実装メモ（着手時に詰める）

- ダブルクリックのルーティングを全カードで「閲覧（=メニュー先頭）」へ一本化。
  既存の InlineTextEditor / ImagePreview / AudioPlayer / MediaPreview(PDF・動画) を
  **読取専用既定**に揃え、「編集」ボタン＝マテリアライズ点に統一。
- 一時的閲覧（`view_temp` 系）を未対応種別のフォールバックに格下げ位置づけ、
  閉じる時の差分検知＋コミット提示を追加。
- `refresh_origin_snapshot` の「閲覧ごと再スナップ」を撤去し、スナップは
  実身化時／正規化リフレッシュ時のみに集約。サイズ閾値＋個別オーバーライド列を追加。
- 正規化コマンド（仮称 `normalize_project`）: dry-run レポート → 差分一覧 → フォーク退避 →
  リフレッシュ → trash 空 → undo 切詰め → 孤児掃き。到達可能性の参照集合を正確に。
- バージョンは3か所 1.3.9。`npx tsc --noEmit` / `cargo test` 通過を確認。
  実機確認チェックリストは `docs/NEXT_SESSION.md` 先頭に。

## 5. オートメーション（v1.5系）への含意

ダブルクリック＝非破壊・実行は明示、という契約が固まることで、
プロセスコントロールカード／ビジュアルコマンドが「副作用は常に明示の動詞から」という
同じ規律の上に乗れる。本書のインターフェイス契約を v1.5 の前提とする。
