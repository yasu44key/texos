# TexoS カード化プログラム 作成規約（AI 依頼用 指示書）

> **これは何か**: 外部プログラム（Python・実行ファイル・スクリプト）を TexoS の
> **フィルタ／ジェネレータ・カード**として搭載するための入出力規約。AI に
> 「TexoS で使える○○プログラムを書いて」と依頼するとき、**この文書をそのまま添付**する。
> 起動後の処理は自由。ただし**入力と出力のインターフェースだけはこの規約に必ず従うこと**。
>
> 初版 2026-07-15（`feat/v1.6-cards`）。正本。背景＝`docs/V1.6_カード拡張SDK検討.md` §10。
> 模範実装＝`I:\ChillChordMaker\cli_render.py`（ヘッドレス WAV レンダラ）。

---

## 0. 大原則 — 「起動後は自由、入出力は規約」

TexoS はプログラムを **1回起動 → 出力ファイルを読み戻す → キャンバスにカードとして置く**、
という UNIX パイプライン型の実行モデルで動かす。だから守るべきは2点だけ:

1. **入力は TexoS が用意した一時ファイル**から受け取る（自分で入力を探しに行かない）。
2. **出力は TexoS が指定したパス**へ書く（自分で保存先を決めない・保存ダイアログを出さない）。

この2点さえ守れば、中でどんな計算・生成をしようと自由。GUI を持ってもよいが、
**カード化する経路は必ずヘッドレス（無人・非対話）で完結**させること。

そしてこの2点を**検証可能**にするための構造規約がもう1つ:

3. **入出力（ファイルの読み書き）はエントリファイル（main）に集約する**。
   他のモジュールはファイルを開かない・書かない — バイト列やオブジェクトを
   受け取って返す**純関数（エンジン層）**にする。

> **なぜ main 集約か**: 複数モジュール構成のプログラムは、出力箇所が散らばると
> 「本当にどこで書いているか」をプログラム全体をトレースしないと確認できない。
> ChillChordMaker が実例 — 書き出しが `audio_io.py`（WAV）・`preset.py`（JSON）・
> `gui.py`（保存ダイアログ）の**3か所**に散らばっており、規約遵守の監査が困難だった。
> main に集約されていれば、**エントリファイル1本を読むだけ**で
> 「入力は `{in}` から・出力は `{out}` へ・他は書いていない」を確認できる。
> レビューする人にも、導入する TexoS ユーザーにも、AI にとっても検証が一瞬で済む。
>（設計論で言う「関数コア・入出力殻」— 計算はコア＝純関数、入出力は殻＝main）

> **なぜ ChillChordMaker はそのままでは載らなかったか**（典型例）:
> 本体は tkinter GUI で、書き出しが「名前を付けて保存」ダイアログだった。
> ダイアログはユーザーが任意の場所に書くので TexoS は出力を拾えない。
> → **GUI とは別に、規約準拠のヘッドレス CLI アダプタ（`cli_render.py`）を1本足す**のが解。
> エンジン層（純粋計算）が分離されていれば、アダプタは数行で済む。

## 1. 3つのモード — どれで作るか

カードの実行種別（`type`）は3つ。作るプログラムがどれに当たるかを最初に決める。

| モード | `type` | 入力 | 用途 | 例 |
|---|---|---|---|---|
| フィルタ | `filter` | あり（1本） | データを変換する純関数 | 画像リサイズ・テキスト整形・音声変換 |
| コマンド | `command` | あり（複数可） | 引数でファイルを受け取るツール | ffmpeg・ImageMagick・whisper |
| ジェネレータ | `generator` | **なし** | 入力なしで出力を生む | 乱数・シンセ音・レンダリング |

- `filter` と `command` の違いは**入力の渡し方だけ**（後述）。中身は自由。
- **入力を持たないなら必ず `generator`**。ジェネレータは入力矢印なしでも実行できる。

## 2. 入力規約

TexoS は入力カードの中身を**一時ファイルに書き出し**、そのパスをプレースホルダで渡す。
プログラムは**渡されたパスまたは標準入力から**読む。

### プレースホルダ（TexoS が実パスに置換）

| 記法 | 意味 |
|---|---|
| `{in}` | 1番目の入力ファイルのパス |
| `{in1}` `{in2}` … `{inN}` | N番目の入力（複数入力を個別に扱う＝**集約**モード） |
| `{in*}` | **全入力**をスペース区切り・各個クォートで展開（可変長ツール向け＝集約モード） |

- `{in2}` 以降または `{in*}` を使うと、そのカードは「全入力を集めて1回実行」（集約）になる。
  `{in}` / `{in1}` だけなら「入力1本ごとに実行」（ファンアウト）。
- 対応する入力矢印が足りないと**実行前にエラー**（`{inN} に対応する入力がありません`）。

### 渡し方（2通り・どちらもプログラム側で対応できると強い）

- **標準入力リダイレクト**（filter 型の作法）: カード定義の CMD が `prog < "{in}"` の形。
  プログラムは **stdin から読む**。
- **引数**（command 型の作法）: CMD が `prog --in "{in}"` の形。プログラムは**引数のパスを開く**。

### 禁止・注意

- **標準入力は既定で閉じている**（EOF が即来る）。`input()` 待ちのような**対話プロンプトは禁止**
  （応答が来ずタイムアウトで強制終了される）。無人で完結させること。
- 入力の**文字コード・拡張子を仮定しない**。必要なら CMD 側で拡張子を制約する。

## 3. 出力規約（最重要）

TexoS は出力先の**一時ファイルパスを生成**してプレースホルダで渡す。
プログラムは**必ずそこへ書く**。TexoS は実行後にそのファイルを読み戻してカード化する。

| 記法 | 意味 |
|---|---|
| `{out}` | 出力ファイルのパス（拡張子つき）。**ここに1個書く。** |
| `{out_noext}` | `{out}` から拡張子を除いたパス。ツールが拡張子を自分で付ける場合に使う（例: whisper の `-of <base>` → `<base>.txt` が `{out}` と一致するよう `output_ext` を合わせる）。 |
| `{out*}` | **出力フォルダ**のパス。複数ファイルをここへ書く（1ファイル＝1カード）。作法は §6。 |

### 出力の作法

- **単一成果物は `{out}` 一択**。標準出力（stdout）に**バイナリを吐かない**
  （Windows で壊れる）。テキストでも、確実なのはファイル書き出し。
- 出力の**種類は拡張子で決まる**（TexoS が `output_ext` から MIME を判定してカードの見た目を選ぶ）。
  `.wav`→音声プレイヤー、`.png`→画像、`.md`→テキスト、等。**正しい拡張子の `output_ext` を宣言**する。
- **「呼ぶだけ」で出力の無いプログラム**（カメラ起動・読み上げなど）は CMD に `{out` を**書かない**。
  TexoS は出力ゼロを正常とみなしカードを作らない（fire-and-forget）。

### キャンバス配置と 実身／仮身（プログラム作者は意識しなくてよいが、規約として明記）

TexoS は `{out}` を拾って**キャンバスにカードを1枚置く**。置き方は TexoS 側の設定で決まる:

- **出力先フォルダ指定なし** → 成果物を**プロジェクト直下にコミット＝実身**（プロジェクトが中身を持つ）。
- **出力先フォルダを外部に指定** → その場所に書き出し、**外部ファイルへの窓＝仮身**として登録
  （プロジェクトはパス参照だけ持つ）。

→ **プログラム側は常に「渡された `{out}` に書く」だけでよい**。実身になるか仮身になるかは
TexoS が決める。プログラムが保存先を選んではならない（これが「保存ダイアログ禁止」の理由）。

---

## 4. 終了コードとエラー

- 成功したら **exit 0**、失敗したら **非0**。TexoS は非0を失敗として扱う。
- **エラーメッセージは stderr へ**（TexoS が先頭〜500字を拾ってカードのエラー表示に使う）。
- 標準出力（stdout）は**カード化に使われない**（捨てられる）。ログは stderr に出す。

## 5. 模範実装（ChillChordMaker `cli_render.py` の骨子）

エンジン層（純粋計算）だけに依存し、GUI・realtime 依存を持ち込まない。
`--in`（省略可＝既定動作）と `--out` を持つ。stdin も受けられる。
**ファイルの読み書きはこのエントリファイルだけ**が行い、エンジン層はパスを知らない（§0-3）。

```python
import argparse, sys
# ... 純粋な計算・生成エンジンだけ import（GUI/音声デバイス等は import しない）

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--in",  dest="inp", default=None,  # 省略/'-'=stdin/既定
                    help="入力ファイル（'-' で stdin）")
    ap.add_argument("--out", dest="out", required=True,  # {out} が渡ってくる
                    help="出力ファイルパス")
    a = ap.parse_args()
    try:
        data = read_input(a.inp)          # None なら既定・'-' なら stdin
        result = process(data)            # ← ここは自由
        write_output(a.out, result)       # ← 必ず a.out へ書く
        print(f"OK: {a.out}", file=sys.stderr)
        return 0
    except Exception as e:
        print(f"ERROR: {e}", file=sys.stderr)  # エラーは stderr
        return 1                                # 失敗は非0

if __name__ == "__main__":
    sys.exit(main())
```

実物全体は `I:\ChillChordMaker\cli_render.py`。実機で `run_external` から駆動・WAV 読み戻しを確認済み
（`flow::tests::chillchord_generator_produces_wav`・green）。

## 6. `{out*}`（複数出力）の作法 — v1.6 で対応済み

`{out*}` は **TexoS が用意した出力フォルダのパス**に置換される。プログラムはそこへ
**好きな名前で何ファイルでも**書いてよい。TexoS は終了後にフォルダ内の全ファイルを
収集し、**1ファイル＝1カード**としてキャンバスに置く（縦に並ぶ）。

- **順序規約**: 収集は**ファイル名の辞書順**。順序が意味を持つ出力（曲の進行・ページ・
  フレーム等）は**ゼロ詰め連番**で名前に順序を埋め込むこと。
  例: ChillChordMaker の `t_01_1_Dm7.wav → t_01_3_G7.wav → t_02_1_CM7.wav`（小節_拍_コード名）。
- **カード名はファイル名の語幹**がそのまま使われる。意味のある名前を付ければ
  キャンバス上でそのまま読める（`Dm7` のように）。名前もプログラムの出力の一部と心得る。
- **種類はファイルごとの拡張子**で決まる（混在可: wav と txt を一緒に出してもよい）。
- 1つも書かずに正常終了するとエラー（「{out*} フォルダに出力がありません」）。
  出力ゼロが正常のプログラムは §3 の fire-and-forget（`{out` を書かない）にする。
- `{out}`（単一）と `{out*}`（複数）は**どちらか一方**を使う（併用しない）。
- サイズ上限（512MB）は**フォルダ合計**に適用される。

**単一成果物なら `{out}`、複数なら `{out*}`** — 迷ったら「1回の実行で成果物がいくつか」で選ぶ。

## 7. カード定義（`filter_ref` JSON）の例

プログラムを載せるカードの定義。CMD にプレースホルダを書く。`name`＝実行するプログラム
（`.texos\filters` 同梱名 or PATH）、`cmd`＝引数テンプレート、`output_ext`＝出力拡張子。

**ジェネレータ（入力なし・WAV 生成）**:
```json
{
  "type": "generator",
  "name": "python",
  "cmd": "\"I:\\ChillChordMaker\\cli_render.py\" --out \"{out}\"",
  "output_ext": "wav"
}
```

**フィルタ（preset JSON を入力 → WAV）**:
```json
{
  "type": "command",
  "name": "python",
  "cmd": "\"I:\\ChillChordMaker\\cli_render.py\" --in \"{in}\" --out \"{out}\"",
  "output_ext": "wav"
}
```

**標準入出力フィルタ（stdin/stdout リダイレクト型ツール）**:
```json
{ "type": "filter", "name": "sort", "cmd": "< \"{in}\" > \"{out}\"", "output_ext": "txt" }
```

**複数出力（進行 JSON を入力 → コードごとの WAV 群 = `{out*}`）**:
```json
{
  "type": "command",
  "name": "python",
  "cmd": "\"I:\\ChillChordMaker\\cli_render.py\" --in \"{in}\" --outdir \"{out*}\"",
  "output_ext": "wav"
}
```

## 8. AI への依頼プロンプト・テンプレート（コピペ用）

> 以下の「TexoS カード化プログラム作成規約」に**厳密に従って** Python プログラムを書いてください。
> 目的: 〔ここに作りたい処理を書く。例: 「1枚の画像を受け取り、8bit 風に減色して返す」〕
>
> **必須の入出力インターフェース**:
> - モードは 〔filter / command / generator のどれか〕。
> - 入力: `--in <path>`（`'-'` で stdin から / 省略時は 〔既定動作 or エラー〕）。〔generator なら「入力なし」〕
> - 出力: 〔単一なら〕`--out <path>` に**必ず1ファイル書き出す** ／
>   〔複数なら〕`--outdir <dir>` に**ゼロ詰め連番＋意味のある名前**で書き出す（辞書順＝順序）。
>   標準出力にバイナリを吐かない。
> - 出力の拡張子は 〔.png / .wav / .txt 等〕。
> - 成功で exit 0・失敗で非0、エラーは stderr。**対話プロンプト（input待ち）を出さない**（無人実行）。
> - GUI の保存ダイアログや、保存先をプログラムが決める処理を**入れない**（TexoS が渡す `--out` に書く）。
> - **ファイルの読み書きはエントリファイル（main）に集約**。他のモジュールは open/write を
>   持たず、バイト列・オブジェクトを受け渡す純関数にする（main を読むだけで入出力を監査できる形）。
> - 依存ライブラリを requirements として列挙。GUI/音声デバイス等、計算に不要な依存は持ち込まない。
>
> （この規約文書 `カード化プログラム作成規約.md` を全文添付）

## 9. チェックリスト（レビュー用）

- [ ] 入力は `--in`（or stdin）から受け、自分で探しに行かない
- [ ] 出力は `--out`（＝`{out}`）に**1ファイルだけ**書く
- [ ] **ファイルの読み書きがエントリファイルに集約**されている（他モジュールに open/write が無い
      — main だけ読めば入出力を監査できる）
- [ ] stdout にバイナリを吐いていない／保存ダイアログが無い／保存先を自分で決めていない
- [ ] `input()` 等の対話待ちが無い（無人で完走する）
- [ ] `output_ext` と実際に書く拡張子が一致
- [ ] 成功 exit 0／失敗 非0、エラーは stderr
- [ ] 計算に不要な重い依存（GUI・realtime 音声等）を import していない
- [ ] （複数出力の場合）`{out*}` フォルダへ書き、**ゼロ詰め連番＋意味のある名前**を付けている
      （辞書順＝意図した順序・語幹がカード名になる）
