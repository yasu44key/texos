## 1. 実施した変更（コミット単位）

### コミット1 `refactor(flow): ノード種別判定の集約と外部実行の結果型を導入`（flow.rs）
- **§4.2**: `enum NodeKind { Generator, Ai, Builtin, External, Invalid }` ＋
  `FilterSpec::node_kind()` / `is_aggregate()` / `is_shell()`。
  これまで `eval_filter`／`run_flow` に散在していた実行種別の判定
  （`filter_type=="generator"`・`builtin` 有無・`builtin=="ai"`・`name`/`cmd` 有無・
  `cmd_is_aggregate`・`shell`）を1か所へ集約。判定順序は現行と完全一致。
  - 注: 対話シェルは終端カードのみ run_flow が特別扱いする概念なので、連鎖評価の
    分類（NodeKind）には含めない＝ execute_node 側の分類は旧 eval_filter と完全一致。
- **§4.1（結果型）**: `run_external_cwd` を `run_external_full(→ExternalOutput)` ＋
  薄いラッパに分割。完走したプロセスの **exit code・stderr 抜粋・出力バイト列を捨てずに
  持ち上げる**。成否ポリシー（非0→エラー／出力なし→エラー）は `ExternalOutput::into_bytes()`
  に閉じ込め、旧契約（`run_external_cwd`）は同一文面のまま。
- テスト: `node_kind_classification` / `is_aggregate_only_for_external` /
  `is_shell_detection` / `external_full_captures_nonzero_exit_code` /
  `external_full_captures_success_and_output` を追加。

### コミット2 `refactor(flow): eval_filter のディスパッチを execute_node へ一本化`（lib.rs ＋ flow.rs）
- **§4.1**: generator／集約external／個別(builtin/ai/external) の3分岐に散っていた実行を
  `execute_node(p, spec, NodeKind, inputs) -> NodeRun` の**単一エントリ**へ統合。
  `eval_filter` は「入力収集（pull再帰）＋型チェック＋命名(stem)」に専念し、実行を委譲。
- `NodeRun { outputs, exit_code, stderr }`: payload に加え外部プロセスの exit/stderr を
  持ち上げる（§4.3 の土台。現状 eval_filter は未消費＝`#[allow(dead_code)]`）。
- `run_flow` 終端のシェル判定を `is_shell()` に集約（§4.2）。
- 旧 `run_external`/`run_external_cwd` は exit code 不要向けの互換ラッパとして温存
  （現状テストが利用）。

### コミット3 `docs/chore: 2レーン境界コメント＋拡張点アンカー`
- **§4.3**: `eval_filter` の flow 矢印収集箇所に「将来 kind='flow' に成功時/失敗時/常に
  を持たせ NodeRun.exit_code で分岐」する拡張点コメント。
- **§4.4**: フローレーン関数群（FlowReport〜run_flow〜ライブラリ）の先頭に境界バナー。
  `flow_run.rs` への切り出し候補・ライブラリの部分グラフ一般化の余地を明記。
- 本計画書を起票。

## 2. 不変条件（このリファクタリングの安全網）

- **serde 後方互換**: `FilterSpec` のフィールドは増減なし。filter_ref JSON は不変。
- **挙動不変**: 出力カードの生成・命名（prefix連番／固定名上書き／入力名_フィルタ名）・
  出力フォルダ（origin仮身 vs コミット実身）・skipped/errors の文面・録音 stdin チャネル・
  集約/ファンアウトの判定・循環検出・cancel/timeout/出力上限はすべて従来どおり。
- **テスト**: `cargo test --lib` 緑（26 passed, 3 ignored=ライブOllama）。新規警告なし。

## 3. この土台の上に v1.5 が載せるもの（塞がれていないことの確認）

- **exit code 分岐**: `NodeRun.exit_code` ＋ §4.3 アンカー → relations の制御属性。
- **モジュール（部分グラフ）**: `execute_node` は既に「部分グラフの1ノード実行」。
  境界つき部分グラフの実行は execute_node を束ねる上位ループとして載る。
- **依存宣言・パラメータ**: `NodeKind` に種別が揃ったので、種別ごとの依存解決
  （外部プログラム・AIエンドポイント）を宣言として持たせる余地ができた。
