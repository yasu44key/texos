## 1. 現状の総括

開発方針（[[feedback-texos-dev-style]]）どおり、**実験リビジョンを 1.3.x で細かく刻み**、
使いながらバグを取ってきた。1.3.3〜1.3.11 で積み上がった機能群は実機で要件を満たすことを
確認済み。次は **これらをまとめて「安定版 v1.4.0」として確定する**段階に入る。

### v1.3.x で積み上げた主な機能（安定版ロールアップ対象）

- **オートフロー（v1.3.3〜）**: フィルタカード＝UNIXパイプラインのGUI再来。内蔵フィルタ
  （grep/置換/画像リサイズ・変換）＋外部プログラムフィルタ（{in}/{out}・連番・ドロップ
  ポイント・自己拡張ループ）。
- **クリップボード双方向（v1.3.4/1.3.8）**: CF_HDROP（ファイル持ち出し）＋CF_DIB（画像）。
- **用語統一・メニュー再編（v1.3.4〜1.3.7）**: 実身/仮身に統一、ツールチップ、テーマ追従、
  マウスモデル刷新。
- **窓モデル（v1.3.9/1.3.10）**: 仮身は相手の実身カードを ID（window_of）で指す。内部/外部
  2レーン分離、重複実身防止、TexoS内リネーム、実体喪失の再リンク。
- **アイデアメモ6-23（v1.3.11、A・C・B・D・E）**: ビルトインフィルタ階層化／並び維持の格子
  整列／借用元プロジェクトを開く／内部D&D=実身・新規ファイル重複バグ根治／新規ファイル作成／
  フォルダ切れ薄赤＋リンク張り直し／オフィスのインラインプレビュー（docx=mammoth・
  表計算=SheetJS・pptx等=LibreOffice→PDF）／音声・動画の簡易編集（ffmpeg）。
- **ランチャー＆フィルタ拡充（v1.3.11）**: ランチャーカード（GUI/cmd/PowerShell・{in}・保存→
  新実身・インストール済みアプリ選択・ランチャーライブラリ）／対話シェルフィルタ（一行目
  設定可・{in}）／フィルタの制限時間 0=無制限（開発者モード）。

## 2. v1.4.0 の位置づけ（＝安定版確定）

**v1.4.0 は新規大型開発ではなく、1.3.3〜1.3.11 のロールアップを実機で詰め切ってバグを取り、
「安定版」として確定する号**（dev 方針: 実験 1.3.x → 安定 1.4）。

ゲート: **「UI とシステムが固まってから V2.0（AI/MCP）へ」**。このゲートを 1.4.x で綺麗に閉じる。
v1.5 系（オートメーション本線）は安定版確定の後に着手する。

> **改訂注記（2026-06-26）**: このゲートは「AI も含めて V2.0」を前提にしていたが、AI は既に
> v1.4 系で内側に入った。改訂後のゲートは **「UI とシステムが固まってから V2.0＝MCP 対外公開
> ／ウィジェット・サンドボックスへ」**。AI モジュール（ローカル AI／外部モジュール取り込み）は
> v1.4.x〜v1.5 の現役テーマ。v1.4.x は実用段階のブラッシュアップ（「コップ→ボトル」の自然な拡張）。

## 4. 今後の課題（v1.4.0 の後）

> **改訂（2026-06-26・正本は `docs/アイデアメモ検討結果_0626.md` §3）**: AI を V2.0 から
> 現在地へ引き上げた結果、区分を組み替えた。v1.5 系の主役は「オートメーション＋**モジュール
> カタログ（外部部品の取り込み）**＋**プロジェクト間共有**」。V2.0 は **MCP 対外公開**と
> ウィジェットに焦点（AI は既に内側にあるので「外向き公開」が残課題）。

### v1.5 系 — オートメーション／モジュール拡充（★次の主役。設計: `docs/オートメーション設計メモ.md`）
- **プロセスコントロールカード（#2 フル版）**: v1.3.11 のランチャーが素地。**exit code に
  よる制御フロー（分岐）**で、キャンバスがビジュアルなシェル/Makefile/CI に。Stop 常設＋
  「実行中プロセス」一覧パネル（detached でもハンドルを失わない）。**強制終了の確実化＝
  Windows Job Object 化**（アイデアメモ0626 ④。`taskkill /T` の取りこぼし＝孫の再ペアレントを根治）。
  常駐・対話プロセスは後送り。
- **ビジュアルコマンド**: 図形＝スコープ＋プロセスコントロール＝領域内カードへ空間的 foreach。
- **モジュールカタログ（新・方針①）**: ffmpeg/pandoc/gcc/whisper.cpp 等の「取り込めるレシピ集」。
  `filter_library.json`/`launcher_library.json` の延長。未導入は 1.4.6 の Ollama 案内と同型。
- **共有は2レーンに分けて設計**（2026-06-26 再整理・正本 `docs/共有とモジュール設計.md`）:
  - **データレーン（中身の共有）**: `origin` 仮身を**跨プロジェクト**に開く（外部レーン再利用・
    実体は元に残り向こうは窓）。＝旧「アイデアメモ0626 ②エクスポート」は**独立機能としては不要化**し、
    これに一本化。Pic Up / Drop On（OLE）は従来どおり V2.0。
  - **フローレーン（構造の共有）＝フローモジュール**: 複数カード＋矢印の**部分グラフ**を名前付き
    部品として保存・再配置・共有。図形スコープ（境界）／ライブラリ（保存）／跨プロジェクト（移送）／
    制御フロー（実行）は**同じ概念の別の顔**＝co-design する。現 `filter_library`/`launcher_library`
    （単一カードのみ）を部分グラフへ一般化。
  - **具体的操作仕様が確定**（2026-06-28・ショートカット検討の副産物・`docs/共有とモジュール設計.md §7`）:
    `Ctrl+C`＝仮身コピー／`Ctrl+V`＝**別プロジェクトに切り替えて貼ると跨プロジェクト仮身**（データ
    レーンの具体UI）、OSエクスポートは右クリック「実体をクリップボードにコピー」へ移設。選択フロー
    右クリック「名前を付けて実身をライブラリ化」＝部分グラフ＋同梱実身（フローレーンの具体UI・実身は
    プロジェクト内保持）、`Ctrl+B`＝実身化して貼り付け。プロジェクト境界をまたぐ矢印は張らない方針。
- **stdin/stdout カード・プログラムのフィルタ化・フィルタライブラリ強化**（この系列に吸収）。

### V2.0 — 大型課題（`docs/V2.0課題.md`）
- **MCP 対外公開**（UI とシステムが固まってから）: TexoS のフィルタ／プロセスコントロールを
  MCP ツールとして外へ公開する形（基盤が先・公開は後）。「AI が並べてくれる」体験は、まず
  MCP 抜きで **AI カードがフロー定義を出力 → TexoS が配置**（0626 検討 §2-D）で先に実現可。
- **サブプロジェクト本実装＋ OLE ピックアップ**（カード→他アプリのドラッグアウト）。
- **カードのグループ化／コンテナ**、**キャンバス内ウィジェット**（Wasm/サンドボックス）、
  **Wasm コーデック編集子の公開 API**。

## 5. リリース手順（毎回共通・再掲）

1. dev 停止 → `npx tsc --noEmit` → `cargo check` / `cargo test`
2. バージョン3か所更新: `package.json` / `src-tauri/tauri.conf.json` / `src-tauri/Cargo.toml`
3. `npm run tauri build` → `src-tauri/target/release/bundle/nsis/texos_x.y.z_x64-setup.exe`
4. インストーラーを `I:\` へコピー、`docs/更新履歴.md` に追記
5. デスクトップショートカット `F:\Desktop\TexoS.lnk` は release exe を指すので再ビルドで自動追従
