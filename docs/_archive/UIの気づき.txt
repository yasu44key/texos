問題点：
プロジェクトフォルダ内の実身を再度キャンバスに取り込んだ際、2つの実身カードが同じ実体を指すことになる。これはまずい。片方の実身を削除した時に、もう片方の実体も消えてしまう。外部ファイルの場合。仮身の場合は赤シグナルで、字ssんかして保全できるが、この場合この分類にあたらない。
１．プロジェクトフォルダ内の実身をキャンバスに登録する際にすでに登録されているかどうかをチェックして、2回目以降の登録は仮身とする。
２．登録の際のチェックは無い。プロジェクトフォルダの実身の実体が消えている場合。現在はファイルが無いことのエラー表示と共に、CASからの復活を試みる（大きなロールバックが生じる）
３．実身を削除する際、同じファイルを指す実身がないかチェックする。存在する場合は、カードのみ削除する。
４．同じプロジェクト内の仮身を編集したいとき、実身化せずに元のファイルがプロジェクト内に存在しているからそてぃらを編集するように促す（実身カードにフォーカスする）

解決策の糸口：
１．同プロジェクト内の実体を2つ以上の実身として登録させない（このシステムの根幹にかかわるため）
２．同プロジェクトの中で仮身を編集したくなったときは、仮身元の実身にフォーカスする（参照元にフォーカスコマンド）、編集後、元のビューに戻る（ビューの履歴記録が要るかもしれない）
３．２の応用で、他のプロジェクトからの借用で仮身を作成できる。借用元のカードの仮身をクリップボードにコピー編集中のプロジェクトに貼り付けできる。これは、（参照元にフォーカス）でプロジェクト間移動も現実味が出てくる。（前のビューに戻る）でも元のプロジェクトの位置に戻り仮身を張り付ければ、プロジェクト間の情報共有が可能となる。


ユーザビリティーの視点（ファイル名の連番問題）
同プロジェクト内の実身に仮身を追加して仮身を実身化する場合、OSの仕様で　FILE >FILE(1) >FILE(2)と後ろにコピーである番号が付きます。これは後で名前を付け替えたくなります。名前を付け替えるとまた、実体のファイルがなくなってしまいます。できればTexoS内からファイル名を変更できるとよいと思います。TwxoS内ならCASの変更もデータベースの変更も安全にできるからです。

２．は、間違った古いフォーマットでプロジェクトキャンバスが構築されており、実身であるのに、実体のファイルが失われている場合です。新フォーマットになっても、ユーザがー意図的に現在のプロジェクトフォルダのファイルをリネーム、削除フォルダ移動などをすると起こりえます。このときの対処方法を考えねばなりません。もともとぷrジェクトのフォルダ内はフラットで、フォルダ分けをして、後からファイル移動には対応していません。最低限の保護をする方法の一つとして考えていました。CASから復元するゟ「このファイルは実態が失われています。正しいファイルを選んでください。（ファイル名を変更、フォルダ移動の場合）、存在しなければ、CASより復元を試みます」などがよいのかもしれません。
