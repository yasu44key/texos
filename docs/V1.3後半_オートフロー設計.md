## ⑤ オートフロー（UNIXパイプラインの再来）

### データモデル（既存スキーマに乗せる）
- **フローエッジ** = `relations.kind='flow'`（kindはスキーマ予約済み。既存の 'link' と共存）
  - 矢印の見た目を変える（例: 二重線 or アニメーション）ことで通常リンクと区別
- **フィルタカード** = 新しいセンチネル実身 `filter:<hash>` + `virtual_bodies.filter_ref`
  （列追加; best-effort ALTER）。filter_ref の中身は JSON:
  `{ "cmd": "実行コマンド", "args": ["{in}", "{out}"], "shell": false }`
  - MVP は外部コマンド（stdin/stdout または {in}/{out} プレースホルダ）
  - 将来は Wasm コーデック（codec_ref 構想と合流）。モジュール化フィルタの配布形式は
    V2.0 の「Wasm コーデック公開API」と同一路線
- **入力**: 既存のファイルカード（データから矢印が出る）または「ドロップ受け入れカード」
  （drop_ref 列 or kind。ドロップされたファイルを自動で取り込みフロー起動）
- **出力**: 既存のリンクフォルダカード（folder_ref）を出力先とする。フロー実行結果は
  フォルダに書き出し、生成ファイルを自動でキャンバスに登録（committed 実身）

### 実行モデル
1. 手動: フィルタカード右クリック「フローを実行」（MVP はこれだけで良い）
2. 自動: 入力ファイルの mtime 変化を検知（ウィンドウfocus時 or タイマー）して再実行
3. 連鎖: 出力 → 次のフィルタの入力、と relations を辿って逐次実行（DAG。循環は拒否）

### MVP スコープ案（次セッション）
- filter_ref 列 + フィルタカード作成UI（コマンド入力ダイアログ）
- data → filter → folder の1段実行（手動トリガー）
- 実行ログをカードの memo に記録

## 外部AIディスカッション（2026-06-12 Gemini）からの採用アイデア

⑤⑦の設計を補強する具体案。プラグインプロトコルの方向性が固まった。

### フィルタ・プラグインプロトコル（⑤の filter_ref を発展させる）
1. **データパッケージ**: フィルタの入出力は MIME型＋メタデータ付きのオブジェクトに統一
   `{ mime_type, metadata: { source_node_id, filename }, stream }`
   → TexoSの real_bodies は最初から mime_type/ext を持つので親和性が高い
2. **マニフェスト**: プラグインは「受け入れ可能な入力MIME」「出力MIME」を宣言
3. **接続時バリデーション**: flow矢印を繋いだ瞬間に型チェック。不一致は矢印を赤表示
   （音声→テキスト専用フィルタ等をその場で警告。実行前に失敗が分かる）
4. **実行関数**: 非同期 execute(in)→out ＋ 進捗コールバック（矢印上にインジケーター表示）
5. **引数のUI自動生成**: プラグインが設定項目を JSON Schema で宣言し、TexoS側が
   フォーム（テキストボックス/スライダー）を自動生成 → プラグインにUIコード不要。
   **これはOSS化戦略の要**（サードパーティの参入障壁を最小化）
6. **公式サンプルプラグイン同梱**: grep（テキスト抽出）/ resize（画像）/ volume（音声）
   など最小実装を数個同梱し、OSS公開時の参考実装にする
7. ユースケースの目玉: 動画→ffmpeg音声抽出→whisper文字起こし→LLM要約、のような
   マルチメディア連鎖。実行基盤は 外部プロセス（MVP）→ Wasm（配布・サンドボックス）の順

### MCP/AI支援（⑦の補強）
- **双方向**: TexoSをMCPサーバー化（create_node/connect_nodes/commit等のツール公開）
  に加え、将来は MCPクライアント としても動き、外部MCPサーバー（GitHub/Drive等）の
  リソースを「仮身」としてキャンバスに取り込む
- **シグナル色をAIコンテキストに含める**: 琥珀=仮身/緑=編集済/グレー=実身/薄赤=窓喪失 を
  ツール応答に載せ、AIが状態ベースで判断（「仮身だから実身化してから加工」等）
- **AIによる実身化トリガー**: 結果検証→コミット（実身化）をAIの承認コマンドとして設計。
  パイプラインが人間の「保存」操作なしで自律進行する=既存デザインアプリとの最大差別化
- **ガードレール**: AIが勝手に実身化してストレージを浪費しない制限、薄赤（エラー）時の
  自己修復・リトライのプロトコル、「ここからAIに任せる」自律モード切替UI
- 実行タイミングの選択肢: リアルタイム逐次 / 実身化（リリース）時の一括バッチ — MVPは手動
