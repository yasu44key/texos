## 2. 決まった方針（ユーザー合意済み）

### 2-1. 2.0 の進め方

- 書き直しはしない。`v1.13-stable` を切り、`main` を 2.0 開発線にする。
- 順番は **挙動を変えない構造整理 → データ形式の移行**。同じ号に混ぜない（回帰の原因が追えなくなる）。
- ユーザーから見える変化は小さく、中身は複雑、という性格の作業。
- 他OSへの移植とフレームワークの入れ替えは一緒にやらない。

### 2-2. 複数PCからの利用（本人のみ・2〜3台）

ユーザーは複数の PC で同じプロジェクトを**開いたまま**にし、座った PC で作業する。他人との同時編集は想定しない。

- 各 PC の状態は「編集中」と「表示のみ」の2つ。プロジェクトは閉じない。
- しばらく操作がなければ自動で「表示のみ」になり、編集権を手放す（既定5分程度・設定可）。
- 操作を始めた PC が自動で「編集中」になる。最新を読み直してから編集権を取る。確認は出さない。
- 別の PC がまさに編集中のときだけ「〇〇で編集中です／引き継ぐ」を出す。
- 「表示のみ」の PC は他の PC の変更を定期的に読み直す。
- 実行中のフローは「操作中」と見なす。
- ネットワーク上では WAL を使わない（§5-1）。
- 表示位置と倍率は PC ごとに持つ（いまはプロジェクトに保存＝見るだけで書き込みが起きる）。

実装済み（§3-6）。全台が「表示のみ」のとき、タイマとウォッチャは**最後に編集していた PC**が発火させる（案のとおり実装。ユーザーの確認はまだ）。

### 2-3. メニューの分類

ユーザーの要望: 検索より**分類でたどれること**が大事。階層は深くしない。

- 右クリック → 分類 → カードの2段まで。分類は8個前後。名前は「やりたいこと」で付ける。
- 並びはデータの流れ（集める → 加工する → 仕上げる）。
- 設定はカード一覧に混ぜない。サブメニューの先頭に「戻る」を置く。
- 分類はビルトイン定義表に持たせ、右クリックメニュー・矢印引き出しメニュー・マニュアルで共通にする。

### 3-2. ネットワーク上では WAL を使わない

- `db.rs open`: `is_remote_path`（UNC か、`GetDriveTypeW` が `DRIVE_REMOTE`）なら `journal_mode=DELETE`、ローカルは従来どおり WAL。
- WAL のままの DB をリモートで開くと、`-wal` の中身を本体へ反映してから切り替わる。**他の接続が開いている間は切り替わらず WAL のまま**（次に単独で開いたときに切り替わる）。
- テスト: `db::journal_tests` 2件。
- **実機確認が要る点**: `X:` 上のプロジェクトを開いたあと `.texos` から `texos.db-wal` / `-shm` が消えること。DELETE モードでは読みと書きが互いを待つので（`busy_timeout` 5秒）、並行フロー実行中に「database is locked」が出ないか。
- これは §2-2 のうち WAL の部分だけ。編集権（`lock.json`）と「表示のみ」は §3-6。

### 3-6. 編集権と「表示のみ」（v2.1.1。v2.1.0 を含めて1つの版）

§2-2 の実装。新規 `src-tauri/src/editlock.rs` と `src/hooks/useEditLock.tsx`。

**考え方**: プロジェクトごとに持ち主は1台。持ち主だけが DB へ書き、タイマ／ウォッチャを発火させる。

| この PC の状態 | 画面 | DB | タイマ等 |
|---|---|---|---|
| `edit` 編集中 | 何も出さない | 書ける | 動く |
| `idle` 持ち主だが操作なし | 「表示のみ（操作すると編集に戻ります）」 | 書ける | 動く |
| `view` 持ち主でない | 覆い＋「表示のみ」 | **書けない** | 止まる |

- `.texos/lock.json` に `{host, session, idle, beat, since, pid}`。持ち主は15秒ごとに `beat` を更新する。
- 同じ PC の、もう動いていないプロセスが残したロックは無いものとして扱う（`drop_dead_local`。強制終了のあとすぐ起動し直しても自分に待たされない）。
- 切り替わりは標準エラーに `[editlock] …` と出す（取得・引き継がれた）。
- 操作が無いまま既定5分たつと `idle: true` を書く（＝手放した）。実行中のジョブがある間は操作中と見なす。
- **v2.1.1 で変更**: 持ち主でない PC は、上部の「編集権を取得」（相手が操作中なら「引き継ぐ」）を押して取る（`edit_takeover`）。触っただけでは取らない。ユーザーの指示（2026-11-11「閲覧側は見るだけはできるように、取得を押してから編集」）。自動で取るのは、開いた時点で持ち主がいない（ファイルが無い／`beat` が60秒より古い＝`Claim::OtherGone`）ときだけ。v2.1.0 は `idle` の相手からも触っただけで引き継いでいた。
- `view` の間は `Canvas` の `readOnly` が透明な板でカードへの操作を止め、左ドラッグ＝パン・ホイール＝ズームだけ通す。キー操作は `useEditLock` が止める。
- 引き継がれた側は5秒ごとの見張り（`editlock::tick`）で気づいて `view` になる。
- `view` の PC は DB 接続を `PRAGMA query_only=ON` にする。**書き込みコマンドを1つずつ塞いではいない**（196個ある）。DB 接続そのものを読み取り専用にして止めている。`run_flow_job`・`fire_op`・MCP の書き込みメソッドは `ensure_editable` で日本語の理由を返す。
- `view` の PC は5秒ごとに DB の指紋（`PRAGMA data_version`＋`texos.db`／`-wal` の更新時刻と大きさ）を見て、変わっていたら `edit:changed` を出し、画面が読み直す。
- 編集権を取った瞬間（`took: true`）に、画面はカードとアンドゥ履歴を読み直す。
- プロジェクトの差し替えは `editlock::set_current_project` に一本化（前のロックを手放し、新しい方を取りにいく）。`project.rs` の4か所。アプリ終了時（`RunEvent::Exit`）にもロックを消す。
- 表示位置と倍率は PC ごと: `app_data/viewports.json`。`set_view_transform` は DB へ書かなくなった。`get_view_transform` は PC の値が無ければ従来の DB の値で始める。
- 時間の設定: 右クリック →「表示・設定」→「「表示のみ」になるまでの時間 ...」。`config.json` の `edit_idle_secs`。
- ロック順は `EditLock.inner` → `AppState.current`。逆順は取らない。ファイル I/O は `inner` を持たずに行う。
- テスト: `editlock::tests` 5件（判定の4通り／2台の受け渡しと `query_only`／残骸ロック／他人のロックは消さない／表示位置）。全体は `cargo test --lib` 251 成功、`tsc` エラーなし。

**わかっている限界**

- 引き継がれてから気づくまで最大5秒、古い持ち主も書ける。利用者は1人なので実害は小さいと見ている。
- `view` の間、キャンバスの外にある部品（ジョブパネルなど）は押せる。押しても DB へは書けない（英語の SQLite エラーが出ることがある）。
- `view` の間はカードのプレビューを開いたり、中をスクロールしたりできない。
- 生存の判定は PC 同士の時計に頼る（60秒）。時計が1分以上ずれていると、操作中の相手を「不在」と見て確認なしで引き継ぐ。
- 引き継いだとき、相手の PC で走っているフローは止まらない（専用の DB 接続で書き続ける）。
- `open_project_at` は開いた時点で小さな修復の書き込みをする（`repair_mime_types` など）。`view` で開く PC でも走る。
- `view` の PC で保存前のインライン編集があった場合、読み直しで消える可能性がある。
- 音声カードの見回り（`voice_tick`）は `view` でも動く。未確認。
- 実機2台での受け渡しはユーザーが確認し「うまくいった」との報告（2026-11-11）。細かい項目ごとの記録はない。タイマ／ウォッチャの発火元と、引き継ぎ時に走っているフローの扱いは未確認。

### 3-7. エージェントカードの作り直し（v2.1.2）

v1.13 のエージェントカード（道具を選んでフローを組み、実行までする）は廃止して置き換えた。`src-tauri/src/agent.rs` と `src/objects/AgentPanel.tsx` は全面書き直し。

**決まった方針（ユーザー合意・2026-11-12）**

- エージェントは**声で壁打ちする相手**。フローを組むのは**コンストラクタ**の仕事で、エージェントは会話のまとめをカードにして渡す。「組む」「実行」「話して頼む」は外した。
- **声は手元で完結させる**。Win+H はマイクロソフトのサーバーへ音声を送るので標準にしない。常駐の聞き取りを必須の部品として持つ（「ローカルで完結」は TexoS のコンセプト）。
- 即答が先。調べるのは必要なときだけ。ウェブは既定で切。

**作り**

- 返事は逐次受信（`flow::run_ai_chat_stream_rec`）。素の OS スレッドで呼ぶ。書きながら `draft` で画面へ流し、文ごとに読み上げる。
- 調べる一手は JSON ではなく、返事の代わりに書く1行: `【調べる】…`（索引）／`【読む】…`（ファイルカード）／`【ウェブ】…`（SearXNG）。実行して `【結果: 名前】` を user ロールで返す。上限は `max_lookups`（既定3・最大8）。
- ウェブの出典は AI に書かせず、検索結果から `sources_of` が `  - [題名](URL)` を並べる（AI に URL を書かせると作り話が混じるため）。パネルではリンクになり、会話の記録にも残る。
- 聞き取りは `python/voice_server.py` を常駐させる（`voice::spawn_server` を音声カードと共用）。`--compute auto` で GPU（cuda float16）を試し、だめなら CPU。**音声カードも同じ変更で GPU を使う**。
- 聞き取りは音声カードと同時には動かさない（`voice_running` なら断る）。`agent_tick` が、プロジェクトの切り替え・カードの削除・音声カードの開始で聞き取りを止める。
- 話しかけて割り込むと読み上げを止める（`speech_start` → `hush`）。設定の `barge_in` で切れる。
- 会話は `app_data/agent/talk_<card>.json` に控え、`エージェント/<名前>の会話.md` を右隣のカードに出す。切り出しとまとめは `エージェント/<名前>の{切り出し|まとめ}_月日_時分秒.md` で、パネルの右の列（`SLOT_DX` 420）に上から並べる。
- パネルは開閉式（`expanded` と `set_expanded`）。閉じている間は `AgentBadge` が印を出す。
- 設定（`filter_ref` の JSON）: `max_lookups`／`web`／`stt_model`（既定 **small**）／`silence`（既定 **1.0 秒**）／`barge_in`／`mic_device`。旧版の `max_steps`・`card_model`・`max_retries`・`mic` は保存時に消す。
- イベント: `agent:event`（role = user／agent／tool／error／status／draft）、`agent:vad`、`agent:level`、`agent:ear`。
- テスト: `agent::tests` 10件＋実機の AI を使う `agent_live`（ignored）。全体は `cargo test --lib` 253 成功、`tsc` エラーなし。

**実測と、既定値の理由**

- 聞き取り（5秒の音声）: whisper-cli small・CPU・毎回起動＝約4.7秒／常駐 CPU base＝約0.6秒／常駐 GPU base＝約0.2秒（RTX 3090）。遅さの原因は発話ごとの起動だった。
- 区切りの無音は 0.7 秒だと考えながら話す途中で切れた。ユーザーが実機で 1.0 秒に決めた。
- モデルは base では聞き違いが多く、medium は既定には大きい（約1.5GB）。ユーザーの判断で small。
- AI は gemma3:latest が調べる一手を5/5で正しく出し、最初の文字まで約0.8秒。gemma4:e2b は4/5で、思考に4〜5秒かかる。

**わかっている限界**

- ウェブは検索結果の抜粋だけを読む。ページの本文は取りに行かない（足すと返事が数秒遅くなる）。
- 相づちや息の音を1発話として拾うことがある（「ん」だけの吹き出し）。短い発話を捨てる処理は入れていない。
- スピーカーで読み上げているときの割り込みの誤作動は未確認。
- パネルを閉じたままの聞き取りの継続は未確認。
- リリースしたインストーラを入れての動作確認の記録はない（確認は開発版）。
