## 修正推奨：別内容・別プロジェクトの再送が成功扱いになる（P2）

再現手順：

1. 現在の検証プロジェクトAに create_note(project=A,text=本文A,request_id=一意ID) を送る。
2. 同じIDで create_note(project=存在しない別プロジェクトB,text=別内容,request_id=同じID) を送る。
3. 2が拒否されず、1のcard_idとreplayed:trueが成功として返る。

実測：accepted:true、replayed:true、error:null（mcp_extra.log）。別プロジェクトへの書き込みを確認したわけではない。以前の結果の再利用だが、対象・本文が異なる要求にも成功を返すため、エージェントが要求の成否を誤認する。

原因は src-tauri/src/mcp_bridge.rs:523 のidempotent。キャッシュキーがmethod＋request_idのみで、命中時にはproject照合を含む実処理を呼ばない。

修正案：再送時も現在の対象プロジェクトを照合し、正規化したprojectと要求内容の指紋を記録。同じIDを異なる内容で再利用したら明示エラーにする。同一要求の再送成功は維持し、このケースの回帰テストを追加する。
