## v1.12.0（2026-10-23）声で頼むとカードが並ぶ

設計と経緯は `docs/V1.12_声の窓口と思考役計画.md`（同日に構成を組み直した）。

- **コンストラクタカード**（自動化カードを追加 → 生成 → コンストラクタ）— つないだ依頼を読み、AI がカードの設計図を書き、
  配線の決まり（`scripts/texos_flow.py` の検査）で確かめて、違反があれば理由ごと AI に返して直させてから、
  いまのプロジェクトのいちばん下に枠で囲んで並べる。並べたカードは実行しない。Ctrl+Z 1回で全部戻せる。
  既定の AI は Strata（OpenAI 互換・`http://127.0.0.1:8080/v1`）。Ollama・LM Studio のモデルにも替えられる。
  設定で「案だけ出す」にもできる。実機で「C のハローワールドを gcc でコンパイル」「Python の GUI 時計」
  「日本語の音声を英訳して読み上げ」を、依頼の付箋から組んで実行まで確認（Strata で1回の設計に約20〜30秒）。
- **音声から AI カードへ依頼がそのまま届く** — 音声カードが発火するとき、話した中身を発火先カードの入力として渡す
  （受け皿ファイルを入力にしなくてよい）。資料つきのカードには「【依頼】…【資料】…」として頭に付ける。
- **役割の付箋で振り分ける** — 音声カードは、発火先の AI カードにつながる役割の付箋の冒頭を、どのカードへ流すかの説明に使う。
- **結果の中身を読み上げる** — 「○○、終わりました。」に続けて出力の最初の段落を読む（設定「結果の報告」で従来どおりにもできる）。
- 検査の追加: 外部プログラムのカードで `cmd` の先頭にプログラム名を書くとエラー（`validate()`）。
- コンストラクタが**マイク録音・Whisper 文字起こし・Whisper 用 WAV 変換**も並べられる（この PC の Whisper の場所・モデル・
  マイク名は並べるときに TexoS が入れる）。手元のファイルを使う依頼では、つなぐ入口として IN カードを置く。
- **コンストラクタと音声カードの AI を、AI カードと同じ設定画面で** — サーバー（Ollama / LM Studio / OpenAI 互換）・
  モデル一覧の取得（能力の印つき）・思考・温度・追加パラメータ。音声カードは設定の右上「🤖 応答 AI の設定…」から。
  音声カードの応答 AI に LM Studio・OpenAI 互換（Strata など）も使えるようになった。

### 音声カード（声の窓口）と思考役

音声カードを「声の窓口」に育てる第一歩。ふだんは軽い AI がその場で答え、重い問いは裏で常駐する
ローカルの思考役へ回す。考えている間も会話は続けられる。設計と経緯は `docs/V1.12_声の窓口と思考役計画.md`。

- **思考役へ回す** — 窓口の AI が「じっくり考える」と判断した問い、または「よく考えて」「詳しく」「比べて」などの
  合図の言葉（設定で変更可）を含む問いは、「考えておきます」と返して思考役へ渡す。答えがまとまったら
  話の切れ目に要約を読み上げ、全文は発話ログの隣の `思考.md` に追記する。
- **思考役の順番** — Strata（`127.0.0.1:8080`）→ 止まっていれば LM Studio（`127.0.0.1:1234`・**読み込み済みの
  モデルだけ**を使う）。Claude へは自動で回さない。カード設定「思考役」で自動／Strata だけ／LM Studio だけ／使わない。
- **状態パネルに思考役の状態** — 「🧠 Strata：生成中（2件待ち）・考え中 1件」のように5秒ごとに表示。
- **矢印が無くても会話できる** — AI と会話する設定なら、矢印の先のカードが1枚も無くても質問に答える
  （従来は黙っていた）。
- **応答用の既定モデルを gemma3:latest に**（新しく置くカード）。Strata と GPU を分け合うと gemma4 は載らないため。
  既存のカードは設定のまま。
- **止める・中止・リセットの取り違え対策** — AI がこれらを選んでも、発話に止める系の言葉が無ければ選び直させる
  （gemma3 は「英語で要約して」を「実行を中止する」にした実測あり）。
- **音声カードの色を紫に** — 発行系（タイマ・ウォッチャ）の琥珀から外し、常駐して人と話すカードとして見分けられるように。


## v1.11.2（2026-10-21）画像生成カードを ComfyUI で動かす

画像生成（Text-To-Image）カードの生成エンジンに **ComfyUI（外部サーバ）** を選べるようにした。
新しいモデル（Qwen-Image 2.1 など）を TexoS 内蔵デーモンに足すのではなく、ComfyUI のワークフローをそのまま使う。
設計と未決事項は `docs/ComfyUIバックエンド設計.md`。

- **カードの設定** — 「生成エンジン」で ComfyUI を選び、接続先（空欄＝`http://127.0.0.1:8188`）と
  **API 形式のワークフロー JSON**（ComfyUI の「エクスポート（API）」）を貼る。「取り込み・解析」で差し込み口
  （プロンプト・負プロンプト・シード・ステップ・cfg・サイズ・入力画像）を自動検出し、ComfyUI のノード一覧と照らして
  ノードの欠け・入力名の変更・モデルファイルの欠けを知らせる。空欄の値はワークフローに入っている値のまま。
  UI 形式（テンプレート・保存ファイル）は案内付きで断る。
- **実行** — 接続したテキストがプロンプト、画像カードは矢印を作った順に入力画像 1, 2 … へ。余った画像入力は
  ワークフローから外して投げる。シード空欄＝毎回ランダム（使ったシードは実行ログに残る）。
  中断・制限時間は自分のジョブだけを止める。
- **GPU の取り合い** — この PC の ComfyUI で生成する前に内蔵の画像生成・3D 生成デーモンを止め、
  内蔵で生成する前には ComfyUI にモデルを下ろさせる。別の PC の ComfyUI なら GPU 枠を取らない。
- 実機（ComfyUI v0.41.0・RTX 3090・Qwen-Image 2.1）で、テキスト→画像 62 秒・画像編集（フィギュア化）82 秒・
  生成→編集の2段 143 秒を確認。テスト用プロジェクトは `scripts/build_comfy_test.py` が組む。
- フロー構築用ビルダー（`scripts/texos_flow.py`）が画像生成・3D 生成カードへの2本入力を誤って警告していたのを修正。

## v1.11.1（2026-10-15）MCP の再送を取り違えない

v1.11.0 の受入検証（`docs/TexoS_v1.11.0_検証レポート.md`）で見つかった不具合の修正。

- **同じ request_id の使い回しを成功扱いにしない** — MCP の作成・実行は `request_id` を付けると再送しても
  重複しないが、同じ ID を**別の本文・別のプロジェクト**の要求に使っても、照合せずに1回目の結果を
  「再送でした」と成功で返していた（エージェントが要求の成否を取り違える）。
  いまは引数が1回目と違えば `request_id_conflict` で断る。同じ要求の再送でも、いま開いているプロジェクトが
  違えば `project_mismatch` で断る。キーの順番やパスの書き方（`/` と `\`・末尾の区切り）の違いは同じ要求とみなす。
- `docs/MCP接続.md` を整理（受入検証の要約・解決済みの項目）。通しテストに再送の照合を3項目追加（実機 32/32）。

## v1.11.0（2026-10-15）AI エージェントから操作できる — MCP 接続

起動中の TexoS を、同じPCの AI エージェント（Claude Code など）が MCP 経由で操作できるようにした。
これまでは「TexoS を終了して DB を組む」か「画面を Computer Use で操作する」しかなかったが、
**いま開いている画面と同じ状態**を、UI と同じ処理で取得・編集・実行・確認できる。
手順・ツール仕様・検証結果は `docs/MCP接続.md`。

- **受け付けのオン/オフ** — キャンバス右クリック「表示・設定」→「AIエージェント接続（MCP）を受け付ける」。
  既定はオフ。オフにすると口ごと閉じる。
- **ネットワークに出さない** — 名前付きパイプ（リモート接続は拒否）＋有効化のたびに作り直すトークン。
  MCP サーバーは `scripts/texos_mcp.py`（Python 標準ライブラリだけ・stdio）。
- **できること（20ツール）** — 現在のプロジェクト・カード・矢印・設定の取得、付箋の作成と本文の更新、
  AI 変換カード・主な内蔵カード（連結・grep・置換・記録など）・IN/OUT の作成と設定変更、移動、
  矢印の作成（役割 system 等も）・属性変更・切断、既存ファイルの取り込み、終端の実行（非同期・ジョブID）、
  ジョブの状態と段ごとの成否・中断、出力カードの本文取得、実機の AI モデル一覧。
- **別のプロジェクトに書かない** — 変更・実行にはプロジェクトの指定が必須。開いているものと違えば拒否する。
- **画面にその場で出る** — エージェントの作成・移動・配線は Ctrl+Z で戻せる（UI の操作と同じ記録）。
- 外部プログラム・シェル・画像生成などのカードは MCP からは作れない（既存フローの実行はできる）。
- 実機の通しテスト `scripts/texos_mcp_selftest.py`（28項目）。

あわせて直したもの:

- **AI 変換カードの中断がすぐ効く** — 変換は応答を一括で待っていたため、中断ボタンを押しても
  LLM が書き終えるまで止まらなかった（実測53秒）。対話と同じストリーム受信にして、中断で接続を閉じる
  （実測 0.01〜0.03 秒）。出力の中身（思考の除去など）は従来と同じ。
- **付箋からの矢印が赤く出る** — 付箋→処理カードの矢印が、実行は正常なのに常に赤（型不一致）表示だった。
  付箋は本文をテキストとして流す定数カードなので、テキストを受けるカードへの矢印は通常の色になる。

## v1.10.0（2026-10-11）話しかけると動く — 音声反射カード

TexoS に「反射神経」を入れる最初の1枚。カードを置いて稼働させている間だけ、マイクで聞き取り、
話した内容に応じてフローを実行し、結果を声で報告する（常駐して裏で動く型は 2.0 以降）。
設計と経緯は `docs/V1.10_音声反射カード計画.md`。

- **音声カード**（発行 → 音声）— 置いた直後は停止。「▶ 稼働開始」で聞き取りを始める。稼働中は
  カードの下に状態パネル（聞き取り中・入力レベルとしきい値の目盛り・直近の発話と判定）が出る。
  マイクは1つなので稼働できるのは1枚。録音カードが動いている間はマイクを譲る。
- **会話で動く** — 話し終えて約1.2秒で区切り、会話の流れごとローカル AI（既定 gemma4:latest・Ollama）に
  渡す。AI が「どのカードを実行するか／続きを待つか／ただの会話か／止める・中止・リセットか」を選び、
  返事をすぐ読み上げる。選べるのはリクエスト矢印の先のカードだけ（カード名とコメントが選択肢の説明）。
  「メモして」→ 話す →「以上」のような区切りも会話の流れで判断し、途中の中身は受け皿に追記していく。
  実機の言い回しで1ターン約1秒。
- **受け皿と書き出しの矢印** — 音声カードからファイルカードへの矢印（「書き出し」）の先に発話の中身が入る。
  フローはそのファイルを入力にする。音声カードを作ると受け皿と発話ログのカードが右に置かれる。
- **口述モード** — 話すたびに全文を受け皿へ入れ、矢印の先を全部実行（清書・キーワード抽出などを自動で）。
- **マイク以外の入口** — 状態パネルのテキスト欄、新カード「会話へ送る」（フローの終端に置くと流れてきた
  テキストを会話へ渡す）。音声ファイル → 文字起こし → 会話へ送る、のように既存カードで組める。
- **発話ログ** — 受け皿と同じフォルダに `発話ログ.md`（人が読む）と `発話ログ.jsonl`（機械用）を追記。
  プロジェクトの記録として一緒に運べる。
- 音声認識は faster-whisper、読み上げは Windows の日本語音声。必要なライブラリは TexoS の管理環境
  （runtime/envs/voice）へ、カードの「音声環境を構築」ボタンで導入する（torch は不要）。
- フロー組み立てのビルダー（`scripts/texos_flow.py`）に `voice()`・`request()`（リクエスト矢印・受け皿の矢印）・
  `ai(seq=)` を追加。手本 `scripts/build_voice_demo.py`。試走ツールはプロジェクト基準の相対パスを読めるように修正。

## v1.9.2（2026-10-08）汎用サーバにも思考を指示できる

ローカルLLMサーバ（Strata など）を「OpenAI互換（その他）」でつなぐと、AIカードの「思考」欄は
何も送っていなかった（画面の説明もそう書いていた）。未知のパラメータで止まるサーバがあるための
安全策だったが、思考を止めたい・浅くしたいときに手が無かった。システムプロンプトに
`"reasoning_budget_tokens": 16000` と書いても、本文として送られるだけで効かない。

- **思考の指定を送る（reasoning_effort）** — サーバーが「OpenAI互換（その他）」のとき、思考欄の下に
  チェックが出る。オンにすると 使わない→`none`・浅く→`low`・中→`medium`・深く→`high` を送る
  （「使う」は送らずサーバ既定に任せる）。既定はオフ＝従来どおり。LM Studio / Ollama は今までどおり
  モデルの能力から自動で決まる。
- **追加パラメータ（JSON）** — リクエストにそのまま加える欄を全サーバ共通で足した。サーバ独自の拡張を
  使うときに。例: Strata の思考上限 `{"reasoning_budget_tokens": 8000}`。モデル・温度・思考など
  専用の欄があるもの（model / messages / stream / temperature / think / reasoning_effort / options）は
  書けない（保存時にエラー表示）。送った値は実行ログの「送信パラメータ」に残る。
- **システムプロンプトの注意書き** — `reasoning_budget_tokens:` のような API パラメータらしい書き方が
  あると、「本文として送られるだけで効きません。追加パラメータ欄へ」と知らせる。
- **抜粋の書き出し位置** — チャットパネルの「書き出し」で作る抜粋カードが、パネルの下に隠れる位置に
  出ていた。パネルの右外（パネル幅に追従）に、パネル上辺の高さから下へ、空いている段に1枚ずつ
  重ねずに並べるようにした。片付けた後は再び上辺から始まる。

## v1.9.1（2026-10-04）フォルダごと運べる

プロジェクトをフォルダごと移動すると、内包していたファイルのカードが全部薄赤（リンク切れ）に
なっていた。DB がプロジェクト内のファイルも絶対パスで覚えていたため。「実ファイルを再リンク」で
1枚ずつ直せはしたが、数十枚あると手に負えない。

- **内包ファイルはプロジェクト基準で覚える** — プロジェクトフォルダの中にあるファイルは、
  フォルダからの相対位置で保存するようにした。以後はフォルダごと移動・別ドライブへコピー・zip で
  渡しても切れない。プロジェクトの外（別ドライブ等）を指す仮身は従来どおり絶対パスのまま。
  既存のプロジェクトは、開いたときにフォルダの中を指すものだけ自動で書き換える（推測はしない）。
- **整理・書き出し → リンク切れを修復** — すでに移動してリンクが切れたプロジェクト向け。
  実ファイルが見つからない実身を、今のプロジェクトフォルダの中から探して繋ぎ直す。
  探し方は「元の場所の、フォルダより下の部分」→ 無ければ「同じファイル名」。先に内訳
  （繋ぎ直す先・候補が複数で選べないもの・見つからないもの）を見せ、確認してから実行する。
  候補が複数あるもの・見つからないものはそのまま残る（右クリックの再リンク／CASから復元で個別に）。
  自動では走らない。
- **修正** — 「実ファイルを再リンク」で、プロジェクト内で取り込んだ実身の取り込み元が古い場所の
  まま残り、メニューに「仮身に戻す」（＝元ファイル削除）が出るようになっていた。

リンクフォルダカード・プロジェクトカードの参照は、まだ絶対パスのまま（次の対象）。

## v1.9.0（2026-10-01）調べてから書く

AIカードは、渡された資料と自分の知識でしか答えられなかった。Web から取り込む道具
（v1.7 のページ取得・フィード）はあっても、「何を調べるか」から始める入口が無かった
（v1.7 で見送り、V2.0 課題に送っていた Web検索コネクタ）。検索エンジンを PC の中で動かし、
キーワード検索をカード1枚にした。AI に検索語を考えさせれば、課題から調べてレポートまでが繋がる。

- **Web検索カード（web_search）** — 検索語（1行=1検索語）で検索し、「タイトル・URL・抜粋・出典」の
  一覧を Markdown 1枚にする。URL は1行ずつ書くので、URLカード化に繋げばリンク集、ページ取得に
  繋げば本文取得へ進める。検索語はパラメータ欄に書くか、テキストカードや AI の出力を繋ぐ。
  AI が付けがちな前置き（「…：」で終わる行）・箇条書き記号・番号・引用符は自動で取り除く。
  設定は分類（一般／ニュース／IT／科学）・検索元・言語・期間・件数。
- **歯止め** — 1回の実行で検索するのは最大3語（設定で1〜10）。AI が大量に出しても、それ以上は
  検索せず結果の末尾に注記する。検索と検索の間は1秒空ける。結果が0件なら下流を止める（no-data）
  ので、AI が空の材料でレポートを書くことはない。
- **検索エンジン（SearXNG）を自動で導入** — 「Web ...」メニューの「Web検索エンジンの管理」から
  「導入する」1回で、専用の Python 3.13・SearXNG 本体（中身が固定版と一致するか検証）・部品を
  取得して組み立て、そのまま試験検索まで進む（約160MB・API キー／Docker 不要）。検索するときに
  自動で起動し、10分使わなければ止まる。TexoS を閉じると（異常終了でも）一緒に終わる。
  置き場所はアプリのデータフォルダ（`runtime\searxng`）で、フォルダを消せば元に戻る。
- **既定の検索元は google・bing・wikipedia** — brave は初回から、duckduckgo は連続検索で
  一時休止されたため外した（設定で足せる）。応答しなかった検索元は理由とともに結果に書く。
- **サンプル** — 検索語を自分で書く形（A1）と、課題から AI が検索語を考える形（A2）。
  `scripts/build_web_search_demo.py`、使い方はユーザーズチップス Tip 16。
- **修正** — t2i の Python 環境構築が、TexoS の外（`~\.local\bin` と Windows レジストリ）に
  python.exe を置こうとしていた（uv 0.8 の既定）。そこに別の python3.x.exe があると構築が失敗した。

AI カードが自分で検索する（tools を使う）機能はまだ無い。検索は人かフローが決めた場所で1回ずつ行う。

## v1.8.9（2026-09-29）できることを知ってから頼む

AIカードのモデル選びは名前の手入力か一覧から選ぶだけで、そのモデルが思考や画像入力に
対応しているかは送ってみるまで分からなかった。しかも Ollama 0.34 は、思考に非対応のモデルへ
think を送ると 400 で拒否する（従来のダイアログは「非対応モデルでは無視されます」と案内していた）。
モデルの能力を先に確かめ、使えない指定は送らないようにした。あわせて、会話の必要な部分だけを
MD に書き出せるようにした。

- **モデルの能力を表示** — 設定ダイアログの「候補▼」に 🧠思考・👁画像入力・🔧ツール の印、
  能力が分からないモデルには ⚠ を付ける。いまの設定では使えないモデル（思考非対応・埋め込み専用）は
  理由つきで選べない。選んだモデルの「能力」欄に機能の有無（○×？）と学習上限・規模・量子化を出す。
  能力は機能の有無であって、品質を示すものではない。
- **取得元** — Ollama は `/api/tags` と `/api/show`（capabilities）、LM Studio は `/api/v1/models`
  （思考で選べる値まで返る）。汎用の OpenAI 互換サーバは取得手段が無いので全部「不明」。
  結果はマシン単位のキャッシュ（`ai_model_cache.json`）に置き、digest が変わったモデルだけ
  取り直す。Ollama を更新したときは全件取り直す。
- **思考の送り方** — 選んだ値をそのまま送るが、思考に非対応のモデルには送らない。gpt-oss 系は
  思考を止められず深さでしか指定できない（Ollama・LM Studio とも実機で確認）ので、選択肢は深さだけ、
  「使う」は「中」として送る。LM Studio へは深さを `reasoning_effort` として送るようになった
  （使う／使わないは LM Studio 側の設定に従う）。
- **コンテキスト長（num_ctx）** — Ollama の実行時コンテキスト長を指定できる。空欄はサーバ既定。
  モデルの学習上限とは別物として並べて表示する。
- **実行ログに実行条件** — AI カードの実行ごとに、モデル・digest（中身の識別子）・その時点の能力・
  実際に送った値・応答に思考があったか、を記録する。同じ名前でも `ollama pull` で中身が入れ替わる
  ため。フローはトレース（`.texos/logs`）、対話は会話履歴 JSON の AI 発言ごとに残す。失敗したときも
  条件は残し、自動で送り直しはしない（送り直すとログの条件と実際が食い違う）。
- **エラーの理由を表示** — 対話モードで API がエラーを返したとき、ステータスだけでなく理由
  （`"gemma3:latest" does not support thinking` など）まで出す。
- **チャットの抜粋を書き出す** — チャットパネル上部の「全部／You／AI」と吹き出しごとのチェックで
  発言を選び、「📝 書き出し」で別の MD カードにする（`<タイトル>の抜粋.md`・既存は上書きせず連番）。
  「見出し」をオフにすると You:／AI: を付けず本文だけを並べる。毎ターン自動更新のログとは別で、
  思考は含まない。

ツール使用（tools）は能力の表示と記録だけで、AI カードにツールを使わせる機能はまだ無い。

## v1.8.8（2026-09-24）動かしても、つなぎ直せる

フォルダを整理してプロジェクトを移動・改名すると、プロジェクトカードのリンクが切れていた
（参照は絶対パス）。リンクフォルダや実身には「リンクし直す」があったが、プロジェクトカードには
無く、切れていても見た目で分からなかった。繋ぎ直す手段と、内包フォルダを一覧から置く入口を足した。

- **プロジェクトカードの「リンクし直す...」** — 右クリックから、正しい TexoS プロジェクトの
  フォルダを選んで繋ぎ直す（既定で元のリンク先の親フォルダを開く）。`relink_project` が
  `project_ref` とパス由来のセンチネル実身（`project:<hash>`）を差し替える。選んだ先が
  プロジェクトでなければ拒否する（フォルダへの格下げはしない）。
- **プロジェクトカードのリンク切れ表示** — 参照先に `.texos/texos.db` が無いとき、リンクフォルダと
  同じ薄赤の点を出す（`list_objects` がプロジェクトカードにも `cur_mtime` を埋める）。
- **リンクフォルダの張り直しでプロジェクトへ昇格** — 選んだ先が TexoS プロジェクトなら
  プロジェクトカードに切り替える。v1.3.11 からコメントにだけあって未実装だった挙動。
- **内包フォルダへのリンク ...**（キャンバス右クリック）— 現在のプロジェクトフォルダ直下の
  フォルダを、内包プロジェクト🗂／普通のフォルダ📁の別つきで一覧し、選んだものをリンクカードとして
  置く（`list_inner_folders`・隠しフォルダは除外）。既に置いてあるものは ✓。未配置が2件以上なら
  「未配置をまとめて配置」で格子状に並べる（Ctrl+Z 一回で戻せる）。

参照が絶対パスのままなので、親フォルダを動かすとその下のリンクはすべて切れ、1枚ずつ張り直す必要がある。

## v1.8.7（2026-09-23）つないだまま、途中が見える

連結したフロー（トリガ発火など）は中間結果をメモリで渡して捨てるので、途中のカードが
何を受け取り何を出したかが後から読めず、失敗しても黙って消えていた。確かめる手段を足した。
どれも既存の記録（`last_run`）と終端の着地処理に乗せ、新しい仕組みは最小にした。

- **実行ログ（トレース）** — フローを1回実行するたびに、通ったカードごとの記録を
  `.texos/logs/<日時>_<カード名>_job<N>.md`（＋`.json`）へ書き出す。完了順＝データの流れ順に、
  状態（成功／エラー／no-data／再利用／未完了）・所要時間・終了コード・入出力（名前・MIME・
  サイズ）・エラー・実行したコマンド行・セレクタの採用枝・シェルの実行コマンドを残す。
  記録点は `eval_filter` の入口と `finish_eval`（全ノードが必ず通る）だけで、種別ごとの分岐には
  手を入れていない。直近100件を残して間引く。カード右クリック「実行ログを見る」で、そのカードの
  直近記録を表示（`virtual_bodies.last_trace` 列を追加）。
- **デバッグモード** — 「表示・設定」のトグル。オンの間の実行は、テキストの先頭4KB・
  SHA-256・外部コマンドの stderr・役割（システムプロンプト）まで記録する。既定オフ。
- **途中の出力もキャンバスに出す（カード単位のスイッチ）** — フィルタカード右クリックで切替、
  面に「⤓出力」。パイプラインの途中で評価されたときも、単体▶実行の終端と**同じ規則**
  （出力名・連番・出力フォルダ）で結果をカードとして着地させる（下流へは従来どおり流す）。
  終端の着地処理を `materialize_payloads` に切り出して両者で共用＝規則が一箇所にしかない。
  連番を設定すれば試行ごとに `fibo001.exe`, `fibo002.exe`… と履歴が残る。記録カードを内蔵した形で、
  終端・失敗・no-data・AI チャットの文脈評価では出さない。
- **カードの色でのお知らせ** — 前回の実行で失敗したカードは赤枠（エラー）、実行は成功したが
  後段（キャンバスへの着地など）で失敗したカードは琥珀枠（注意）＋上辺に理由の1行目。ホバーで全文、
  クリックで実行ログ。`last_run` に `warning` を追加し、起動前後で止まった実行（出力フォルダが
  ない・入力がない等）は終端カードを error にする。トリガ発火はダイアログが出ないので、これが
  ないとユーザーのミスが黙って消えていた。失敗で終わったジョブでもキャンバスを読み直す。
- 設定ダイアログ（外部フィルタ・画像生成）が spec を組み直すときに `emit_mid` を落とさない。
- 回帰テスト — トレースの記録順・要約／詳細の差・未完了とエラーの報告・文字境界での切り詰め、
  途中出力（連番履歴・下に置く・終端／OFF／失敗／チャットでは出さない・seq 書き戻しでスイッチが
  消えない）、`last_run` の warning/error と再実行での消去。

見送り: 実行ごとに全カードの出力を `.texos/logs/<実行>/` へ丸ごと保存する案は試作したが、
実身／CAS の外側に置く「緊急措置」になるため不採用（カード単位のスイッチで置き換えた）。
ウィンドウを開くシェル実行では、起動したプログラムの終了コードは取れない（従来どおり）。

## v1.8.6（2026-09-21）載るなら GPU を使う。思考は見せるが、残さない

VRAM が 6GB に満たない PC を「確実に動く」CPU 構成に落としていた既定をやめた。
4GB 級でも SD1.5 fp16（~2GB）は GPU の方が桁違いに速く、溢れた分は
attention/VAE slicing と CPU オフロードで吸収できる。「確実に動く」を CPU で買うのは
代償が大きすぎた。あわせて、AI カードに GPU の使い方と Thinking（思考）モードを足した。

- **VRAM 量で CPU に落とさない** — `runtime/spec.rs` の推奨判定から「VRAM 6GB 未満は CPU 版
  torch」の分岐を外し、NVIDIA GPU が見つかれば常に cu124 を既定にする。CPU 分岐は
  「対応 GPU なし」だけになった。既に CPU 版で構築済みの少 VRAM 機には、t2i セットアップ
  画面の「GPU 版に再構築」の導線が出るようになる（DL は CPU 版より約 2.5GB 重い）。
- **AI カードに「GPU」欄** — `gpu` = 自動（既定・キー無し＝Ollama が VRAM に載る層だけ
  GPU に置く）／最大限（全層を強制＝`options.num_gpu=999`）／CPU のみ（`num_gpu=0`）。
  層割り当ての標準パラメータを持たない OpenAI 互換サーバーでは欄ごと出さない。
  なお AI カードは元から CPU 固定の設定を持っておらず、既定（自動）の挙動は変わらない。
- **AI カードに「思考」欄** — `think` = 使わない（既定）／使う／浅く・中・深く。Ollama は
  `/api/chat` の `think` に渡して `message.thinking` を受け、OpenAI 互換は
  `delta.reasoning_content`（`reasoning`）を受ける。加えて全経路で、本文に混ざった
  `<think>…</think>`・`<thinking>…</thinking>` を分離する。ストリームはタグが
  `<thi` / `nk>` と割れて届くので、確定できない末尾を保留する状態機械で受ける
  （割れたタグが本文へ漏れない）。
- **思考は表示するだけで保存しない** — 対話パネルに 💭 の折りたたみで出し、ターンが
  確定したら捨てる。会話履歴 JSON にも MD ログにも入らず、次ターンのコンテキストにも
  送らない。変換モードは出力から思考を必ず除去する（下流のフィルタが食べるため）。
  `think` を使わない場合でも、モデルが勝手に混ぜてくるタグは常に取り除く。
- 回帰テスト — タグ分離の状態機械に、1文字ずつ流す最悪のチャンク分割・未閉じのまま
  打ち切り・`<` を含む普通の本文を壊さないこと、`gpu`/`think` の spec 写しを追加。
- `scripts/texos_flow.py` の `ai()` に `gpu` / `think` 引数、
  `docs/AIエージェント向け_フロー構築規約.md` に該当節を追記。

## v1.8.4（2026-08-27）判断の材料は、答えを書く場所に置く

問い合わせカードは、聞かれたときに届いていた材料を答え箱の付箋へ `>` の引用で
書き写す。ところがそれが走るのは**付箋がまだ無いとき**だけだった。
`AIエージェント向け_フロー構築規約.md §3-12` は「付箋は自分で用意して先に繋いでおける
（そのほうが面から読める）」と勧めていて、エージェントが組んだフローは実際そうする。
その配線では引用が一度も入らず、**人は判断のたびに別のカードを開きに行く**ことになっていた。
規約の推奨と実装の分岐が噛み合っていなかっただけで、どちらも単体では正しい。

- **先に置いてある答え箱にも材料が入る** — 答えがまだ空のあいだは、実行のたびに
  質問と材料の引用を入れ直す。答えが書かれた付箋には触らない（人の判断を上書きしない）。
- **人が書いた案内は消えない** — 付箋の中は「目印 `── ここから下に答えを書いてください`
  より上＝自動生成、下＝人の領分」で分けた。目印の無い付箋（人やエージェントが自分で
  置いたもの）は中身を丸ごと下へ送るので、書いたものが失われない。2回流しても
  目印も案内も二重にならない。
- **変わった付箋に緑シグナルが付く** — 固定名上書きで中身が変わったカードと同じ流儀
  （`FlowReport.updated`）。どれが入れ替わったか面で分かる。
- 引用は 40 行／1200 字までの抜粋（従来どおり）。全文は記録カードの実身で読む。
- **材料が空なら、答えが書いてあっても止まる** — 2パスのフロー（①原案を作る
  ②人が判断して仕上げる）で②を先に押したときの保険。従来は「採用」の3文字だけが
  下流へ流れ、**下流の AI が承認された中身を知らないまま**それらしい文書を書いていた。
  実機では、人が読んでいない企画（別製品・別文書番号）に判子を押した形になっていた。
  入力の矢印が1本も無いカードは従来どおり通す（質問だけのカードは正当）。
  これにより **空の実身を継ぎ目に置く2パス配線**が成立する（規約 §3-12 に追記）。

きっかけは AI 自己構築の実機テスト（`scripts/自己構築回帰.py`）で組んだ
「人の判断を挟む」フロー。ローカル LLM が規約どおりに答え箱を先に置いたことで、
この分岐の抜けが表に出た。**規約が正しく、生成も正しく、実装だけが追いついていなかった**。

## v1.8.3（2026-08-26）カレントはプロジェクト — フォルダ欄の手打ちをやめる

ウォッチャの監視パスだけが**フルパス必須**で、カード設定のフォルダ欄の規約から
外れていた。他のフォルダ欄（外部プログラムの出力先・記録・新規カードを登録）は
とっくに「空欄＝プロジェクト直下」なのに、ここだけ空欄を弾いていた。
`ユーザーズチップス.md` の Tip 8 は 7月の時点で「監視パスは空欄＝プロジェクト直下に
しておくと噛み合う」と書いていたので、**ドキュメントの方が実装より先に正しかった**。
それを揃えるついでに、フォルダ欄の規約そのものを可搬性の側へ寄せた。

- **フォルダ欄の規約を3つに統一** — **空欄＝プロジェクトフォルダ／相対＝プロジェクト
  基準／絶対＝そのまま**。解決は `util.rs :: resolve_project_path` の1箇所。
  相対パスは従来**プロセスの作業ディレクトリ基準**で、事実上壊れていた（誰も書けなかった）。
  絶対パスは潰さない — 別ドライブや UNC を指す仮身は正当な第一級機能なので、
  「根絶」ではなく「分ける」（`V2.0_マルチプラットフォーム検討.md` §3 の方針）。
- **ウォッチャの監視パスが任意になった** — 空欄で作れば、そのプロジェクトフォルダを
  見張る。相対パス（例: `受信箱`）ならプロジェクトごと移動・配布しても壊れない。
  適用先はウォッチャの `path`・外部プログラムと記録カードの `out_dir`・
  「新規カードを登録」の `path`。
- **フォルダ欄に「参照…」ボタンが付いた** — 内蔵フィルタ／オペレーションの設定
  ダイアログにもフォルダ選択が来た（従来は外部プログラムのダイアログだけ）。
  **プロジェクト配下を選ぶと自動で相対パスに畳む**（プロジェクトそのものなら空欄）。
  絶対パスをDBに焼き込まないための入口側の手当て。
- **自己発火の警告を精度上げ** — 運用前評価の「監視パスがプロジェクトフォルダを含む」
  検査は、監視パスと出力先を**解決してから**比べるようにした（でないと空欄が空文字の
  まま素通りして、警告が黙って消える）。あわせて、その実行が**実際にプロジェクト直下へ
  ファイルを書くときだけ**警告するようにした。ウォッチャ＋「新規カードを登録」の対
  （v1.6 の随時登録）は何も書かない＝発振しないので、もう黄色くならない。
  既定が「プロジェクトフォルダ」になった以上、ここで黙らないと警告そのものが空気になる。

`%PROJECT%` トークン化（§3 の本体）の先行実装でもある。着手時は、この解決関数の入口で
`%PROJECT%/…` を受けるだけで済み、移行対象は「この規約より前に絶対パスで書かれたカード」
だけに絞れる。

## v1.8.2（2026-08-21）データの型を取り違えない — と、AI に組ませるための手引き

矢印は `accept_mime` で型を検査していて、**合わない入力はエラーにならず黙って
飛ばされる**。この「静かな失敗」を起こす原因が、拡張子から MIME を引く表の
取りこぼしだった。実際に組んでみて2件見つかったので塞いだ。

- **`.java` などが「テキストではない」扱いだった** — 表に無い拡張子は
  `application/octet-stream` に落ちるため、`text/*` を受けるカード（AI・連結・grep）が
  黙って読み飛ばしていた。**コードブロック抽出は lang に java / kotlin / go / ruby /
  powershell を持っているのに、切り出したソースを下流が捨てていた**ことになる。
  java / kt / go / rb / sh / ps1 / bat / sql / lua / cs / swift / hs などを追加。
- **`.tsv` も同じ穴に落ちていた** — 「列の取り出し(cut)」「行の横結合(paste)」は
  まさに TSV を扱うカードなのに、`.tsv` ファイルを繋げなかった。
- **既存プロジェクトは開いたときに直る** — MIME はプロジェクトを開くたびに
  拡張子から引き直しているので、更新後に一度開けば古いカードも正しくなる。

### AI エージェントに仕組みを組ませるための手引き（アプリ本体の変更ではない）

「TexoS でこういう仕組みを作って」と AI に頼めるようにするための資料を整えた。
実際に規約だけを別のセッションへ渡し、**ソースを読ませずに1周で組めるか**を試して、
詰まった箇所を書き戻してある。

- **`docs/AIエージェント向け_フロー構築規約.md`** — 実行モデル・落とし穴・設計則。
  受け取った側が最初に確認する4項目、いま開いているプロジェクトの調べ方、
  AI のモデルは実機で確認すること、「入力する」と言われたときの入口の作り分け
  （付箋／実身／IN カード）、外部プログラム名は拡張子まで書くこと、などを追加。
- **カードカタログ** — カードの種類を1枚ずつ「押せる標本」にしたプロジェクト。
  サンプル入力が繋いであるので ▶ で挙動が見られる。UI のスキーマ表から機械生成。
  **データの見本を26形式**（画像・音・動画・PDF・Word・Excel・3D(glb)・書庫）同梱し、
  それぞれに MIME／カードの上で見えるか／どのカードに繋がるか を書いた。
- **レシピ集** — これまでの実プロジェクトから、目的の違う仕組み18本を抜き出した
  プロジェクト。外部プログラムの引数は実際に動いていたものをそのまま写してある。
- **試走スクリプト** — TexoS を起動せずにフローを1周流して出力を確かめる道具。

## v1.8.1（2026-08-09）ドラッグアウト — カードを OS 側へそのまま手渡す

TexoS は外からドラッグで受け取れるのに、外へはドラッグで出せなかった。出口は
Ctrl+C（クリップボード持ち出し）だけで、相手アプリが「ドロップしてください」と
言ってくる場面（DAW・サンプラー・アップローダ）では手が止まっていた。

- **左端の持ち出しつまみ（↗）** — カードにホバーすると左端に出る。掴んで外の
  アプリ（エクスプローラ・DAW・GRIDPLAY・ブラウザ）へドラッグすると、実ファイルが
  そのまま渡る。**右端＝TexoS 内へつなぐ／左端＝OS へ持ち出す**の対。
  素ドラッグ＝カード移動、Ctrl+ドラッグ＝化身、Alt＝つながり選択 はそのまま。
- **持ち出しの規則は Ctrl+C と同じ** — 未コミットの仮身はここで実身になる
  （エクスポート＝コミット原則）。URL／フィルタ／ドロップポイント／ランチャは
  実体が無いのでつまみ自体が出ない。リンクフォルダ・プロジェクトは
  フォルダそのものが渡る。
- **複数選択もまとめて** — つまみを掴んだカードが選択に含まれていれば選択ぜんぶ、
  含まれていなければその1枚。群移動と同じ流儀。
- **コピー限定** — 相手アプリに「移動」を許さない。許すと向こうが TexoS の
  実ファイルを消せてしまう（クリップボード持ち出しが Explorer の「切り取り」を
  読まないのと同じ判断）。

実装は `drag_out.rs`（Windows・`drag_drop.rs` の対）。IDataObject を手実装せず
シェルの `SHCreateDataObject` に空のデータオブジェクトを作らせ、CF_HDROP を
`SetData` して `SHDoDragDrop` に渡すだけなので、受け側より短い。CF_HDROP の
組み立ては `clipboard_out::alloc_hdrop` を共用＝Ctrl+C とドラッグアウトは
同じバイト列を運ぶ。持ち出せるカードの判定も `resolve_export_paths` に一本化した。

そのほか:

- **問い合わせカードに「答えが入ったら」スイッチ**（`skip_upstream`）— v1.8.0 では
  「答えがあれば上流を評価しない」への変更を**見送っていた**が、実機で回すと、AI に
  原案を書かせてから聞く形では2パス目に原案が作り直され、**人が読んで判断した案とは
  別物**が下流へ行く。既定は変えないまま、**任意のスイッチ**として入れた。
  「上流を動かさない」を選ぶと、答えが入っているあいだは上流を1枚も評価せず答えだけを
  流す（AI も呼ばれない）。答えを消せばまた上流から動く。
  判定は**入力エッジの収集より手前**に置いてある — 収集した時点で上流の AI はもう
  走っているので、そこより後ろでは意味がない。
  サンプルフロー `scripts/build_sample_human_decision.py`（課題に人の判断を挟む・2パス）。

## v1.8.0（2026-08-08）記法カード4枚 — キャンバスを人とAIの共通の記法にする

TexoS の狙いが「OS の UI への不満への回答」から**「人と AI のコミュニケーション記法
（ビジュアル言語）」**へ移ったことを受けた号。エージェントが強くなるほど、難所は
「できるか」から**「正しくやったか確かめ、直せるか」**へ移る。チャットは線形・揮発で
結論しか見せないのでこれに向かない。そこで「記法として何が言えないか」を4つ埋めた。

- **役割ポート（矢印の役割＝システムプロンプト）** — 付箋から AI カードへ「役割」の矢印を
  引くと、付箋の中身がその AI の**役割（システムプロンプト）**になる。設定ダイアログの中に
  隠れていた一番重要な中身が、**キャンバスから読めて、その場で書き換えられる**ようになった。
  役割の矢印は入力に数えないので、束カードを挟まなくてよい（ファンアウトしない）。
- **記録カード（途中を残す・素通し）** — 矢印の途中に置くと、データはそのまま下流へ通し
  ながら、通った中身をファイルに書き出してカードにする。中間の結果はこれまで実行が
  終われば消えていたので、**1周流したあとに「何がどう変わったか」を読み返せる**ようになった。
- **問い合わせカード（途中で人に聞く）** — 実行の途中で人の判断を待つ。答えは繋がった
  「答えの付箋」に書く（付箋が無ければ最初の実行で用意され、質問とそのとき届いていた
  材料が引用で入っている）。答えが空のあいだは先へ進まない（エラーではない）。
  人が口を挟めるのが**前か後ろだけ**だったフローに、途中の判断が入るようになった。
- **反復カード（納得するまで繰り返す）** — 上流のカードをもう一度たどり直す。
  「判定 → 直して再判定」という**練り直しがそもそも描けなかった**のが描けるようになった。
  戻り矢印（役割＝前周の結果）を引くと、そこを1周前の出力が流れる。暴走止めの最大周回数は
  必須で、停止条件は「出力にこの語が出たら」等を選べる。
  絵は輪に見えるが、実行はこれまでどおり一方向のまま（循環エラーにはならない）。

そのほか:

- **設定の編集** — 記録・反復・問い合わせの各カードに設定フォームを用意した。
  フォームの無いカードの「フィルタ定義（JSON）」も、1行の入力欄から**複数行の編集欄**に
  （整形して表示・Enter は改行・Ctrl+Enter で OK）。
- **AI エージェント向けの資料** — `docs/AIエージェント向け_フロー構築規約.md`（依頼時に
  添付する指示書）と `scripts/texos_flow.py`（宣言的にフローを組むビルダー。規約違反は
  保存時に例外で弾く）。実例プロジェクトを4つ同梱の想定で作成。

## v1.7.4（2026-08-05）生成系の制限時間 — 「空欄＝無制限」を実装と一致させる

v1.7.3 のソーク中に見つかった軽微なバグの修正号（バグフィックスのみ）。

- **未記入の制限時間が無制限にならなかった（不具合修正）** — 原因は2段重なっていた。
  ①UI は「空欄＝無制限」と案内していたのに、バックエンドは未指定時に独自の既定値
  （AI変換 180秒／t2i 300秒／t23d 600秒・テクスチャ付き 900秒）を当てていた。
  ②**`reqwest::blocking::ClientBuilder` は timeout の既定が 30 秒**（async の Client は
  無制限だが blocking だけ違う）で、`.timeout()` を呼ばなければ無制限ではなく**30秒**になる。
  ②のせいで、0 を入れても空欄でも生成が 30 秒で切れていた（AIチャットは v1.4.12 から
  この状態だった＝「空欄＝無制限」が実際は 30 秒）。
  → **未記入＝0＝無制限**を **ai変換・aiチャット・t2i・t23d の4経路で共通化**し
  （`flow.rs` の `gen_timeout` / `gen_client` に一本化）、無制限のときは
  **`timeout(None)` を明示的に渡して**既定30秒を外す。契約は単体テストで固定
  （`gen_timeout_treats_blank_and_zero_as_unlimited`）。**既存カードは保存し直し不要**。
  ※ モデルのダウンロード系（Ollama pull／t2i・Whisper のモデル取得／uv 取得）は
  進捗を1行ずつ読む streaming なので、30秒既定でも読み取りごとに期限が更新され無害。
- **接続タイムアウト10秒を追加** — 無制限でも「サーバーが起動していない」ケースは
  従来どおり即エラーになる（生成中の停止は中断ボタン＝デーモンへ /cancel）。
- **t23d に「制限時間(秒)」欄を新設** — 従来は設定ダイアログに欄が無く、JSON 直編集で
  しか変えられなかった（テクスチャ付きが 900秒 で打ち切られる原因はこれ）。空欄＝無制限。
- 表記の統一 — AI 設定・t2i 設定の説明文を実装に合わせて「空欄／0＝無制限」に。
- **t23d のテクスチャ付きが 500 エラーで失敗した（不具合修正）** —
  `Hunyuan3DTexGenConfig.__init__() missing 1 required positional argument: 'subfolder_name'`。
  turbo 対応版の hy3dgen で TexGenConfig の引数が増え、**第3引数（paint サブフォルダ名）**で
  内部パイプライン（`hunyuanpaint` / `hunyuanpaint-turbo`）を選ぶ仕様になったため。
  上流の `from_pretrained` と同じ渡し方に合わせ、**署名を見て新旧どちらの hy3dgen でも動く**
  ようにした（`t23d_server.py` `_load_paint`）。実機の同梱 hy3dgen で
  `pipe_name = hunyuanpaint` の取得を確認済み。
- **同上・形状生成も 500 エラーになった（不具合修正）** —
  `No module named 'hy3dgen.shapegen.models.hunyuan3ddit'`。更新版エンジンでは DiT の置き場所が
  **`models/denoisers/` 配下へ移動**しており、turbo 互換パッチ（v1.7.3）が旧パス決め打ちで
  import していたため。新旧どちらのレイアウトも試し、見つからなければパッチを飛ばすようにした。
  更新版は guidance_embed もスケジューラも本物が入っている＝**互換パッチは丸ごと不要**になる。
- **同上・重みの読み込みも失敗した（不具合修正）** —
  `Weights only load failed ... WeightsUnpickler error: Unsupported operand 3`。
  更新版の `from_single_file` は**拡張子を見ず、`use_safetensors` が真のときだけ** safetensors
  として読み、それ以外は `torch.load(weights_only=True)` に流す。TexoS は
  `model.fp16.safetensors` を優先して渡していたため、safetensors を pickle として
  読もうとして落ちていた。→ **渡すファイルの拡張子に合わせて `use_safetensors` を明示**
  （引数を持たない旧エンジンでは渡さない）。実機の重みファイルでキー構造
  （`model` / `vae` / `conditioner`）も確認済み。
- **上記3件は「ポータブル版エンジンの更新でモジュール構成と引数が変わった」ことが共通原因**。
  デーモンがエンジンに触る 9 か所（rembg／from_single_file／後処理3種／FaceReducer 引数／
  スケジューラ／DiT の場所／TexGenConfig 署名／paint 呼び出し形／paint.models のキー）を
  実機の更新版エンジンで一括照合し、他に食い違いが無いことを確認済み。
  **SERVER_VERSION 4 → 7**（古い常駐デーモンは自動で停止・入れ替わる）。
- **チェックスクリプトを追加** — `scripts/t23d_engine_check.py`。エンジン同梱の Python で走らせると
  上記の照合を一覧で出す（NG には「対処」付き・終了コードで判定可）。エンジンの git 版・torch・
  **稼働中デーモンの版とスクリプトの版のズレ**・取得済みモデルと選ばれる重みファイルも表示。
  `--weights` で重みのキー構造まで確認。使い方と過去事例は `docs/V2.0_t23d設計.md` §8。

## v1.7 P2（2026-07-17 実装・v1.7.1 に収録）URLカードの仮身昇格 — 更新マークと取得系譜

**URLカードを「外部ブラウザを開くボタン」から「外部実身への仮身」へ昇格**させる号
（計画 §3 P2・v0.1 §2.3 キャッシュモデルの回収）。リリースは P4 完了後に一括
（2026-07-16 決定）— 本エントリは実装記録。

- **実行契約: URLカードを入力接続可に**: kind='url' の入力は **url_ref 文字列を
  text/plain として下流へ渡す**（付箋＝定数カードと同じ流儀）。URLカード→web_fetch が
  矢印1本で繋がるほか、テキスト系フィルタにも普通に流せる。接続時型チェック
  （赤矢印・preflight）も text/plain 扱いで整合。
- **取得系譜（relations kind='fetched'・新種エッジ）**: web_fetch の終端カード化時、
  直結入力の URLカード（source_url 一致）→取得実身へ系譜を張る。**最新系譜のみ表示**
  （§7-3 決着）＝張り替え時に旧エッジは soft-delete（過去の実身は残り、検索で辿れる）。
  キャンバスでは控えめなグレー点線の矢印。
- **「更新を確認」（URLカード右クリック）**: 条件付きGET（If-None-Match/If-Modified-Since）
  →304なら変化なし。200なら**同じ変換（本文抽出→md）を通してハッシュ比較**→取得物は
  **破棄**（実身は作らない＝CAS肥大対策 §7-3。実身が増えるのは明示「再取得」だけ）。
  変化があればカードに**更新マーク**（薄赤の控えめなシグナル・強制反映なし・v0.1 §2.3）。
- **「再取得（新しい実身を作る）」**: 取得→新実身カード（プロジェクト直下・カード右隣に配置）
  ＋系譜を更新。**旧実身は残る**（イミュータブル・履歴が自然に溜まる）。未取得の URL では
  初回取得として動く＝web_fetch フィルタなしでも URLカード単体で実身化できる。
- **一括「URLカードの更新を確認」**（キャンバスメニュー「整理・書き出し」）: 取得済み
  URLカードを直列に確認（同一ホスト間隔2秒は §4 共通台帳が担保）・結果サマリを表示。
- 付随: create_url が kind='url' を作成時に確定（migrate 後追い補正への依存を解消）・
  web_fetch ダイアログ文言に URLカード接続を追記・`fetch_url` の条件付きGET対応と
  変換部 `response_to_out` の切り出し（P1 と「更新確認/再取得」で共用）。
- **実機FB（同日修正）: 内容が同一なら実身を増やさない**（§1-3「同一なら CAS 同一ハッシュ＝
  実身は増えない」の着地。連続再取得で同じテキストカードが量産される問題）。
  「再取得」= 条件付きGET（304なら転送なしで「変化なし」）→ 200 でも変換後ハッシュが
  ベースラインと同一なら**実身を作らず** ETag/取得日時だけ最新化。web_fetch フィルタの
  再実行も同様に、そのフィルタの生きた出力カードに同一ハッシュがあれば再利用
  （「変化なし・実身は増やしません」）。
- 単体テスト +2（系譜張り替え/マークのライフサイクル・実機 304〔ignored〕）。回帰 98 件 green。

- **行の横結合（text_paste・paste 相当・N入力)**: 各入力の同じ行番号を区切り文字

- メニューは「テキスト ...」グループに3項目追加。設定ダイアログ（BuiltinFilterDialog）・
  preflight/フロントの出力 MIME 推定（text/plain）も整備。
- **§8-1 決着: text_uniq は立てない** — text_sort の「重複行=除去」（v1.5.13）が用途を
  吸収しており、ソートなしの隣接 dedup が必要になった実例が出たら再考する。

## v1.5.7（2026-07-09）セレクタ設定パネル — 下流に送る情報の宣言

実機フロー（Cコンパイラ→セレクタ→コマンドプロンプト）で見つかった「セレクタを通ると
ファイル名が変わる」問題への対応。フローのペイロードはバイト列＋stem でファイル名を
運ばない設計のため、**ユーザーがセレクタで「下流に送る名前」を宣言できる**ようにした
（上流に本当の名前を問い合わせる参照渡しは v2.0 要求駆動の議論へ）。

- **セレクタ設定パネル**（ダブルクリックで開く。従来は JSON 直編集のみだった）:
  - **出力名**（`prefix` を共用）: 採用した枝のデータをこの名前で下流へ送る（stem 差し替え）。
    「fibo.exe」のように**拡張子付きも可**（最後の . 以降 1〜8 文字の英数字を拡張子と解釈）。
    セレクタ自身を▶実行した場合はこの名前の固定ファイルとして毎回上書き。
  - **エラー時メッセージ**（`fail_text` 新設）: 失敗時矢印の枝を採用したとき、コンパイラ等の
    エラーテキストの代わりにこの文を text/plain で下流へ送る（空欄=従来どおりスルー）。
    エッジに失敗枝フラグ（`EdgeOut.failure`）を追加して判定する。
- 終端の固定名命名: 「fibo.exe」のように拡張子込みで書かれた Prefix に `.ext` を重ねて
  「fibo.exe.exe」にならないようにした（全終端カード共通の寛容化）。
- **シェル終端の pull 評価（実機FB「トリガ→コマンドプロンプトで上流が動かない」対応）**:
  シェルカード（cmd/PowerShell）の `{in}` 解決を2段にした。①直結の実ファイルカード
  （kind='file'・ファイル実在）があればそのライブパス＝従来動作（`notepad {in}` で本物を
  編集できる意味論を維持）。②無ければ**上流を pull 評価**し（eval_filter はシェルを IN/OUT
  同様の素通し扱いに）、採用ペイロードを一時ファイル（{stem}.{ext} 名）へ実体化して渡す。
  これで**トリガ発行→シェルだけでコンパイル〜起動の全パイプラインが動く**（要求駆動の入口）。
  従来はフィルタカードを入力として拾い、存在しない CAS パスに展開されて cmd が
  「The system cannot find the path specified.」になるバグがあった（kind 条件で解消）。
  材料なし＋エラーありのときは窓を開かず報告。入力なしの素のシェルカードは従来どおり。
- テスト: cargo test 70件緑（出力名分解・失敗枝フラグを追加）・tsc / vite build 緑。

## v1.5.3（2026-07-07）オペレーション層 Phase1 — 経路の選択（WS-P1）

`docs/v1.5_実装指示書.md` WS-P1（正本=オペレーション層設計.md §5.4＋§6.1）。pull 評価に
「経路の選択」を導入する土台＝**IN 側だけの工事**（OUT はシングルのまま）。データモデルの
変更は relations.attrs 1本の migration に集約（**NULL=無条件・接続順＝完全後方互換**）。

- **矢印の制御属性（relations.attrs {when, carry, port}）**: フロー矢印クリックが条件メニューに
  （削除は項目へ降格・リンク矢印は従来どおりクリック=削除）。
  - `when`: 常に（既定）／**成功したときだけ**／**失敗したときだけ** — 上流のジョブ内評価結果
    （ok/exit・データ有無）を読む。**条件付き矢印が付いた上流の失敗は、フロー全体のエラー
    ではなく経路選択の情報になる**（失敗の格下げ。条件なし矢印は従来どおりエラー伝搬）。
  - `carry`: 枝が運ぶもの＝既定（成功=出力／失敗=**エラーメッセージ**）・失敗時の入力
    （リトライ材料）・なし（信号のみ＝エッジ属性版ゲート）。
  - 条件付き矢印は中点に小ラベル（成功時/失敗時・信号のみ）。
- **no-data の一級化**: エラーでも空ファイルでもない「枝が取られなかった/材料がなかった」
  第三の結果。既定=伝搬型（入力に no-data があれば自分も実行しない）／spec `nodata:"absorb"`
  =吸収型（欠けたまま残りで実行）。終端が no-data のときは「材料なし」をスキップ欄で報告。
- **セレクタ（builtin:"select"・新カード）**: 入力順の first-match ＝最初に有データを返した
  枝を採用（no-data 吸収を内包）。**exit code 分岐のイディオム**: 同じ上流から成功枝
  （when=成功）と失敗枝（when=失敗）を引き、セレクタで合流 → 成功時は出力・失敗時は
  エラーメッセージが流れる（AI に読ませて判定＝メタ認知の入口）。
- **ジョブスコープメモ化**: 複数下流が同じカードを pull しても**実行は1回**（録音・AI 等の

- カード/コメントが選択された状態でその下の図形をドラッグすると、**選択されたものだけが追従**し、
  非選択は置いていく（選択＝分離の意図）。選択が図形の上に無いときは従来通り全員追従。
  Shift+ドラッグ（図形のみ移動）も従来通り。
- 図形クリックの全選択は**推移的な子図形も含む**ようになり、「クリックで選択される集合＝ドラッグで
  動く集合」が一致。Ctrl+クリックで不要なカード・子図形を外してから図形ドラッグ＝選択だけ分離。

### プロジェクト間コピー/移動 — 送り先で選択状態で迎える
- 完了ダイアログに**「送り先を開く」**ボタン。送り先で新規採番されたIDを覚えておき、送り先を
  開いたとき（後で手動で開いても）**送った物を選択状態にしてビューを寄せる**。
- 着地点で既存カードと重なっても選択済みなので、そのままドラッグで空きキャンバスへ分離できる。

### 「選択を図形で囲む」
- 空きキャンバス右クリックの選択系に追加。選択部（カード＋コメント）の外接矩形＋余白で
  角丸四角を作成し、**図形＋カード選択のまま**渡す。囲んでドラッグ＝混在密集地から選択だけを
  新グループとして引き出せる。

### 矩形選択が図形を拾う
- ラバーバンドに**完全に収まっている図形**は選択に含まれる（はみ出している大きな背景図形は
  選択されない＝交差ではなく内包判定）。混在密集地でも「矩形一発→不要だけ Ctrl+クリックで外す」
  で選択が済む。Ctrl+ドラッグの範囲トグルも図形に効く。

### 図形のグリッドスナップ
- 「図形を追加 ...」サブメニューに**「グリッドにスナップ」**（既定オフ・保存される）。オンの間、
  図形の作成・移動・リサイズの**対角が見えない38px格子にライブ吸着**（カード150×115≒横4×縦3単位）。
  乗ったカードは相対位置を保って追従。カードの配置は自由なまま＝自由レイアウトの流儀と両立。
- **「全図形を今すぐグリッドへ」**: オプションがオフでも使える一括スナップ（Ctrl+Z 一手で戻せる）。

## v1.3.10（2026-06-21〜）窓モデルをカードIDリンクに作り直す（内部/外部レーン分離）

**テーマ: 仮身は内容ハッシュ(real_id)やパスではなく、相手の実身カードを ID（不変）で指す。
プロジェクト内ファイルをユーザーが自由にリネーム／フォルダ分けしても、カードの関係性で
追従できるようにする。設計は `docs/窓モデル設計.md`。本号は窓モデルの核。**

- **内部仮身は `window_of`（実身カードID）で実身を指す**: 「仮身を作成」や重複登録（問題点1）で
  できる内部仮身は、複製元実身のカードIDを window_of に持つ。表示はそのカードの「今の」実ファイル
  を辿るので、**複製元がリネーム・編集されても自動追従**する（内容が同じ実身が複数あっても混同しない）。
- **内部レーン / 外部レーンの分離**: 外部ファイルの仮身（origin_path）の挙動は **1.3.9以前のまま凍結**。
  リンク切れ→赤→CAS参照→materialize は従来どおり。`resolve_view_conn` は ②③④⑤（real_id兄弟／
  origin／CAS／fork）に一切手を入れず、①の直後に内部レーンを1段足すだけ（window_of を持つカード
  だけが通る）。window_of が無い既存カード・外部カードは**従来と完全に同じ経路**。
- **実体喪失で確実に赤**: 内部仮身は指し先カードの「生きた実ファイル」だけを辿り（CAS・real_id兄弟
  には落とさない）、無ければ赤（CAS保険のみ）。＝指し先カードが存在するだけでなく**実体を持つか**で
  判定。リネーム前のCASを黙って映す誤りが消える。
- 実装: `virtual_bodies.window_of` 列追加（best-effort ALTER）。`resolve_live_file`（内部チェーンの
  生きた実ファイルのみ辿る）。`duplicate_virtual`／import_file 問題点1 が window_of を記録。
  list_objects が window_of を返し、フロント `lostOf` が内部仮身の喪失も薄赤に。
- **「仮身を作成」の意味を一本化**: 常に「**このカード自身**」を指す窓を作る（window_of=このカードの
  id）。実身→その実身の窓／仮身→その仮身の窓（仮身の仮身・チェーン）。実身を編集・リネームすると
  追従。メニューは実身・仮身の両方に出す。**「特別→仮身を複製」（窓対象をコピーして元を指す②の
  動作）は廃止**（混乱の元）。
- **バグ修正（make_real）**: 仮身を実身化したとき `window_of` が残っていたため、その後「仮身を作成」
  すると新しい実ファイルでなく**元の実身を指してしまっていた**。実体を持った時点で窓ではなくなるので
  origin_path に加え window_of も NULL クリアし、独立した内部実身にする。
- **TexoS内リネーム（`rename_real`）**: 実身カードの右クリック「実ファイルのリネーム...」で、実体ファイル
  を TexoS から安全に改名（実ファイル改名＋committed_path/mtime/label/ext を一括更新）。**カードIDは不変
  なので window_of で指す仮身は全部自動追従**（OSで改名すると committed_path がずれて赤くなるのを防ぐ）。
  連番ファイル名（FILE (2)）の付け替えにも使える。新名に拡張子が無ければ元拡張子を維持、衝突は (2)。
  プロジェクト外ファイルは対象外。仮身は従来どおり「表示名を変更」（ラベルのみ）。
- **タイトル（ラベル）のダブルクリックでもリネーム**: 普通のファイルカードのラベルをダブルクリック
  → **実身・仮身とも「表示名を変更」に統一**（実身だけ実ファイル改名になると混乱＝UIの気づき2 問題点2）。
  カード本体のダブルクリック＝プレビューと衝突しないよう stopPropagation。フィルタ/ドロップ/プロジェクト/
  URL/フォルダは対象外。実ファイル名の変更は右クリックメニューの「表示名を変更」の**下**に「実ファイル名
  の変更...」として配置。
- **補完（UIの気づき2）**: ①フィルタ/ドロップカードは「アイコン/名前/種類/▶実行」の4行で固定サイズ
  (115px)がいっぱい→実行ログのメモが5行目になり下端でクリップされていた。メモはカード面から外して
  **ホバー(ツールチップ)へ移し**、余白を詰めて4行を確実に収める。③`duplicate_virtual` が `ext`/
  `mime_type` も引き継ぐように（.docx の仮身が実身側の型に落ちて text 扱い→実身化/リネームで .txt に
  なる問題の根治。仮身作成時に元実身の拡張子属性を保全）。
- **リンク矢印を空きキャンバスへ → その場にノードを作って繋ぐ**: カードの接続ハンドルから矢印を
  引き出し、既存カードでなく空きキャンバスに落とすと、ドロップ位置にメニューが出て、選んだものを
  **その場に作成して矢印で繋ぐ**。**カードにできるものは全部**: このカードの仮身を配置（＝引き出し元
  カードの仮身。第一案）／ファイルを配置／テキストカード／コメント／クリップボードから貼り付け／
  URLリンク／フィルタカード（サブメニュー）／**既存プロジェクトへのリンク**（最近のプロジェクト
  一覧＋「その他...」でファイル選択＝相互リンクの礎）。図形は対象外
  （コストが高いため今回見送り）。フィルタのデータフロー記述に対し、思考リンク側を関係づけながら
  生やせる。実装は既存の生成ハンドラに optional `linkFrom` を足し（linkNewNode で繋ぐ）、
  handleStartLink から linkActionsRef 経由で呼ぶ・フロントのみ。Undoは作成＋リンクをまとめて取り消し。
  注: 外部プログラムフィルタは設定ダイアログ経由のため自動リンクは対象外。
- 次（同じ刻みで）: CAS/サムネキャッシュの役割整理、正規化コマンドへの反映

## v1.3.9（2026-06-20〜）ダブルクリック＝閲覧の統一・閲覧は非破壊（インターフェイス固め）

**テーマ: ダブルクリックを「安全（非破壊）」に統一し、編集・実身化・実行を明示操作にする。
オートメーション（v1.5 系）前にインターフェイスを固める大型改修。
設計の全体像は `docs/V1.3.9_閲覧と安全策設計.md`。本号は①と②のインターフェイス部分。**

- **ダブルクリック＝閲覧（非破壊）に統一**: どのカードもダブルクリックで実身化・実行・編集を
  しなくなった。「そのカードが何であるかを、状態を変えずに覗く」だけ。
  - 画像/音声/動画/PDF → キャンバス内インラインプレビュー（従来は動画/PDF が自動実身化だった）。
  - テキスト → **読み取り専用**のインライン表示（従来は即編集だった）。「編集」ボタンで実身化して編集。
  - インラインプレビューが無い種別 → 一時的閲覧（最新内容を読取専用で開き、閉じると破棄）。
  - フィルタカード → **設定を開く**（従来は即フロー実行だった）。実行はメニュー「▶ フローを実行」で明示。
  - プロジェクト📁＝入る／URL＝開く／フォルダ＝開く（従来どおり・いずれも非破壊）。
- **右クリックメニューの先頭に「閲覧」**（＝ダブルクリックと同じ非破壊ディスパッチ）。
- **閲覧では CAS に書き込まない（②）**: 閲覧のたびに CAS スナップショットを取り直していた挙動
  （旧 `refresh_origin_snapshot` の閲覧時呼び出し）を撤去。スナップは実身化（コミット）時のみ。
  これで閲覧による CAS 肥大が止まる。閲覧は常にライブ（origin 優先）を映す。
  - 薄赤（窓喪失）の意味が「最後に見た状態」→「取り込み／最後の実身化時点」に変わる。
- 実装: `read_view_text`（未コミット仮身のライブ内容を読取専用で取得）追加。
  `InlineTextEditor` に読取専用モード（objId 経由ロード・「編集」ボタン）。`ObjectCard` がテキストの
  読取専用／編集を `editPath` の有無で分岐。`handleOpenObject` を純粋な閲覧ディスパッチに書き換え。
- **フィルタ/コマンド/ジェネレータカードの仕上げ**: ダブルクリック＝設定に変わったので
  バッジ文言を整理（「⚙ フィルタ」等・括弧書きの操作説明は削除しホバーへ）。**本物の ▶実行
  ボタンをカード面に追加**（誤爆しない・ジェネレータは「▶ 生成」）。実行結果 memo の紛らわしい
  先頭 ▶ を「✓ 前回:」に変更。カードを「名前／種類／実行ボタン」の3行で統一。
- **重複実身の防止（データ整合の根幹ガード／`docs/UIの気づき.txt` 問題点1）**: プロジェクト
  フォルダ内の実ファイルを2回以上キャンバスに取り込んでも、**2枚目以降は実身ではなく仮身（窓）**
  として登録するようにした。同じ実体を2つの実身が指すと、片方を削除したときにもう片方の窓まで
  壊れる（実ファイルが trash 退避される）――この危険な状態を作らせない。仮身は同 real_id を
  共有し兄弟解決でその実ファイルを映すので見た目・閲覧は実身と同じ、ただし削除しても実体に
  触れない。`import_file` の in_project 経路に重複チェックを追加（同 committed_path の生きた
  カードがあれば仮身化）。
- **実体喪失の実身の再リンク（`docs/UIの気づき.txt` 問題点2）**: プロジェクト内の実ファイルを
  ユーザーがエクスプローラ等でリネーム／フォルダ移動／削除すると、実身カードが実体を見失う
  （プロジェクト直下はフラット前提で、後からの移動は未対応）。従来は黙って CAS スナップショット
  （取り込み時点の古い版）にフォールバックし、そのまま編集・コミットすると最新版を失う恐れがあった
  ＝「大きなロールバック」。本号では:
  - **検出と可視化**: 実体を見失った実身（own/兄弟/origin に届かず CAS/none に落ちた committed
    カード）を**薄赤シグナル**で警告（従来は仮身だけが薄赤対象だった）。ツールチップに
    「実体ファイルが見つかりません・リネーム/移動/削除？」。`model.ts` に `lostRealOf`。
  - **再リンク**（`relink_object`）: 右クリック「実ファイルを再リンク...」→ 移動／改名先の正しい
    ファイルを選ぶ → committed_path / mtime を繋ぎ直す（real_id・CAS は不変）。
  - **CASから復元**: 正しいファイルが無ければ、取り込み時点のスナップショットから実体を書き出す
    （= `commit_object` force）。確認ダイアログ付き。
  - 「黙って古い CAS を使う」自動ロールバックではなく、**ユーザーが選ぶ**形にした（① で編集自体が
    明示操作になったことと併せ、薄赤で気づける）。
- 未実装（後続）: ③正規化コマンド（最新へ確定→履歴を手放す→孤児回収）、②のサイズ閾値ゲートと
  カード個別オーバーライド。`docs/UIの気づき.txt` の問題点3（削除時の共有チェック）・問題点4

## v1.3.6（2026-06-16）ファイルタイプ判定の修復＋実身/仮身メニュー再編

**テーマ1: 空ファイルが型を失う問題の根治（ext/MIME を仮身の属性に）**

症状: Windowsの「新規作成」で作った空ファイル（.docx/.bmp/.odt/.odp 等）を取り込むと、
全部が同じ型（例: 表計算/ODS）になり、ダブルクリックで誤ったアプリが起動した。

- 根因: 空ファイルは内容が同一（0バイト）なので CAS の内容ハッシュが一致し、**1つの実身
  （real_body）を共有**する。`mime_type`/`ext` は実身に紐づくため、最初に取り込んだ空ファイル
  の型を後続の全員が継承していた（`INSERT OR IGNORE` で上書きもされない）。
- 方針: 拡張子/MIME は「そのファイルの見え方」＝**仮身（virtual_body）の属性**として持つ。
  `virtual_bodies` に `ext`/`mime_type` 列を追加し、取り込み時にファイル名から保存。表示・
  オープン（一時ファイル）・コミット名は `COALESCE(仮身, 実身)` で仮身優先（NULL は実身へ
  フォールバック）。フロントは無変更。
- 既存データ補修: プロジェクトを開くたび、ラベルの拡張子から仮身 ext/MIME をバックフィル
  （`backfill_vbody_ext`）。壊れていた既存ファイルも開けば自動で正しい型に直る（自己修復）。
- アプリ起動は従来どおり Windows の既定アプリに従う（`FileProtocolHandler`）。正しい拡張子で
  渡るようになったため、Windowsの「常にこのアプリで開く」がそのまま反映される。

**テーマ2: 実身/仮身メニューの再編**

- 仮身 →「**実身にする**」（`make_real`）: 仮身が指す内容を独立した内部実身に確定し、元ファイル
  との縁を切る（origin を NULL）。以後は仮身に戻す/実身化し直すの対象外（戻り先が無く編集を
  捨てるだけになるため、UI でも出さず、バックエンドにも二重の安全弁 `isInternalReal`）。
- 実身 →「**仮身を作成**」: この実身を指す生きた窓（仮身）を作る。
- 危険・低頻度の操作（実身化し直す/仮身に戻す/仮身を複製/クリップボードにコピー）は
  「**特別 ...**」サブメニューへ退避して優先度を下げた。

## v1.3.4（2026-06-14）クリップボード持ち出し＋用語統一・メニュー再編

**テーマ1: クリップボードの双方向化 第1弾 — カードをファイルとして OS へ持ち出す**

v1.1 で実装済みの「受け（Ctrl+V）」に対し、未実装だった「出す側（Ctrl+C）」を追加。
これでファイルの取り込み／持ち出しがクリップボード経由で一往復する。

- **Ctrl+C** または右クリック「クリップボードにコピー（ファイル）」で、選択カードを
  CF_HDROP（ファイルリスト）として OS クリップボードへ。Explorer・メール・各アプリに
  「ファイルとして」貼り付けできる。複数選択で「全部または一部」を一括コピー。
- **エクスポート＝コミット原則**: 未コミットの仮身はコピー時に自動でコミット（実体化）
  してからパスを載せる。TEMP への孤児コピーを作らない。全タイプ（画像・音声・動画・
  データ・テキスト）を1つのコマンドで賄う。
- フォルダ／プロジェクトリンクは実フォルダのパスをそのまま渡す。
- ファイルを持たないカード（URL・フィルタカード・ドロップポイント）はスキップし、
  内訳をダイアログで通知（全コミットの警告と同じ分類）。全件成功なら無音。
- **内部ペースト（Ctrl+V でファイル）は取り込まず案内ダイアログ**: 「実身のコピーは
  実身になる」という一般原則と仮身（元ファイルへの窓）モデルが衝突するため、クリップボードが
  ファイル（CF_HDROP）のときは取り込まず、「ファイルは D&D で仮身化」「外部へは Ctrl+C」と
  案内する。画像・テキスト・URL の貼り付けは従来どおり。
- テキスト入力中（ダイアログ等）の Ctrl+C は奪わない（ブラウザ標準のコピーを優先）。
- 実装: 生 Win32（`clipboard_out.rs`：OpenClipboard / SetClipboardData / DROPFILES）。
  受け側 `drag_drop.rs` の CF_HDROP 読み取りを逆向きに。`copy_objects_to_clipboard` コマンド。
- 次（v1.3.5 予定）: 画像カードに CF_DIB を追加し、他アプリへ画像として直接貼り付け。

**テーマ2: 用語統一とコンテキストメニュー再編**

機能追加でメニューの動詞と表記が割れていた（単体カードは git 語「コミット」、一括は
「実身化／仮身化」）。**実身/仮身を主語彙に統一し、UI ラベルから「コミット」を消去**

- **用語統一**: 実身化（Materialize）／仮身化（Dematerialize）／実身化し直す／仮身を複製／
  クリップボードにコピー／すべて実身化。キャンバスの「新規プロジェクトを内包（コミット）」も
  「内包」に修正。坂村健・TRON の real/virtual モデルが源流、git の object 衝突を避け
  英語版は object→entity（Real/Virtual entity）。

- 全コミット（データ持ち出し）: プロジェクトフォルダを単体で持ち出せる状態に。
  URL・外部プロジェクト・プログラムリンクは赤警告
- URLのドラッグ&ドロップ取り込み（独自OLEドロップターゲット実装）
- PDF・動画のキャンバス内プレビュー（asset protocol＋WebView2）
- 画像サムネイルのディスクキャッシュ

配布: texos_1.1.0_x64-setup.exe

## v1.0 〜 v1.0.2（2026-06-09〜10）ファーストリリース

構想から3日。「アイデアをデータの関係性で表現する」コンセプトの土台。

- 実身／仮身モデルとCAS（内容アドレス・不変ストレージ）— リソースを傷つけない設計
- プロジェクト＝普通のWindowsフォルダ（.texosに台帳）。内包・分岐フォーク・相互リンク・行き来
- 無限キャンバス（パン・ズーム）、ファイルD&D取り込み、矢印リンクで関係性を表現
- キャンバス内テキスト編集・画像プレビュー・音声再生
- コミットモデル: 仮身→実身化で実ファイル生成、編集破棄して再コミット（タイムマシン）、
  コミット取り消し（仮身に戻す）
- 付箋コメント、URLリンクカード、作業状態（パン・ズーム・展開状態）の永続化
- 単体exe＋インストーラー（NSIS/MSI）

技術スタック: Tauri 2 + React 19 / TypeScript + Rust / SQLite
