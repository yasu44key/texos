## v1.5.1（2026-07-07）ジョブレジストリ — singleton 撤廃と中央 kill スイッチ（WS-B）

`docs/v1.5_実装指示書.md` WS-B（正本=凍結仕様 §12.B）。同時1つを物理強制していた AppState の
singleton フィールド群（flow_cancel / chat_cancel / rec_stdin / flow_running）を **JobId キーの
ジョブ台帳**に置き換えた。WS-C 並行解禁の土台＝内部改修が主で、見た目の変化は Stop-all ボタンのみ。

- **Jobs 台帳**: `Jobs{ map: HashMap<JobId, Arc<Job>> }` を AppState に追加。
  `Job{ id, kind(Flow|Chat), label, started_at, cancel, control(stdin), project_root }`。
  JobId=プロセス内連番・ジョブは揮発（再起動で消える＝凍結 §11.5）。project_root は記録のみ
  （束縛の検査/撤廃は WS-C）。
- **コマンドの job_id 化（一気置き換え・併設なし＝全体方針3)**: `break_flow(job_id)`・
  `flow_send_stdin(job_id, text)`・`ai_chat_cancel(job_id?)`（チャットも起動時に Job 登録）。
  新設 `list_jobs()`（WS-C パネルの土台）・**`cancel_all()`＝中央 kill スイッチ**
  （全ジョブの cancel＋t2i デーモンへ /cancel。子プロセスの物理停止は既存の taskkill /T）。
- **job:\* イベント（WS-C 全規格の先行最小3種）**: `job:started {job_id, kind, label(, card)}` /
  `job:done` / `job:failed {job_id}`。run_flow は完了同期返しを維持しつつ起動時に emit、
  フロントは job_id を保持して停止/中断に使う。
- **同時実行ルールは従来同等**: Flow 同時1（実行中は state.current ロック**前**に従来文言で
  即拒否＝v1.4.10 の教訓の台帳版）・Chat 単一・Flow と Chat は相互並行可。
  プロジェクト切替ガード（ensure_no_flow_running）も台帳判定に置換・挙動不変。
- **t2i 生成の中断を実効化**: デーモン側 /cancel＋step コールバック（v1.4.14 実装済み）に加え、
  中断後に diffusers が返す**部分画像を破棄**するようにした（従来は中途半端な画像カードが
  生まれ得た）。AI フィルタも同様に中断後の応答を破棄（「中断＝出力は破棄」の契約に統一）。
- **UI 最小改修**: 実行中パネルに **Stop-all ボタン**（cancel_all）。停止/中断ボタンは
  job:started で受けた job_id を渡す（背景ジョブパネルは WS-C）。
- テスト: cargo test 35件緑（ライブOllama要3件 ignored）・tsc 緑。

## v1.5.0（2026-07-06）シェルカード統合 — コマンドプロンプト/PowerShell の改修

v1.5系列の最初の号（機能追加のため凍結済み v1.4系ではなく v1.5.0。指示書の WS-B 以降は
v1.5.1〜へ順送り＝号数は目安の原則）。`docs/コマンドプロンプト改修.odt` の要望に対応。
Cの自作ミニフィルタ・Pythonプログラム駆動の利便性向上。

- **メニュー統合（入口2か所に）**: 別メニューに分かれていたランチャー版（開くだけ）と
  対話フィルタ版（一行目設定可）を「**コマンドプロンプト / PowerShell ...**」1項目に統合。
  入口は「自動化カードを追加」のランチャー節と、フロー矢印の引き出しの2か所のみ。
  シェル種別（PowerShell/cmd）は専用設定ダイアログで選ぶ。
- **専用設定ダイアログ**: 外部プログラム用ダイアログの流用をやめた（cmd/powershell で
  「✗ プログラムが見つかりません」の赤エラーが出る不適合を解消）。カード名・シェル・
  コマンド（{in} 可・空欄=開くだけ）・ウィンドウ・制限時間・NOTE のみの最小フォーム。
- **ウィンドウ3モード**（spec に `window` キー追加・未指定=keep で既存カード挙動不変）:
  - `keep`: 開いたまま対話継続（従来どおり cmd /K・powershell -NoExit）
  - `close`: ウィンドウで実行して閉じる（cmd /C・-File のみ）
  - `hidden`: **ウィンドウなし実行＋結果パネル** — stdout/stderr を 2>&1 で時系列マージ捕捉
    （シェルウィンドウに見えるものと同じ並び）し、終了コードと共にパネル表示（コピー可・
    64K字で切り詰め表示）。エンコーディングは UTF-8→推定（cmd 内蔵コマンドの CP932 対応）。
    タイムアウト・中断・ツリーkill・出力上限は run_external_full の既存安全弁をそのまま使用。
- **起動経路の安定化**: ウィンドウあり/なしの全モードが一時スクリプト書き出し
  （write_shell_script）の一本道を通る（引用符の入れ子問題の排除）。
- **カードバッジ「＞_ シェル」**: 従来の「⚙ フィルタ」表示と見分けがつくように
  （配色はコマンド系を流用・テーマ変数の追加なし）。
- **細部**: シェルのウィンドウあり起動後に出ていた空の「フローを実行しました」ダイアログを
  廃止（ウィンドウ自体がフィードバック）。
- **後方互換**: 既存の対話シェルカード（window 無し）= keep 動作のまま・編集は新ダイアログへ。
  既存のランチャー版 cmd/PowerShell カードは従来どおり動作（新規作成の入口だけ撤去）。
- テスト: FilterSpec.window パース＋hidden 捕捉実行（cmd/PowerShell 実プロセス）の3本を追加
  （計35件緑）。tsc 緑。
- **AI系パネルのテーマ追従**（同日追加・ユーザー指摘）: AI設定・t2i設定/セットアップ・
  Whisperセットアップ・AppPicker を `--panel-*` 変数化し、他の設定ダイアログと統一。
  「設定中のアテンション＝暗色固定」の 2026-06-26 決定は改訂（シェル/外部プログラム設定と
  並んだときの不整合が理由）。フッターボタン（キャンセル/保存）は既存のテーマ追従ダイアログと
  同じく固定色のまま。t2iセットアップ内の成功/警告ボックスはアクセント色の半透明ティントに
  変換（ライト/ダークどちらのテーマでも沈まない）。

## v1.4.27（2026-07-05）基盤整備②: Python 実行環境の TexoS 管理化（uv）

t2i（画像生成）の Python 依存を「ユーザーの PC の Python ＋手動 pip」から
**TexoS が自前で構築・所有する環境**へ（計画書 WS2）。

- **runtime/python.rs 新設**: uv（Astral 製・単一 exe）を自動ダウンロードし、
  Python 3.12 の取得 → venv 構築 → torch/diffusers 等の導入まで TexoS が面倒を見る。
  置き場所は `%APPDATA%\com.yoshi.texos\runtime\`（bin/python/cache/envs）。
- **t2i 設定画面から「環境を構築する」ワンクリック**: 進捗表示付き（"python-env" イベント）。
  「pip install してください」という手動導入の案内は廃止。
- **実行環境の選択**: 自動（管理 env 優先→システム Python フォールバック）／TexoS 管理／
  システム、を設定で切替可能。**既存 PC で構築済みのシステム Python 環境はそのまま使い続けられる**。
- **ディスクは肥大しない**: uv のハードリンク共有キャッシュにより、env 1本（GPU 版 torch 込み）で
  実質 ≈4.7GB。2本目以降の env は差分のみ増える（開発機で実測）。
- torch 2.4GiB の DL タイムアウト対策として `UV_HTTP_TIMEOUT=600` を恒久設定。

## v1.4.25（2026-07-03）図形＝思考グループの操作強化 — 分離・囲み・スナップ

`docs/UI追加アイデア.txt` を起点に、図形まわりの選択・移動を一日で連続強化
（開発リビジョン v1.4.21〜v1.4.25 をまとめてリリース）。5つの機能は互いに噛み合う設計:
**矩形で丸ごと選ぶ→囲む→選択だけ引き出す→別プロジェクトへ送って選択のまま受け取る→図形はグリッドで整う**。

### 図形ドラッグの「分離モード」
- カード/コメントが選択された状態でその下の図形をドラッグすると、**選択されたものだけが追従**し、
  非選択は置いていく（選択＝分離の意図）。選択が図形の上に無いときは従来通り全員追従。
  Shift+ドラッグ（図形のみ移動）も従来通り。
- 図形クリックの全選択は**推移的な子図形も含む**ようになり、「クリックで選択される集合＝ドラッグで
  動く集合」が一致。Ctrl+クリックで不要なカード・子図形を外してから図形ドラッグ＝選択だけ分離。

### プロジェクト間コピー/移動 — 送り先で選択状態で迎える
- 完了ダイアログに**「送り先を開く」**ボタン。送り先で新規採番されたIDを覚えておき、送り先を
  開いたとき（後で手動で開いても）**送った物を選択状態にしてビューを寄せる**。
- 着地点で既存カードと重なっても選択済みなので、そのままドラッグで空きキャンバスへ分離できる。

### 「選択を図形で囲む」
- 空きキャンバス右クリックの選択系に追加。選択部（カード＋コメント）の外接矩形＋余白で
  角丸四角を作成し、**図形＋カード選択のまま**渡す。囲んでドラッグ＝混在密集地から選択だけを
  新グループとして引き出せる。

### 矩形選択が図形を拾う
- ラバーバンドに**完全に収まっている図形**は選択に含まれる（はみ出している大きな背景図形は
  選択されない＝交差ではなく内包判定）。混在密集地でも「矩形一発→不要だけ Ctrl+クリックで外す」
  で選択が済む。Ctrl+ドラッグの範囲トグルも図形に効く。

### 図形のグリッドスナップ
- 「図形を追加 ...」サブメニューに**「グリッドにスナップ」**（既定オフ・保存される）。オンの間、
  図形の作成・移動・リサイズの**対角が見えない38px格子にライブ吸着**（カード150×115≒横4×縦3単位）。
  乗ったカードは相対位置を保って追従。カードの配置は自由なまま＝自由レイアウトの流儀と両立。
- **「全図形を今すぐグリッドへ」**: オプションがオフでも使える一括スナップ（Ctrl+Z 一手で戻せる）。

## v1.4.19（2026-07-02）ゴミ箱を開く／カードを検索（Ctrl+F）

### ゴミ箱を開く（データ衛生の出口の完成）
- 空きキャンバス右クリック→**「ゴミ箱を開く ...」**: 削除したカード・コメント・図形を削除日時つきで
  一覧。**「復活」**（UNDO履歴を掃除した後でもいつでも可能・退避ファイルも元の場所へ・復活後は

## v1.3.10（2026-06-21〜）窓モデルをカードIDリンクに作り直す（内部/外部レーン分離）

**テーマ: 仮身は内容ハッシュ(real_id)やパスではなく、相手の実身カードを ID（不変）で指す。
プロジェクト内ファイルをユーザーが自由にリネーム／フォルダ分けしても、カードの関係性で
追従できるようにする。設計は `docs/窓モデル設計.md`。本号は窓モデルの核。**

- **内部仮身は `window_of`（実身カードID）で実身を指す**: 「仮身を作成」や重複登録（問題点1）で
  できる内部仮身は、複製元実身のカードIDを window_of に持つ。表示はそのカードの「今の」実ファイル
  を辿るので、**複製元がリネーム・編集されても自動追従**する（内容が同じ実身が複数あっても混同しない）。
- **内部レーン / 外部レーンの分離**: 外部ファイルの仮身（origin_path）の挙動は **1.3.9以前のまま凍結**。
  リンク切れ→赤→CAS参照→materialize は従来どおり。`resolve_view_conn` は ②③④⑤（real_id兄弟／
  origin／CAS／fork）に一切手を入れず、①の直後に内部レーンを1段足すだけ（window_of を持つカード
  だけが通る）。window_of が無い既存カード・外部カードは**従来と完全に同じ経路**。
- **実体喪失で確実に赤**: 内部仮身は指し先カードの「生きた実ファイル」だけを辿り（CAS・real_id兄弟
  には落とさない）、無ければ赤（CAS保険のみ）。＝指し先カードが存在するだけでなく**実体を持つか**で
  判定。リネーム前のCASを黙って映す誤りが消える。
- 実装: `virtual_bodies.window_of` 列追加（best-effort ALTER）。`resolve_live_file`（内部チェーンの
  生きた実ファイルのみ辿る）。`duplicate_virtual`／import_file 問題点1 が window_of を記録。
  list_objects が window_of を返し、フロント `lostOf` が内部仮身の喪失も薄赤に。
- **「仮身を作成」の意味を一本化**: 常に「**このカード自身**」を指す窓を作る（window_of=このカードの
  id）。実身→その実身の窓／仮身→その仮身の窓（仮身の仮身・チェーン）。実身を編集・リネームすると
  追従。メニューは実身・仮身の両方に出す。**「特別→仮身を複製」（窓対象をコピーして元を指す②の
  動作）は廃止**（混乱の元）。
- **バグ修正（make_real）**: 仮身を実身化したとき `window_of` が残っていたため、その後「仮身を作成」
  すると新しい実ファイルでなく**元の実身を指してしまっていた**。実体を持った時点で窓ではなくなるので
  origin_path に加え window_of も NULL クリアし、独立した内部実身にする。
- **TexoS内リネーム（`rename_real`）**: 実身カードの右クリック「実ファイルのリネーム...」で、実体ファイル
  を TexoS から安全に改名（実ファイル改名＋committed_path/mtime/label/ext を一括更新）。**カードIDは不変
  なので window_of で指す仮身は全部自動追従**（OSで改名すると committed_path がずれて赤くなるのを防ぐ）。
  連番ファイル名（FILE (2)）の付け替えにも使える。新名に拡張子が無ければ元拡張子を維持、衝突は (2)。
  プロジェクト外ファイルは対象外。仮身は従来どおり「表示名を変更」（ラベルのみ）。
- **タイトル（ラベル）のダブルクリックでもリネーム**: 普通のファイルカードのラベルをダブルクリック
  → **実身・仮身とも「表示名を変更」に統一**（実身だけ実ファイル改名になると混乱＝UIの気づき2 問題点2）。
  カード本体のダブルクリック＝プレビューと衝突しないよう stopPropagation。フィルタ/ドロップ/プロジェクト/
  URL/フォルダは対象外。実ファイル名の変更は右クリックメニューの「表示名を変更」の**下**に「実ファイル名
  の変更...」として配置。
- **補完（UIの気づき2）**: ①フィルタ/ドロップカードは「アイコン/名前/種類/▶実行」の4行で固定サイズ
  (115px)がいっぱい→実行ログのメモが5行目になり下端でクリップされていた。メモはカード面から外して
  **ホバー(ツールチップ)へ移し**、余白を詰めて4行を確実に収める。③`duplicate_virtual` が `ext`/
  `mime_type` も引き継ぐように（.docx の仮身が実身側の型に落ちて text 扱い→実身化/リネームで .txt に
  なる問題の根治。仮身作成時に元実身の拡張子属性を保全）。
- **リンク矢印を空きキャンバスへ → その場にノードを作って繋ぐ**: カードの接続ハンドルから矢印を
  引き出し、既存カードでなく空きキャンバスに落とすと、ドロップ位置にメニューが出て、選んだものを
  **その場に作成して矢印で繋ぐ**。**カードにできるものは全部**: このカードの仮身を配置（＝引き出し元
  カードの仮身。第一案）／ファイルを配置／テキストカード／コメント／クリップボードから貼り付け／

## v1.3.6（2026-06-16）ファイルタイプ判定の修復＋実身/仮身メニュー再編

**テーマ1: 空ファイルが型を失う問題の根治（ext/MIME を仮身の属性に）**

症状: Windowsの「新規作成」で作った空ファイル（.docx/.bmp/.odt/.odp 等）を取り込むと、
全部が同じ型（例: 表計算/ODS）になり、ダブルクリックで誤ったアプリが起動した。

- 根因: 空ファイルは内容が同一（0バイト）なので CAS の内容ハッシュが一致し、**1つの実身
  （real_body）を共有**する。`mime_type`/`ext` は実身に紐づくため、最初に取り込んだ空ファイル
  の型を後続の全員が継承していた（`INSERT OR IGNORE` で上書きもされない）。
- 方針: 拡張子/MIME は「そのファイルの見え方」＝**仮身（virtual_body）の属性**として持つ。
  `virtual_bodies` に `ext`/`mime_type` 列を追加し、取り込み時にファイル名から保存。表示・
  オープン（一時ファイル）・コミット名は `COALESCE(仮身, 実身)` で仮身優先（NULL は実身へ
  フォールバック）。フロントは無変更。
- 既存データ補修: プロジェクトを開くたび、ラベルの拡張子から仮身 ext/MIME をバックフィル
  （`backfill_vbody_ext`）。壊れていた既存ファイルも開けば自動で正しい型に直る（自己修復）。
- アプリ起動は従来どおり Windows の既定アプリに従う（`FileProtocolHandler`）。正しい拡張子で
  渡るようになったため、Windowsの「常にこのアプリで開く」がそのまま反映される。

**テーマ2: 実身/仮身メニューの再編**

- 仮身 →「**実身にする**」（`make_real`）: 仮身が指す内容を独立した内部実身に確定し、元ファイル
  との縁を切る（origin を NULL）。以後は仮身に戻す/実身化し直すの対象外（戻り先が無く編集を
  捨てるだけになるため、UI でも出さず、バックエンドにも二重の安全弁 `isInternalReal`）。
- 実身 →「**仮身を作成**」: この実身を指す生きた窓（仮身）を作る。
- 危険・低頻度の操作（実身化し直す/仮身に戻す/仮身を複製/クリップボードにコピー）は
  「**特別 ...**」サブメニューへ退避して優先度を下げた。

## v1.3.4（2026-06-14）クリップボード持ち出し＋用語統一・メニュー再編

**テーマ1: クリップボードの双方向化 第1弾 — カードをファイルとして OS へ持ち出す**

v1.1 で実装済みの「受け（Ctrl+V）」に対し、未実装だった「出す側（Ctrl+C）」を追加。
これでファイルの取り込み／持ち出しがクリップボード経由で一往復する。

- **Ctrl+C** または右クリック「クリップボードにコピー（ファイル）」で、選択カードを
  CF_HDROP（ファイルリスト）として OS クリップボードへ。Explorer・メール・各アプリに
  「ファイルとして」貼り付けできる。複数選択で「全部または一部」を一括コピー。
- **エクスポート＝コミット原則**: 未コミットの仮身はコピー時に自動でコミット（実体化）
  してからパスを載せる。TEMP への孤児コピーを作らない。全タイプ（画像・音声・動画・
  データ・テキスト）を1つのコマンドで賄う。
- フォルダ／プロジェクトリンクは実フォルダのパスをそのまま渡す。
- ファイルを持たないカード（URL・フィルタカード・ドロップポイント）はスキップし、
  内訳をダイアログで通知（全コミットの警告と同じ分類）。全件成功なら無音。
- **内部ペースト（Ctrl+V でファイル）は取り込まず案内ダイアログ**: 「実身のコピーは
  実身になる」という一般原則と仮身（元ファイルへの窓）モデルが衝突するため、クリップボードが
  ファイル（CF_HDROP）のときは取り込まず、「ファイルは D&D で仮身化」「外部へは Ctrl+C」と
  案内する。画像・テキスト・URL の貼り付けは従来どおり。
- テキスト入力中（ダイアログ等）の Ctrl+C は奪わない（ブラウザ標準のコピーを優先）。
- 実装: 生 Win32（`clipboard_out.rs`：OpenClipboard / SetClipboardData / DROPFILES）。
  受け側 `drag_drop.rs` の CF_HDROP 読み取りを逆向きに。`copy_objects_to_clipboard` コマンド。
- 次（v1.3.5 予定）: 画像カードに CF_DIB を追加し、他アプリへ画像として直接貼り付け。

**テーマ2: 用語統一とコンテキストメニュー再編**

機能追加でメニューの動詞と表記が割れていた（単体カードは git 語「コミット」、一括は
「実身化／仮身化」）。**実身/仮身を主語彙に統一し、UI ラベルから「コミット」を消去**
（コード／コマンド名／CAS など内部にのみ残す）。詳細・由緒は `docs/バージョンアップ計画.md`。

- **用語統一**: 実身化（Materialize）／仮身化（Dematerialize）／実身化し直す／仮身を複製／
  クリップボードにコピー／すべて実身化。キャンバスの「新規プロジェクトを内包（コミット）」も
  「内包」に修正。坂村健・TRON の real/virtual モデルが源流、git の object 衝突を避け
  英語版は object→entity（Real/Virtual entity）。
- **ツールチップ＋トグル**: ラベルは動詞だけに絞り、説明はホバーの自前ツールチップへ
  （テーマ色追従）。`MenuItem.hint`、キャンバス右クリックの「メニューの説明を表示」で
  オン/オフ（`showMenuHints`、localStorage 永続）。
- **メニュー再編**: カード／キャンバスメニューを区切り線でカテゴリ分け。複数選択時は
  クリップボードコピー・削除を「まとめて…」サブメニューに一本化（インライン重複を排除）。
- 実装: `ui/ContextMenu.tsx`（divider/hint/tooltip）、`ui/menuBuilder.ts`（全ビルダー）、
  `App.tsx`（showMenuHints 状態・配線）。

## v1.3.3（2026-06-13）オートフロー — フィルタパイプライン

**テーマ: UNIX フィルタパイプラインの GUI 再来 — データ→フィルタ→結果を矢印でつなぐ**

v1.3 後半の本命。カードを「データ→フィルタ→結果」のパイプラインとして接続・実行できる
オートフロー機構を、MVP から連鎖実行・外部コマンド・自己拡張まで一気に実装した。

- **オートフローMVP**: `flow.rs` 新設。内蔵フィルタ（text_grep／text_replace／
  img_resize／img_convert）と外部コマンド（`{in}`/`{out}`）。`virtual_bodies` に
  `kind`／`filter_ref` 列を追加（カード統一モデルの第一歩）。⚗ 緑系カード・ダブルクリック
  実行・flow 矢印（緑破線、型不一致は赤）。フィルタカード接続は自動で `kind='flow'`。
- **パイプライン連鎖実行（pull 型）**: `run_flow` を再帰評価（`eval_filter`）に。フィルタ→
  フィルタを上流から評価し、中間結果はメモリで受け渡し（中間ファイル・中間カードなし）。
  最終段だけが実身カードに。循環検出あり。型チェックは上流フィルタの出力 MIME で照合。
- **ドロップポイント**（`kind='drop'`・データ入口カード）: 投入のたび中身が入れ替わる窓。
  D&D／ダブルクリックで投入 → 下流末端まで自動実行（flow 矢印を BFS で辿る）。青破線＋📥。
- **外部プログラムフィルタ＝プロフェッショナルコマンド**: 設定ダイアログ（`FilterDialog.tsx`：
  NAME／PATH／Type／CMD／IN／出力拡張子／Prefix連番／制限時間、所在の事前チェック付き）。
  exe をファイル選択して標準入出力型／引数型を自動構成。複数入力（`{in*}`集約／`{inN}`位置
  指定）、ジェネレータ型（入力不要）、Type 別カード配色（緑／シアン／琥珀）、Prefix＋連番出力。
- **可搬化・自己拡張ループ**: `.texos/filters` 同梱（解決順＝明示パス→filters→環境変数 PATH）、
  同梱解除は `.removed` 退避で Ctrl+Z 復元。gcc をフィルタ化し成果物を filters へ書き出すと
  自動で同梱コマンド登録される自己拡張まで通る。フィルタライブラリ（プロジェクト横断、
  `app_data/filter_library.json`）に登録／配置／削除。
- **安全弁**: stdin 遮断・タイムアウト・出力 512MB 上限・中断ボタン・taskkill /T のツリー kill・
  stderr 捕捉表示。`run_flow` は async コマンド化。cmd /C への引数は `raw_arg` で素渡し
  （引用符の非互換による exit 1 を修正、回帰テスト追加）。
- **土台整理（リファクタ）**: `App.tsx` を分割（`model.ts`／hooks `useUndo`・`useSelection`／
  `ui/menuBuilder`）。2755 行 → 2038 行、挙動は不変。

## v1.3.2（2026-06-12）UNDO/REDOと一括操作

**テーマ: 操作の取り消し・やり直しの完全対応とUIブラッシュアップ（アイデアメモ２）**

### UNDO / REDO
- UI全体のUNDO（Ctrl+Z）/ REDO（Ctrl+Shift+Z・Ctrl+Y）を実装
  - 対象: 作成（配置・貼り付け・コメント・図形・矢印リンク）、移動（単体・グループ・図形連動）、

    （復活先に同名ファイルができていたら「名前 (2)」形式で衝突回避）
  - 物理削除（行・trashの掃除）は将来の「データの正規化」メンテナンスツールの仕事
