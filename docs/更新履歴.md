## v1.7.0（2026-07-16）web_fetch — Webの実身化・情報収集経路 P1 【v1.7系 開始】

**「Web を実身化する」**号（計画の正本＝[V1.7_情報収集経路計画.md](V1.7_情報収集経路計画.md)）。
v0.1 M1-6（URLキャッシュ・外部実身の仮身化）の宿題回収を v2.0 前に行うシリーズの第1弾。
WebView は埋め込まず、**取得物（本文 Markdown）を実身としてキャンバスに取り込む** —
ページは消えるが実身は残る（水泡に帰さない）。

- **`web_fetch` ビルトイン（L1・メニューに「Web ...」グループ新設＝「OS機能 ...」と同格）**:
  URL → 本文抽出（readability 相当・dom_smoothie）→ **Markdown 実身**（htmd。
  **ページタイトル＝カード名**）。抽出失敗は全文 HTML→MD にフォールバック。
  **text/html 以外の直リンクは raw のまま実身化**（画像/CSV/JSON がこの1カードで済む）。
- **入力両対応（新機構なし）**: パラメータ欄に URL 直書き（入力矢印なしで単独実行可・
  作成時にURLを質問）／テキスト実身を接続（**1行目＝URL**。複数行の展開は P3 の複数出力で）。
- **取得メタの記録（キャッシュモデルの着地・v0.1 §2.3）**: `virtual_bodies.web_meta` 新設。
  {source_url, final_url, fetched_at, etag, last_modified} JSON — P2「更新を確認」
  （条件付きGET→ハッシュ比較→更新マーク）がここを読む。
- **§4 安全最小セットを共通関数化（`web.rs` 新設・P2〜P4 の web_* 系で共用）**:
  タイムアウト30秒・サイズ上限20MB・リダイレクト上限5・同一ホスト最小間隔2秒（プロセス内
  で直列化）・User-Agent 明示（`TexoS/1.7 (+local thinking tool)`）・**プライベートIP遮断**
  （localhost/127.*/10.*/192.168.* 等＋DNS解決先も判定。開発者向けに spec JSON
  `"allow_private": true` で解除可）。明示 pull 原則＝実行した時だけ取りに行く。
- **文字コードは text_convert と分離（§7-4）**: 実身化の瞬間に一度だけ UTF-8 化
  （BOM → HTTPヘッダ charset → meta charset → UTF-8 厳密の順）。判定不能は raw の
  .html のまま実身化 → 後段 text_convert で直す（分離してあるから成立するリカバリ経路）。
- HTTP は既存 reqwest（rustls・blocking・OSスレッド隔離＝run_ai と同流儀）を共用。
  新規クレートは dom_smoothie（MIT）・htmd（Apache-2.0）— ライセンス確認済み（計画 §6-6）。
- チェックリスト全項目: execute_node アーム＋単体テスト12件（プライベートIP判定・URL遮断・
  charset 優先順位・html→md 両経路・実機 example.com 統合〔ignored〕）／BUILTIN_SCHEMAS／
  preflight 出力MIME（不明=None）＋「入力なし」の URL 直書き例外／model.ts filterOutputMime／
  メニュー2系統（共有ビルダー）。回帰 97 件 green。→ ユーザーズチップス **Tip 9**。

## v1.6.0（2026-07-15）カード拡張 — {out*} 複数出力・新規カードを登録・作成規約 【v1.6系 開始】

**ユーザーが自分のプログラムをカードとして登録できる基盤**の号（検討と経緯の正本＝
[V1.6_カード拡張SDK検討.md](V1.6_カード拡張SDK検討.md) §10）。パイロット＝ChillChordMaker
（LoFi シンセ・Python）で「移植」と「TexoS 搭載前提の新規開発（単体でも動く）」の両前例を通した。

- **`{out*}` 複数出力プレースホルダ（実行系の拡張・本号唯一のエンジン改修）**:
  外部プログラム CMD の `{out*}` は**出力フォルダ**に置換され、プログラムはそこへ複数ファイル
  を書ける。終了後に**ファイル名の辞書順**で収集し **1ファイル＝1カード**（縦積み）。
  各ファイルは自分の拡張子で MIME 判定（混在可）・**ファイル名の語幹がカード名**になる
  （例: 進行の書き出し `t_01_1_Dm7.wav` → カード「t_01_1_Dm7」）。順序が意味を持つ出力は
  ゼロ詰め連番で名前に埋める（順序規約）。512MB 上限はフォルダ合計・{out} と {out*} は排他。
- **「新規カードを登録」ビルトイン（OS機能メニュー・builtin:import_new）**:
  対象フォルダ（空＝プロジェクト直下）の未登録ファイルをカードとして登録する作用カード。
  **プロジェクト内＝実身／外部フォルダ＝窓（仮身）**。登録済み（committed_path/origin_path
  照合）・一時ファイル（`~`/`.` 始まり・tmp/part/crdownload/bak）は自動スキップ。
  **ウォッチャ→本カードの req 矢印で「随時登録」パターン**が成立（外部アプリの書き出しや
  フォルダへの直接ドロップが現れるたびにカード化）。→ ユーザーズチップス **Tip 8**。
- **`docs/カード化プログラム作成規約.md` 新設**: プログラムを TexoS カードにするための
  入出力規約＝**AI にプログラム作成を依頼するときに添付する指示書**。3原則
  （①入力は `{in}` から ②出力は `{out}`/`{out*}` へ ③**ファイル入出力はエントリファイルに
  集約**＝main だけ読めば監査できる）＋依頼プロンプトテンプレート＋チェックリスト。
- パイロットの実物: `I:\ChillChordMaker` に純関数コア `render_core.py`（4か所に重複していた
  ディザ/int16 変換を集約・GUI と CLI が同一レンダ経路）とヘッドレスアダプタ `cli_render.py`
  （単音 `--out` / 進行 `--outdir`・規約の模範実装）。
- テスト: {out*} 単体3件＋ChillChordMaker 実機統合2件（単発 WAV / Two-Five-One→3 WAV 辞書順）＋
  import_new 統合1件（登録/スキップ/重複ゼロ/不在エラー）。回帰 86 件 green。

## v1.5.17（2026-07-12）集約系テキストフィルタ — cat・diff・paste 【v1.5系 最終号】

標準フィルタ充実の続き（[標準フィルタ充実検討.md](標準フィルタ充実検討.md) §3 第2候補＝P2）。
「ビルトインは入力1個」の制約を外し、**複数入力を1回で受ける集約系ビルトイン**を導入した号。
§8 の未決論点を全決着（1=text_uniq は立てない・2=P2 は熟成期間中に投入・
4=グループ表示 on/off は実装しない〔トリガ条件付き・詳細は同文書 §8-4〕）。
**本号をもって v1.5 系は完了**（以後はバグフィックスのみ。次の本題は v2.0 系 —
要求駆動・畳み込み・配布・マルチプラットフォーム・t2x ファミリー）。

- **集約の Builtin 対応（実行系の小さな拡張）**: External の集約（CMD の {in*}/{in2}〜で判定）
  に対し、ビルトインは**名前で静的に決まる**（`builtin_is_aggregate()`）。実行は
  `run_builtin_agg()`（全入力を1回で受ける純関数）。入力の並びは既存契約のまま＝
  **port 昇順 → 矢印の接続順**（v1.5.3 WS-P1）。新しい概念は増やしていない。
- **連結（text_concat・cat 相当・N入力)**: 接続順に連結。入力の間は選択式 —
  改行境界の保証（既定・行の融合を防ぐ）／そのまま（純 cat）／空行／Markdown 区切り線 `---`。
- **差分（text_diff・diff -u 相当・2入力固定)**: unified diff を出力（前後の文脈行数は設定・既定3）。
  接続順が 入力1=旧・入力2=新。同一なら出力は空（Unix diff と同じ）。入力が2つでなければ
  明確なエラー。実装は定番 OSS の `similar` クレート（MIT）に乗り自前実装しない。
  出力実身は `.diff`（mime_for_ext に diff/patch = text/plain を追加）。
- **行の横結合（text_paste・paste 相当・N入力)**: 各入力の同じ行番号を区切り文字
  （タブ/カンマ/空白）で横に並べる＝TSV/CSV の列組み立て。行数が違う入力は空欄で埋める
  （GNU paste と同じ）。
- メニューは「テキスト ...」グループに3項目追加。設定ダイアログ（BuiltinFilterDialog）・
  preflight/フロントの出力 MIME 推定（text/plain）も整備。
- **§8-1 決着: text_uniq は立てない** — text_sort の「重複行=除去」（v1.5.13）が用途を
  吸収しており、ソートなしの隣接 dedup が必要になった実例が出たら再考する。

## v1.5.16（2026-07-12）プレビューのリサイズ対応 — 画像・PDF・動画・Office文書

実機FB「テキスト系は拡大縮小できるが、画像・PDF・動画はできない」への対応。
テキストエディタだけ v1.3.1 で先行していたリサイズ（右端ハンドル＋DB永続化）を、
全プレビューへ一般化した号（意図した差ではなく実装の抜けだった）。

- **画像・動画 = 右端ハンドル（横幅）**: 高さは中身のアスペクト比に追従。
  広げれば拡大・狭めれば縮小（従来の maxHeight 上限は撤廃しパネル幅が基準）。
- **PDF・Office文書プレビュー = 右下コーナーハンドル**: 幅と高さを独立に変更。
  Office の HTML 表示（docx/xlsx 等）も同じハンドルで高さが変わる。
- **サイズは カードごとに DB 永続化**（panel_w 既存＋panel_h 列を新設・
  `set_panel_size` コマンド。テキストエディタの旧 `set_panel_width` も統合して削除）。
  次に開いたとき同じ大きさで復元される。整列（格子・重なり解消）の実寸計算も追従。
- 実装は共通フック `panelResize.ts`（InlineTextEditor v1.3.1 方式の一般化。
  キャンバス倍率補正・ドラッグ中は iframe/video の pointer-events を一時停止）。
- 対象外: 音声プレビュー（再生バーのみで固定でも困らない）・t2i 生成パネル（別系統）。

## v1.5.15（2026-07-12）読み上げビルトイン — 外部ヘルパーの軽量導入支援

標準フィルタ充実の続き（[標準フィルタ充実検討.md](標準フィルタ充実検討.md) §9.1）。
L2 OSアダプタ・ビルトイン第1弾と、スクリプト系ヘルパー（jgawk 等）の取り込み設計を実装した号。

- **読み上げ（speak）ビルトイン — L2 OSアダプタ第1弾**:
  テキストを OS の音声合成で読み上げる（Windows=SAPI／macOS=say／Linux=espeak）。
  OS 差は builtin の内側に閉じ込め、カード定義は全 OS 共通＝プロジェクトの可搬性を保つ。
  本文は UTF-8 一時ファイル経由で渡す（日本語の文字化け・引用符・長さの問題を回避）。
  **fire-and-forget＝出力カードは作らない**（camera 系の自己完結コマンドと同じ契約）。
  未対応環境や espeak 未導入は明確なエラー（黙って失敗しない）。
  メニューは「自動化カードを追加」に**「OS機能 ...」グループを新設**して収める。
  実機FBで2件修正（同日）:
  - **読み上げ成功後に「入力がありません」エラーが出ていた**: 終端の出力ゼロ判定
    `is_self_contained()` が外部コマンドしか見ておらず speak builtin が対象外だった → 追加。
  - **音声が固定だった**: SAPI/System.Speech の既定音声は旧 sapi.cpl 設定を見るため、
    **Windows 設定（時刻と言語 > 音声）で切り替えた音声（OneCore 側）が効かない**。
    さらに Windows PowerShell 5.1 の System.Speech は Desktop 系音声しか列挙せず
    名前照合も不可 → **OneCore の既定トークン（DefaultTokenId）を COM の
    SpObjectToken.SetId で直接 SpVoice に挿す**方式に変更（PS 5.1 実機で
    "Microsoft Ayumi - Japanese (Japan)" の選択を確認済み）。
    OneCore キーが無い環境では従来の既定音声のまま（黙って続行）。
  - 付箋（コメント）→ 読み上げの矢印も動く＝付箋はプロンプト定数として text/plain が
    流れる既存仕様（v1.4.17）のまま。
- **既知ヘルパーの軽量導入支援**:
  外部プログラムが見つからないとき（3段解決: 指定パス → .texos\filters → PATH の失敗時）、
  実行エラーとフィルタ設定ダイアログの「✗ 見つかりません」に**💡入手のヒント**を1行添える。
  収録: gawk・awk／pandoc／ffmpeg／jq／nkf（→内蔵 text_convert 案内）／
  grep（→内蔵 text_grep 案内）／python／gcc（正本＝外部依存プログラム一覧.md）。
  ※当初 jgawk の L4→L3 昇格として設計したが、**jgawk は 16bit のみ・開発停止と判明し断念**
  （同日実機知見）。現行の日本語対応 awk は gawk-mbcs-win32 の igawk.exe（内部で gawk.exe を
  呼ぶ・フォルダごと配置＋PATH）で、導入支援対象にせず入手案内のみ。
- **awk スクリプトの持ち方は「両対応」で確立（新機構なし）**:
  短い1行ものは CMD 内に直接（コマンドラインはユーザーが独自に組む＝基本形）、
  長いスクリプトは**実身カードとして持ち `{in2}` で渡す**
  （v1.5 複数入力の既存機構で成立。入力順は矢印の port 順）。スクリプトカードは
  SampleProject.zip 配布に自然に乗る＝GPL バイナリ非同梱の方針と両立。
  レシピ＝[ユーザーズチップス.md](ユーザーズチップス.md) **Tip 6**。

## v1.5.14（2026-07-12）矢印引き出しメニューの対称化 — 新規ファイルはWindows流の型選択に

カードから矢印を空きキャンバスへ引き出したときの「ここに作って矢印で繋ぐ」メニューを、
キャンバス右クリックメニューの「作成・配置」節と同じ名称・並び・構造に対称化した号。

- **矢印引き出しメニューをキャンバスメニューと対称化**:
  クリップボードから貼り付け／ファイルを配置／コメントを追加／新規ファイルを作成／
  URLリンクを追加／自動化カードを追加 — の6項目（＋見出し）。名称もキャンバス側に統一。
  - 「フィルタカード ...」「ランチャーで開く ...」→ **「自動化カードを追加 ...」に統合**
    （キャンバスメニューと同一の共有ビルダー。ランチャー／フィルタ（生成・テキスト・メディア）／
    オペレーション／**ユーザーのカード・モジュール**まで全て引き出しから作って繋げる）。
    ライブラリ管理（右クリック名前編集・削除）はキャンバスメニュー専用のまま。
    モジュール展開は複数カードが生まれ繋ぎ先が一意でないため配置のみ（矢印は張らない）。
  - **「このカードの仮身を配置」を廃止**（カード右クリック「仮身を作成」で代替可能）。
  - **「既存プロジェクトへのリンク ...」→ キャンバスメニュー1階層目へ移設**:
    「**登録プロジェクトへのリンク ...**」として「プロジェクトを作成 ...」「プロジェクトを
    切り替え...」の並びに。登録済み（最近開いた）プロジェクトの一覧から選んでリンクカードを
    置く＝相互リンクの入口。フォルダ選択で**新規に登録しつつ**リンクする従来の
    「既存プロジェクトへのリンクを配置...」（プロジェクトを作成 ... 内）とは別動作のまま。
- **「新規ファイルを作成」を Windows の新規作成メニュー方式に刷新（テキストカード統合）**:
  型（テキスト .txt／Markdown .md／CSV／JSON／HTML）を選ぶと**名前を聞いて**空の
  **仮身カード**を作る（旧テキストカードと同じ CAS 実身経路＝未保存でも消えない）。
  名前欄は名前部分のみで拡張子は自動付与・**空欄なら「新規.拡張子」**。
  「その他の拡張子...」は**名前欄＋拡張子欄の2欄プロンプト**（PromptDialog に2欄目を追加）。
  カードには拡張子バッジが付き、表示名「名前.拡張子」＝**実ファイル名の予約**
  （コミット時にその名でプロジェクトフォルダへ書き出される）。
  空だと壊れる形式（docx 等）は従来方式をサブメニュー末尾「**ファイルブラウザで作成...**」
  に残した（エラーが出る形式はこちらへ、とツールチップで案内）。旧「テキストカード」項目は廃止。

## v1.5.13（2026-07-11）Unixテキストフィルタ内蔵・メニュー再編 — t2i手持ちモデル診断

「標準フィルタ充実検討」（4層モデル・`docs/標準フィルタ充実検討.md`）の P1 実装と、
フィルタが増えたのを機にしたメニューの役割別再編、t2i の手持ちモデル診断をまとめた号。

- **Unix標準テキストフィルタを内蔵（P1・grep/置換と同型の6種）**: 先頭N行（head）・末尾N行（tail）・
  並べ替え（sort。数値比較＝sort -n・重複除去＝sort -u で uniq を吸収）・行数/単語数/文字数（wc）・
  列の取り出し（cut。タブ/カンマ/空白区切り・"1,3-5" 指定）・**文字コード変換（→UTF-8）**。
  文字コードの自動判定は閲覧ビューと同じ手順（BOM→UTF-8→推定）＝表示と変換の結果が一致。
  **nkf が外部プログラム不要になった**（外部依存プログラム一覧を更新・jgawk を追記）。
  全て設定ダイアログ（フォーム）対応・出力MIMEの静的検査（preflight）対応。
- **メニュー再編（「やりたいこと」の言葉で並べる・HD画面の縦収まり対策）**:
  - 「ビルトインフィルタ」の平坦21項目を廃止 → 第一階層に **生成（AI・画像生成）／テキスト／
    メディア（画像・音声・動画）**。「生成」は将来の 3D・音源・動画（t2x ファミリー・
    `docs/生成カード群企画.md`）の受け皿。深さは従来と同じ3段のまま各リスト3〜9項目に。
  - オペレーションも **制御（セレクタ・ドロップポイント）／発行（トリガ・タイマ・ウォッチャ）／
    モジュールの口（IN・OUT）** の3グループへ。セレクタ・ドロップポイントは「データを加工しない
    制御カード」としてフィルタ節からこちらへ移動。
  - **ユーザーのカード/モジュール: 登録名の「/」でカテゴリに畳める**（例 "画像/標準生成" → 📁 画像）。

## v1.5.7（2026-07-09）セレクタ設定パネル — 下流に送る情報の宣言

実機フロー（Cコンパイラ→セレクタ→コマンドプロンプト）で見つかった「セレクタを通ると
ファイル名が変わる」問題への対応。フローのペイロードはバイト列＋stem でファイル名を
運ばない設計のため、**ユーザーがセレクタで「下流に送る名前」を宣言できる**ようにした
（上流に本当の名前を問い合わせる参照渡しは v2.0 要求駆動の議論へ）。

- **セレクタ設定パネル**（ダブルクリックで開く。従来は JSON 直編集のみだった）:
  - **出力名**（`prefix` を共用）: 採用した枝のデータをこの名前で下流へ送る（stem 差し替え）。
    「fibo.exe」のように**拡張子付きも可**（最後の . 以降 1〜8 文字の英数字を拡張子と解釈）。
    セレクタ自身を▶実行した場合はこの名前の固定ファイルとして毎回上書き。
  - **エラー時メッセージ**（`fail_text` 新設）: 失敗時矢印の枝を採用したとき、コンパイラ等の
    エラーテキストの代わりにこの文を text/plain で下流へ送る（空欄=従来どおりスルー）。
    エッジに失敗枝フラグ（`EdgeOut.failure`）を追加して判定する。
- 終端の固定名命名: 「fibo.exe」のように拡張子込みで書かれた Prefix に `.ext` を重ねて
  「fibo.exe.exe」にならないようにした（全終端カード共通の寛容化）。
- **シェル終端の pull 評価（実機FB「トリガ→コマンドプロンプトで上流が動かない」対応）**:
  シェルカード（cmd/PowerShell）の `{in}` 解決を2段にした。①直結の実ファイルカード
  （kind='file'・ファイル実在）があればそのライブパス＝従来動作（`notepad {in}` で本物を
  編集できる意味論を維持）。②無ければ**上流を pull 評価**し（eval_filter はシェルを IN/OUT
  同様の素通し扱いに）、採用ペイロードを一時ファイル（{stem}.{ext} 名）へ実体化して渡す。
  これで**トリガ発行→シェルだけでコンパイル〜起動の全パイプラインが動く**（要求駆動の入口）。
  従来はフィルタカードを入力として拾い、存在しない CAS パスに展開されて cmd が
  「The system cannot find the path specified.」になるバグがあった（kind 条件で解消）。
  材料なし＋エラーありのときは窓を開かず報告。入力なしの素のシェルカードは従来どおり。
- テスト: cargo test 70件緑（出力名分解・失敗枝フラグを追加）・tsc / vite build 緑。

## v1.5.3（2026-07-07）オペレーション層 Phase1 — 経路の選択（WS-P1）

`docs/v1.5_実装指示書.md` WS-P1（正本=オペレーション層設計.md §5.4＋§6.1）。pull 評価に
「経路の選択」を導入する土台＝**IN 側だけの工事**（OUT はシングルのまま）。データモデルの
変更は relations.attrs 1本の migration に集約（**NULL=無条件・接続順＝完全後方互換**）。

- **矢印の制御属性（relations.attrs {when, carry, port}）**: フロー矢印クリックが条件メニューに
  （削除は項目へ降格・リンク矢印は従来どおりクリック=削除）。
  - `when`: 常に（既定）／**成功したときだけ**／**失敗したときだけ** — 上流のジョブ内評価結果
    （ok/exit・データ有無）を読む。**条件付き矢印が付いた上流の失敗は、フロー全体のエラー
    ではなく経路選択の情報になる**（失敗の格下げ。条件なし矢印は従来どおりエラー伝搬）。
  - `carry`: 枝が運ぶもの＝既定（成功=出力／失敗=**エラーメッセージ**）・失敗時の入力
    （リトライ材料）・なし（信号のみ＝エッジ属性版ゲート）。
  - 条件付き矢印は中点に小ラベル（成功時/失敗時・信号のみ）。
- **no-data の一級化**: エラーでも空ファイルでもない「枝が取られなかった/材料がなかった」
  第三の結果。既定=伝搬型（入力に no-data があれば自分も実行しない）／spec `nodata:"absorb"`
  =吸収型（欠けたまま残りで実行）。終端が no-data のときは「材料なし」をスキップ欄で報告。
- **セレクタ（builtin:"select"・新カード）**: 入力順の first-match ＝最初に有データを返した
  枝を採用（no-data 吸収を内包）。**exit code 分岐のイディオム**: 同じ上流から成功枝
  （when=成功）と失敗枝（when=失敗）を引き、セレクタで合流 → 成功時は出力・失敗時は
  エラーメッセージが流れる（AI に読ませて判定＝メタ認知の入口）。
- **ジョブスコープメモ化**: 複数下流が同じカードを pull しても**実行は1回**（録音・AI 等の
  副作用ノードの二重実行防止。分岐イディオムの成立要件）。
- **入力の順序ダイアログ**（カード右クリック「入力の順序 ...」）: 上下ボタンで並べ替え→
  attrs.port へ確定。{in2} 等の位置指定・セレクタの採用順がこの並びに従う（IN ポート方式
  案①の第1段。キャンバス上のポート描画は第2段=後続）。
- **last_run の構造化（§6.1）**: 実行した各フィルタカードに {at, exit, ok, nodata, skipped,
  message} を保存（message=エラーメッセージ＝一級の語彙）。WS-P2 のウォッチャ・運用前評価・
  メタ認知カードが読む口。list_objects が返却（memo の「✓ 前回:」は従来どおり併存）。
- テスト: cargo test 51件緑（+WS-P1 7: エッジ意味論・格下げ・carry・NULL伝搬・attrs パース・
  last_run 保存）・tsc / vite build 緑。

- **セットアップ系の台帳化**: whisper 導入/モデルDL・ffmpeg 導入・Ollama 導入/モデル取得・

## v1.4.25（2026-07-03）図形＝思考グループの操作強化 — 分離・囲み・スナップ

`docs/UI追加アイデア.txt` を起点に、図形まわりの選択・移動を一日で連続強化
（開発リビジョン v1.4.21〜v1.4.25 をまとめてリリース）。5つの機能は互いに噛み合う設計:
**矩形で丸ごと選ぶ→囲む→選択だけ引き出す→別プロジェクトへ送って選択のまま受け取る→図形はグリッドで整う**。

### 図形ドラッグの「分離モード」
- カード/コメントが選択された状態でその下の図形をドラッグすると、**選択されたものだけが追従**し、
  非選択は置いていく（選択＝分離の意図）。選択が図形の上に無いときは従来通り全員追従。
  Shift+ドラッグ（図形のみ移動）も従来通り。
- 図形クリックの全選択は**推移的な子図形も含む**ようになり、「クリックで選択される集合＝ドラッグで
  動く集合」が一致。Ctrl+クリックで不要なカード・子図形を外してから図形ドラッグ＝選択だけ分離。

### プロジェクト間コピー/移動 — 送り先で選択状態で迎える
- 完了ダイアログに**「送り先を開く」**ボタン。送り先で新規採番されたIDを覚えておき、送り先を
  開いたとき（後で手動で開いても）**送った物を選択状態にしてビューを寄せる**。
- 着地点で既存カードと重なっても選択済みなので、そのままドラッグで空きキャンバスへ分離できる。

### 「選択を図形で囲む」
- 空きキャンバス右クリックの選択系に追加。選択部（カード＋コメント）の外接矩形＋余白で
  角丸四角を作成し、**図形＋カード選択のまま**渡す。囲んでドラッグ＝混在密集地から選択だけを
  新グループとして引き出せる。

### 矩形選択が図形を拾う
- ラバーバンドに**完全に収まっている図形**は選択に含まれる（はみ出している大きな背景図形は
  選択されない＝交差ではなく内包判定）。混在密集地でも「矩形一発→不要だけ Ctrl+クリックで外す」
  で選択が済む。Ctrl+ドラッグの範囲トグルも図形に効く。

### 図形のグリッドスナップ
- 「図形を追加 ...」サブメニューに**「グリッドにスナップ」**（既定オフ・保存される）。オンの間、
  図形の作成・移動・リサイズの**対角が見えない38px格子にライブ吸着**（カード150×115≒横4×縦3単位）。
  乗ったカードは相対位置を保って追従。カードの配置は自由なまま＝自由レイアウトの流儀と両立。
- **「全図形を今すぐグリッドへ」**: オプションがオフでも使える一括スナップ（Ctrl+Z 一手で戻せる）。

## v1.3.10（2026-06-21〜）窓モデルをカードIDリンクに作り直す（内部/外部レーン分離）

**テーマ: 仮身は内容ハッシュ(real_id)やパスではなく、相手の実身カードを ID（不変）で指す。
プロジェクト内ファイルをユーザーが自由にリネーム／フォルダ分けしても、カードの関係性で
追従できるようにする。設計は `docs/窓モデル設計.md`。本号は窓モデルの核。**

- **内部仮身は `window_of`（実身カードID）で実身を指す**: 「仮身を作成」や重複登録（問題点1）で
  できる内部仮身は、複製元実身のカードIDを window_of に持つ。表示はそのカードの「今の」実ファイル
  を辿るので、**複製元がリネーム・編集されても自動追従**する（内容が同じ実身が複数あっても混同しない）。
- **内部レーン / 外部レーンの分離**: 外部ファイルの仮身（origin_path）の挙動は **1.3.9以前のまま凍結**。
  リンク切れ→赤→CAS参照→materialize は従来どおり。`resolve_view_conn` は ②③④⑤（real_id兄弟／
  origin／CAS／fork）に一切手を入れず、①の直後に内部レーンを1段足すだけ（window_of を持つカード
  だけが通る）。window_of が無い既存カード・外部カードは**従来と完全に同じ経路**。
- **実体喪失で確実に赤**: 内部仮身は指し先カードの「生きた実ファイル」だけを辿り（CAS・real_id兄弟
  には落とさない）、無ければ赤（CAS保険のみ）。＝指し先カードが存在するだけでなく**実体を持つか**で
  判定。リネーム前のCASを黙って映す誤りが消える。
- 実装: `virtual_bodies.window_of` 列追加（best-effort ALTER）。`resolve_live_file`（内部チェーンの
  生きた実ファイルのみ辿る）。`duplicate_virtual`／import_file 問題点1 が window_of を記録。
  list_objects が window_of を返し、フロント `lostOf` が内部仮身の喪失も薄赤に。
- **「仮身を作成」の意味を一本化**: 常に「**このカード自身**」を指す窓を作る（window_of=このカードの
  id）。実身→その実身の窓／仮身→その仮身の窓（仮身の仮身・チェーン）。実身を編集・リネームすると
  追従。メニューは実身・仮身の両方に出す。**「特別→仮身を複製」（窓対象をコピーして元を指す②の
  動作）は廃止**（混乱の元）。
- **バグ修正（make_real）**: 仮身を実身化したとき `window_of` が残っていたため、その後「仮身を作成」
  すると新しい実ファイルでなく**元の実身を指してしまっていた**。実体を持った時点で窓ではなくなるので
  origin_path に加え window_of も NULL クリアし、独立した内部実身にする。
- **TexoS内リネーム（`rename_real`）**: 実身カードの右クリック「実ファイルのリネーム...」で、実体ファイル
  を TexoS から安全に改名（実ファイル改名＋committed_path/mtime/label/ext を一括更新）。**カードIDは不変
  なので window_of で指す仮身は全部自動追従**（OSで改名すると committed_path がずれて赤くなるのを防ぐ）。
  連番ファイル名（FILE (2)）の付け替えにも使える。新名に拡張子が無ければ元拡張子を維持、衝突は (2)。
  プロジェクト外ファイルは対象外。仮身は従来どおり「表示名を変更」（ラベルのみ）。
- **タイトル（ラベル）のダブルクリックでもリネーム**: 普通のファイルカードのラベルをダブルクリック
  → **実身・仮身とも「表示名を変更」に統一**（実身だけ実ファイル改名になると混乱＝UIの気づき2 問題点2）。
  カード本体のダブルクリック＝プレビューと衝突しないよう stopPropagation。フィルタ/ドロップ/プロジェクト/
  URL/フォルダは対象外。実ファイル名の変更は右クリックメニューの「表示名を変更」の**下**に「実ファイル名
  の変更...」として配置。
- **補完（UIの気づき2）**: ①フィルタ/ドロップカードは「アイコン/名前/種類/▶実行」の4行で固定サイズ
  (115px)がいっぱい→実行ログのメモが5行目になり下端でクリップされていた。メモはカード面から外して
  **ホバー(ツールチップ)へ移し**、余白を詰めて4行を確実に収める。③`duplicate_virtual` が `ext`/
  `mime_type` も引き継ぐように（.docx の仮身が実身側の型に落ちて text 扱い→実身化/リネームで .txt に
  なる問題の根治。仮身作成時に元実身の拡張子属性を保全）。
- **リンク矢印を空きキャンバスへ → その場にノードを作って繋ぐ**: カードの接続ハンドルから矢印を
  引き出し、既存カードでなく空きキャンバスに落とすと、ドロップ位置にメニューが出て、選んだものを
  **その場に作成して矢印で繋ぐ**。**カードにできるものは全部**: このカードの仮身を配置（＝引き出し元
  カードの仮身。第一案）／ファイルを配置／テキストカード／コメント／クリップボードから貼り付け／
  URLリンク／フィルタカード（サブメニュー）／**既存プロジェクトへのリンク**（最近のプロジェクト
  一覧＋「その他...」でファイル選択＝相互リンクの礎）。図形は対象外
  （コストが高いため今回見送り）。フィルタのデータフロー記述に対し、思考リンク側を関係づけながら
  生やせる。実装は既存の生成ハンドラに optional `linkFrom` を足し（linkNewNode で繋ぐ）、
  handleStartLink から linkActionsRef 経由で呼ぶ・フロントのみ。Undoは作成＋リンクをまとめて取り消し。
  注: 外部プログラムフィルタは設定ダイアログ経由のため自動リンクは対象外。
- 次（同じ刻みで）: CAS/サムネキャッシュの役割整理、正規化コマンドへの反映

## v1.3.9（2026-06-20〜）ダブルクリック＝閲覧の統一・閲覧は非破壊（インターフェイス固め）

**テーマ: ダブルクリックを「安全（非破壊）」に統一し、編集・実身化・実行を明示操作にする。
オートメーション（v1.5 系）前にインターフェイスを固める大型改修。
設計の全体像は `docs/V1.3.9_閲覧と安全策設計.md`。本号は①と②のインターフェイス部分。**

- **ダブルクリック＝閲覧（非破壊）に統一**: どのカードもダブルクリックで実身化・実行・編集を
  しなくなった。「そのカードが何であるかを、状態を変えずに覗く」だけ。
  - 画像/音声/動画/PDF → キャンバス内インラインプレビュー（従来は動画/PDF が自動実身化だった）。
  - テキスト → **読み取り専用**のインライン表示（従来は即編集だった）。「編集」ボタンで実身化して編集。
  - インラインプレビューが無い種別 → 一時的閲覧（最新内容を読取専用で開き、閉じると破棄）。
  - フィルタカード → **設定を開く**（従来は即フロー実行だった）。実行はメニュー「▶ フローを実行」で明示。
  - プロジェクト📁＝入る／URL＝開く／フォルダ＝開く（従来どおり・いずれも非破壊）。
- **右クリックメニューの先頭に「閲覧」**（＝ダブルクリックと同じ非破壊ディスパッチ）。
- **閲覧では CAS に書き込まない（②）**: 閲覧のたびに CAS スナップショットを取り直していた挙動
  （旧 `refresh_origin_snapshot` の閲覧時呼び出し）を撤去。スナップは実身化（コミット）時のみ。
  これで閲覧による CAS 肥大が止まる。閲覧は常にライブ（origin 優先）を映す。
  - 薄赤（窓喪失）の意味が「最後に見た状態」→「取り込み／最後の実身化時点」に変わる。
- 実装: `read_view_text`（未コミット仮身のライブ内容を読取専用で取得）追加。
  `InlineTextEditor` に読取専用モード（objId 経由ロード・「編集」ボタン）。`ObjectCard` がテキストの
  読取専用／編集を `editPath` の有無で分岐。`handleOpenObject` を純粋な閲覧ディスパッチに書き換え。
- **フィルタ/コマンド/ジェネレータカードの仕上げ**: ダブルクリック＝設定に変わったので
  バッジ文言を整理（「⚙ フィルタ」等・括弧書きの操作説明は削除しホバーへ）。**本物の ▶実行
  ボタンをカード面に追加**（誤爆しない・ジェネレータは「▶ 生成」）。実行結果 memo の紛らわしい
  先頭 ▶ を「✓ 前回:」に変更。カードを「名前／種類／実行ボタン」の3行で統一。
- **重複実身の防止（データ整合の根幹ガード／`docs/UIの気づき.txt` 問題点1）**: プロジェクト
  フォルダ内の実ファイルを2回以上キャンバスに取り込んでも、**2枚目以降は実身ではなく仮身（窓）**
  として登録するようにした。同じ実体を2つの実身が指すと、片方を削除したときにもう片方の窓まで
  壊れる（実ファイルが trash 退避される）――この危険な状態を作らせない。仮身は同 real_id を
  共有し兄弟解決でその実ファイルを映すので見た目・閲覧は実身と同じ、ただし削除しても実体に
  触れない。`import_file` の in_project 経路に重複チェックを追加（同 committed_path の生きた
  カードがあれば仮身化）。
- **実体喪失の実身の再リンク（`docs/UIの気づき.txt` 問題点2）**: プロジェクト内の実ファイルを
  ユーザーがエクスプローラ等でリネーム／フォルダ移動／削除すると、実身カードが実体を見失う
  （プロジェクト直下はフラット前提で、後からの移動は未対応）。従来は黙って CAS スナップショット
  （取り込み時点の古い版）にフォールバックし、そのまま編集・コミットすると最新版を失う恐れがあった
  ＝「大きなロールバック」。本号では:
  - **検出と可視化**: 実体を見失った実身（own/兄弟/origin に届かず CAS/none に落ちた committed
    カード）を**薄赤シグナル**で警告（従来は仮身だけが薄赤対象だった）。ツールチップに
    「実体ファイルが見つかりません・リネーム/移動/削除？」。`model.ts` に `lostRealOf`。
  - **再リンク**（`relink_object`）: 右クリック「実ファイルを再リンク...」→ 移動／改名先の正しい

## v1.3.6（2026-06-16）ファイルタイプ判定の修復＋実身/仮身メニュー再編

**テーマ1: 空ファイルが型を失う問題の根治（ext/MIME を仮身の属性に）**

症状: Windowsの「新規作成」で作った空ファイル（.docx/.bmp/.odt/.odp 等）を取り込むと、
全部が同じ型（例: 表計算/ODS）になり、ダブルクリックで誤ったアプリが起動した。

- 根因: 空ファイルは内容が同一（0バイト）なので CAS の内容ハッシュが一致し、**1つの実身
  （real_body）を共有**する。`mime_type`/`ext` は実身に紐づくため、最初に取り込んだ空ファイル
  の型を後続の全員が継承していた（`INSERT OR IGNORE` で上書きもされない）。
- 方針: 拡張子/MIME は「そのファイルの見え方」＝**仮身（virtual_body）の属性**として持つ。
  `virtual_bodies` に `ext`/`mime_type` 列を追加し、取り込み時にファイル名から保存。表示・
  オープン（一時ファイル）・コミット名は `COALESCE(仮身, 実身)` で仮身優先（NULL は実身へ
  フォールバック）。フロントは無変更。
- 既存データ補修: プロジェクトを開くたび、ラベルの拡張子から仮身 ext/MIME をバックフィル
  （`backfill_vbody_ext`）。壊れていた既存ファイルも開けば自動で正しい型に直る（自己修復）。
- アプリ起動は従来どおり Windows の既定アプリに従う（`FileProtocolHandler`）。正しい拡張子で
  渡るようになったため、Windowsの「常にこのアプリで開く」がそのまま反映される。

**テーマ2: 実身/仮身メニューの再編**

- 仮身 →「**実身にする**」（`make_real`）: 仮身が指す内容を独立した内部実身に確定し、元ファイル
  との縁を切る（origin を NULL）。以後は仮身に戻す/実身化し直すの対象外（戻り先が無く編集を
  捨てるだけになるため、UI でも出さず、バックエンドにも二重の安全弁 `isInternalReal`）。
- 実身 →「**仮身を作成**」: この実身を指す生きた窓（仮身）を作る。
- 危険・低頻度の操作（実身化し直す/仮身に戻す/仮身を複製/クリップボードにコピー）は
  「**特別 ...**」サブメニューへ退避して優先度を下げた。
