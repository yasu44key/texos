# TexoS 現状評価と発展計画（2026-07-02）

起票: 2026-07-02 / 現在地: **v1.4.16 リリース済み**（プロジェクト間ワークフロー共有・GC・付箋の充実・カラフルUI）。
性格: **棚卸しと企画のディスカッション記録**。号割りの正本は従来どおり
`docs/アイデアメモ検討結果_0626.md`（3本柱）＋`docs/v1.5_並行実行・資源・プロセス通信設計.md`（凍結仕様）。
本書は「v0.1 コンセプトからの到達度評価」と「v1.4 締め → v1.5 → V2.0 の通し計画」を一枚にまとめる。

## 1. 現状評価

### 1.1 定量サマリ

| 項目 | 値 |
|---|---|
| 期間 | v1.0.2（2026-06-09頃）→ v1.4.16（2026-07-01）＝**約3週間で4マイナー系列** |
| コード | TypeScript/TSX 約12,400行 ／ Rust 約9,800行（うち lib.rs 7,265）／ Python 1,050（t2i デーモン） |
| 設計文書 | docs/ に30本超（検討結果・凍結仕様・引き継ぎノート・ユーザーズチップス） |
| 配布 | NSIS インストーラ（`I:\`）、GitHub プライベートリポジトリ同期 |
| 実運用 | 本人が日常運用・NAS 越しの可搬性を別PCで実証済み |

### 1.2 コンセプト達成度（v0.1 仕様との対比）

| コンセプトの核 | 到達度 | 根拠 |
|---|---|---|
| 水泡に帰さない設計 | **達成** | CAS＋ソフトデリート＋UNDO永続化の三重安全網。窓喪失も薄赤シグナルで可視化・復活可能 |
| 思考の外部化 | **達成＋発展** | キャンバス・付箋（色/見出し/サイズ）・図形スコープ・リンク・自動整列。実プロジェクトで常用 |
| AI が前提 | **前倒しで達成** | 当初 V2.0 予定 → v1.4 系で AI-as-module（`builtin:"ai"`/Whisper/T2I）として内蔵。「AIは新種カードでなくフィルタ」という統一が効いた |
| OSS に乗る（全部自前で持たない） | **構造として実証** | Ollama/whisper.cpp/ffmpeg/pandoc/LibreOffice/diffusers を「カタログ化可能な部品」として取り込む型ができた |
| 軽量クロスプラットフォーム配布 | **半分達成** | Tauri で軽量・自己完結プロジェクトは実証。ただし Win32 依存（clipboard_out/drag_drop/os_icon）は隔離済みでも他OSは未検証 |

**総評: v0.1 のスモールプロダクト構想は v1.4.16 で完全に超過達成。**
特に「オートフロー（UNIXパイプのGUI化）× AI-as-module × 実身/仮身モデル」の三位一体は、
類似ツール（ComfyUI＝画像特化・n8n＝クラウド連携・Obsidian＝ノート）のどれとも重ならない
**「ローカル思考OS＋可視パイプライン」という独自ポジション**を確立している。

### 1.3 強み（伸ばすべき資産）

1. **統一モデルの拡張性** — 「カード＝フィルタ＝モジュール」に乗せるだけで機能が増える構造。
   AI/Whisper/T2I/ランチャーが全部この型で入った実績が証明。
2. **開発回転** — 実験リビジョン刻み＋実機チェックリスト＋設計文書化のサイクルが高速で回っている。
   AI協働開発（設計文書＝コンテキスト）との相性が非常に良い。
3. **実運用によるフィードバックループ** — 「使いたい機能優先」が機能の空振りを防いでいる
   （気づき.txt → 検討結果 → 実装 → チップス化、の一気通貫）。
4. **安全網の厚さ** — データ事故系のバグ（空ファイル実身共有・片方削除など）を構造で根治してきた履歴。

### 1.4 リスク・弱点（正直な評価）

1. **lib.rs 7,265行のモノリス** — flow 系は v1.4.10 で `execute_node` に整理済みだが、
   コマンド層が肥大。**v1.5 のジョブレジストリ導入がちょうど切れ目**なので、その際に
   `jobs.rs` / `commands/` 区画化を随伴させるのが低コスト（独立リファクタ号を立てるより安全）。
2. **自動テストが薄い** — flow.rs の単体テストのみ。実機チェックリスト文化は優秀だが回帰が全手動。
   並行実行（v1.5 B/C）はレース系バグの温床なので、**ジョブ層だけでも自動テストを併設**したい。
3. **計画文書の「正本」が世代交代の連鎖** — バージョンアップ計画 → v1.4.0_計画 →
   アイデアメモ検討結果_0626 と注記で上書きが連なり、NEXT_SESSION.md は v1.4.14 止まり。
   **v1.4 安定版宣言のタイミングで正本を1本に畳む**のが良い（本書 §3-H1 に含めた）。
4. **セットアップ体験が普及のボトルネック** — t2i は system Python＋torch、他に
   ffmpeg/LibreOffice/Ollama 等の外部依存。外部依存一覧・セットアップ案内は整備済みだが、
   「知り合いに配る」フェーズでは**最初の30分の体験**が評価を決める。
5. **リリース手順が手動** — バージョン3か所更新・ビルド・I:\ コピー・履歴追記。スクリプト化余地。
6. **ユーザー＝開発者1名** — フィードバックの多様性がない。②知り合いフェーズへの移行判断材料が
   自分の満足度しかない状態。

## 2. 発展性の評価

### 2.1 外部環境（追い風）

- ローカルLLM（Ollama/gemma系）・ローカルASR・ローカル画像生成の成熟が加速しており、
  「ローカルでできることを増やす」路線（3本柱②）は時流と完全に一致。
- MCP エコシステムの拡大は V2.0「フィルタを MCP ツールとして公開」の受け皿が育つことを意味する
  （後送りの判断は正しい。公開時には規格が枯れている）。

### 2.2 発展の3軸

| 軸 | 内容 | 対応ホライズン |
|---|---|---|
| **深化**（オートメーションOS化） | ジョブ・資源・プロセス通信 → exit code 分岐 → ビジュアルコマンド → モジュールカタログ | v1.5 |
| **自律化**（要求駆動） | リクエスタ／アーキテクト／コンストラクタ＋ヒューズ・中央kill の安全設計 | V2.0 |
| **拡散**（共有・配布・公開） | SampleProject.zip → 知り合い配布 → Note/YouTube → OSS判断 | 並走レーン |

3軸は独立に進められるが、**深化が自律化の土台**（ジョブレジストリ＝中央killスイッチ）であり、
**拡散は深化の成果物（カタログ・サンプル）を運ぶ**関係。順序は現ロードマップどおりで正しい。

## 3. 計画提案（3ホライズン＋並走レーン）

### H1: v1.4 系の完了と「安定版宣言」（7月上旬〜中旬）

新規開発を止め、残課題を締めて **「v1.4 安定版」を宣言する号**。完了条件を先に決める:

1. **t2i インライン編集パネル**（ChatPanel 風・ポジ/ネガ欄＋実行ボタン。気づき.txt の★本命）
2. **AIチャットの Ctrl+C コピー不安定**の修正（気づき.txt 既知バグ）
3. **付箋→カード統一（kind='note'）** — 決定済み・未実装の最後のデータモデル課題。
   **v1.5 の「モジュール＝部分グラフ」表現に入る前に済ませる**（カード派生モデルの完成が前提整理になる）
4. 4モーダル（Confirm/Prompt/Filter/ProjectChooser）のテーマ追従（軽微・任意）
5. **文書の正本一本化**: NEXT_SESSION.md を v1.4 安定版時点で全面改訂し、
   バージョンアップ計画.md / v1.4.0_計画.md は「アーカイブ（歴史）」宣言を頭に付けて凍結。
   以後の生きた計画は「本書＋v1.5 凍結仕様＋オートメーション設計メモ」の3本に絞る

**宣言の意味**: 「知り合いに配れる版」のベースライン確定＝拡散レーンの起点。

### H2: v1.5 オートメーション（7月中旬〜8月）

凍結仕様（`v1.5_並行実行・資源・プロセス通信設計.md`）に従う。(A) は v1.4.11 で実装済み。

1. **(B) ジョブレジストリ** — singleton（flow_cancel/chat_cancel/rec_stdin/flow_running）を
   JobId 台帳へ。＝中央 kill スイッチ（V2.0 安全設計の先行部品）
   - **随伴リファクタ**: この号で lib.rs から jobs/commands を区画化（§1.4-1）
   - **随伴テスト**: ジョブのライフサイクル（Queued→Running→Done/Failed/Canceled）の単体テスト
2. **(C) 資源セマフォ＋プロセス通信の一般化** — 資源タクソノミ・ジョブ別 stdin/イベントストリーム
3. **モジュール＝部分グラフ**（共有とモジュール設計.md）→ **モジュールカタログ**
   （nkf/ffmpeg/pandoc… ユーザーズチップスのレシピを「取り込める部品」へ昇格）
4. **exit code 分岐**（成功/失敗で下流を選ぶ）→ キャンバス＝ビジュアル CI/Makefile
5. **ビジュアルコマンド**（図形スコープ＝空間 foreach）・タイマー/トリガーカード

### H3: V2.0 要求駆動・対外公開（9月〜）

- **要求駆動の自律構築**（リクエスタ／アーキテクト／コンストラクタ）＋ヒューズ・並行上限・中央kill
  （`要求駆動と自律安全設計.md` を確定仕様に昇格させるところから）
