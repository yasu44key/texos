## 2. 設計メモ（実装上の判断）

- **属性の分配**: モジュール化で矢印を分割するとき、when/carry（上流の結果を読む条件）は
  上流側エッジへ、port（消費側の入力順）は下流側エッジへ。溶解はこの逆合成＝往復で属性が戻る。
- **モジュール化は Ctrl+Z に積まない**: カード削除だけでは繋ぎ替えた矢印が戻らないため。
  逆操作は「溶解」（案内ダイアログにも明記）。
- **仮身分裂（§8.3 両ロック）は後回し**（指示書どおり）: 両ロック重なりのメンバーは当面
  「動かない側に残る」に倒した（保守的・ロック保全を優先）。
- **op:"in"/"out" は paused/スケジューラ/fire_op の対象外**（発火しない静的 op・§9.4）。
- **縮小警告はリサイズのみ**: 図形移動はメンバー移動の永続化と並走するため、移動まで
  警告対象にすると誤警告になる（Shift+図形のみ移動＝明示の意図として警告なし）。
- **ロック弾きのリセットは命令的**（実機FB修正）: React の VDOM 差分は「座標が変わって
  いない」と DOM を書き戻さないため、state 差し替えでは戻らない。ドラッグ中の transform
  直書きと同じレーン（element.style＋redrawArrowsFor）で戻す。
- **削除ガードの要衝は handleDeleteObject**（実機FB修正）: 右クリック削除・Del 単体が全部
  ここを通る。一括削除（handleBulkDelete）は invoke 直呼びなので入口で別途ガード。
