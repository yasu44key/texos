# TexoS 外部依存プログラム一覧（インストールガイド）

[ユーザーズチップス.md](ユーザーズチップス.md) と対になる資料。チップスが「フィルタの組み方」なら、こちらは「そのフィルタが必要とする外部プログラムは何で、どこから入手し、どう導入するか」をまとめる。

外部プログラムは大きく3種類に分かれる:

1. **アプリが導入を支援** … TexoS が存在を確認し、自動ダウンロードや winget での導入を案内する。
2. **ユーザーが用意** … 外部プログラムフィルタで使う。TexoS は導入まで面倒を見ない（入手・設定はユーザー）。
3. **内蔵で外部不要** … 同名の内蔵フィルタがあり、外部バイナリは要らない。

（[標準フィルタ充実検討.md](標準フィルタ充実検討.md) の4層モデルとの対応: 1＝L3導入支援・2＝L4ユーザー用意・3＝L1ビルトイン。L2=OSアダプタはOS内蔵機能なのでこの一覧には載らない）

> ⚠️ いずれも**再配布時は各プログラムのライセンスを確認**すること。`SampleProject.zip` などにサードパーティ製バイナリを同梱して配るのは避け、入手先の案内を添える（→ チップスの「配布」節）。winget の ID は目安。実際のIDは `winget search <名前>` で確認を。

## 1. アプリが導入を支援

### Ollama — ローカルAI（AIチャット / AI変換フィルタ `builtin:"ai"`）
- **役割**: ローカルで動く LLM。AIカード（チャット／一発変換）のバックエンド。
- **TexoSでの扱い**: チャットパネルが起動状態を確認し、未導入なら winget で自動インストール＋既定モデル `gemma3` の取得まで案内する。OpenAI 準拠エンドポイント（LM Studio 等）に切り替えも可能。
- **入手先**: https://ollama.com/download ／ winget: `Ollama.Ollama`
- **ライセンス**: MIT（Ollama本体）。モデルは各モデルのライセンスに従う。

### Whisper（whisper.cpp）— 音声→テキスト
- **役割**: 録音や音声ファイルを文字起こしするフィルタ。
- **TexoSでの扱い**: whisper.cpp の Windows バイナリとモデル（`ggml-*.bin`）を GitHub / HuggingFace から自動ダウンロードし、`%APPDATA%\com.yoshi.texos\whisper\` で管理（Whisper セットアップダイアログ）。モデルは small / medium などを選択。
- **入手先**: アプリ内セットアップ推奨。手動なら https://github.com/ggerganov/whisper.cpp
- **ライセンス**: MIT。

### ffmpeg — 録音・音声変換（Whisper の前段）
- **役割**: マイク録音、および Whisper に渡す前の音声フォーマット変換。フィルタからは `name="ffmpeg.exe"` で利用。
- **TexoSでの扱い**: 存在を確認し、未導入なら winget で自動導入を案内（導入後は PATH 反映のため要再起動）。
- **入手先**: https://ffmpeg.org/download.html ／ winget: `Gyan.FFmpeg`
- **ライセンス**: LGPL または GPL（ビルド構成による）。再配布時は要確認。

## 2. ユーザーが用意（外部プログラムフィルタ用）

> このグループのプログラムは「ユーザーが組むフィルタ」から呼ばれるため、**TexoS のソースコードには現れない**。コードに無いことは「使っていない」を意味しない（nkf・gcc・Python・pandoc は全てこの形）。

### gcc — C などのコンパイル
- **役割**: ソースをコンパイルする外部フィルタの代表例。AI が出力したコード（.md → コード抽出）を gcc へ渡す、分割ソースを集約してビルド、などのパイプラインを組める。
- **TexoSでの扱い**: 自動導入しない。フィルタの NAME に `gcc`（PATH 解決）または同梱。
- **入手先**: MSYS2（https://www.msys2.org/ → `pacman -S mingw-w64-x86_64-gcc`）、または w64devkit / MinGW-w64。winget: `MSYS2.MSYS2`
- **ライセンス**: GPL（コンパイラ。生成物にはランタイム例外あり）。

### Python — スクリプトフィルタの実行系
- **役割**: Python で書いたフィルタを動かすインタプリタ。NAME=`py`（ランチャ）または `python`、スクリプトは CMD の引数で渡す（Type=command）。
- **TexoSでの扱い**: 自動導入しない。`lang` 指定で拡張子推定（`python`/`py` → `.py`）に対応。
- **入手先**: https://www.python.org/downloads/ ／ winget: `Python.Python.3.12`
- **ライセンス**: PSF（寛容）。

### jgawk — 日本語対応 awk（パターン処理プログラミング）
- **役割**: awk（パターン＋アクションのテキスト処理言語）。内蔵の text_*（grep / cut / sort …）の
  組み合わせでは届かない「条件付きの集計・フィールド演算・整形」を1行〜数行のプログラムで書ける。
  ちょっとしたプログラミングとして細やかなことができる、内蔵フィルタの上の段。
- **awk でなく jgawk なのは日本語を使うため**（日本語対応版 gawk。日本語テキストのフィールド処理が通る）。
- **TexoSでの扱い**: 自動導入しない。バイナリをフィルタの「参照…→同梱⬇」で `.texos\filters` に
  置くか PATH。Type=**フィルタ**（stdin→stdout）で CMD に awk プログラムを書くのが手軽
  （例: `"{ sum += $1 } END { print sum }"` で1列目の合計）。スクリプトが長ければ
  Type=コマンドで `-f スクリプト.awk "{in}"` の形に。
- **入手先**: Vector 等のアーカイブ（jgawk for Windows）。UTF-8 で足りる場合は GNU gawk
  （MSYS2 / GnuWin）＋前段に内蔵 `text_convert` を挟む構成でも代替できる。
- **ライセンス**: GPL。⚠️ 配布物には同梱せず入手案内を添える。

### pandoc — ドキュメント相互変換
- **役割**: 文書フォーマットの相互変換。実際の使い方の例:
  - **docx → プレーンテキスト**: AI に渡す前処理。Word 文書をテキスト化して AI対話カードの「資料」にする。
  - **.md → PDF**: Markdown を配布用 PDF に書き出す。
  - ほか Markdown ↔ docx / HTML など、入出力の拡張子に応じて変換。
- **TexoSでの扱い**: ユーザー導入の外部フィルタ。設定例（実機）: NAME=`pandoc.exe`、Type=**コマンド**、CMD=`"{in}" -o "{out}"`。pandoc は **`{out}` の拡張子から出力形式を推定**するので、「出力拡張子」を `txt` にすればテキスト化、`pdf` にすれば PDF 化になる。
- **入手先**: https://pandoc.org/installing.html ／ winget: `JohnMacFarlane.Pandoc`
- **ライセンス**: GPL。PDF 出力には別途 LaTeX エンジン（例: MiKTeX / TinyTeX）が要ることがある。

## 3. 内蔵で外部不要

### grep
- TexoS は内蔵フィルタ **`text_grep`**（Rust の regex クレート）で正規表現抽出を提供する。**外部の grep バイナリは不要**。
- GNU grep 特有のオプション・挙動が必要なときだけ、別途 GNU grep（GnuWin / MSYS2）を用意して外部フィルタにする。

### nkf（→ 内蔵 `text_convert` で不要化）
- 文字コード変換（Shift_JIS / EUC-JP 等 → UTF-8）は内蔵フィルタ **`text_convert`** が提供する
  （自動判定＋明示指定。encoding_rs / chardetng クレート）。**外部の nkf バイナリは不要**。
- nkf 特有の機能（半角/全角変換・MIME デコード等）が要るときだけ、従来どおり
  Windows バイナリ（nkf32、OSDN ほか）を入手して外部フィルタにする。⚠️ 配布物には同梱せず入手案内を添える。

### head / tail / sort / uniq / wc / cut
- Unix 標準のテキストフィルタは内蔵で提供する（P1・[標準フィルタ充実検討.md](標準フィルタ充実検討.md) §3）:
  **`text_head`**（先頭N行）/ **`text_tail`**（末尾N行）/ **`text_sort`**（並べ替え・数値比較・重複除去=uniq相当）/
  **`text_count`**（行数・単語数・文字数）/ **`text_cut`**（列の取り出し。タブ/カンマ/空白区切り）。
- GNU coreutils 特有の挙動が要るときだけ外部バイナリ（MSYS2 等）を使う。

## メモ
- この一覧は「現在依存していると思われる」ものの棚卸し。新しい外部プログラムをフィルタに使ったら、ここに役割・入手先・ライセンス注意を追記する。
- アプリが導入支援するもの（1）は導入ガイドが UI に組み込まれている。ユーザー用意のもの（2）は、フィルタカードの NOTE 欄やマニュアルに「何を入手してどう設定するか」を書いて配るのが親切。
