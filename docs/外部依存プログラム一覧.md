# TexoS 外部依存プログラム一覧（インストールガイド）

[ユーザーズチップス.md](ユーザーズチップス.md) と対になる資料。チップスが「フィルタの組み方」なら、こちらは「そのフィルタが必要とする外部プログラムは何で、どこから入手し、どう導入するか」をまとめる。

外部プログラムは大きく3種類に分かれる:

1. **アプリが導入を支援** … TexoS が存在を確認し、自動ダウンロードや winget での導入を案内する。
2. **ユーザーが用意** … 外部プログラムフィルタで使う。TexoS は導入まで面倒を見ない（入手・設定はユーザー）。
3. **内蔵で外部不要** … 同名の内蔵フィルタがあり、外部バイナリは要らない。

（[標準フィルタ充実検討.md](標準フィルタ充実検討.md) の4層モデルとの対応: 1＝L3導入支援・2＝L4ユーザー用意・3＝L1ビルトイン。L2=OSアダプタはOS内蔵機能なのでこの一覧には載らない）

> ⚠️ いずれも**再配布時は各プログラムのライセンスを確認**すること。`SampleProject.zip` などにサードパーティ製バイナリを同梱して配るのは避け、入手先の案内を添える（→ チップスの「配布」節）。winget の ID は目安。実際のIDは `winget search <名前>` で確認を。

---

## 0. まず何を入れるか（受け取った人向け）

**TexoS 単体では何も要らない。** テキスト処理・連結・差分・画像のリサイズと形式変換・
文字コード変換・Web取得・記法カードは全部内蔵で動く。**やりたいことが出てきたときに、
その分だけ足せばよい。**

やりたいこと別の最短ルート（詳細は各節）:

- **AI に考えさせたい** → Ollama を入れる（アプリが案内する）。まずは軽いモデル1つで十分。
- **音声を文字にしたい** → ffmpeg ＋ Whisper（どちらもアプリが導入を支援する）
- **画像を作りたい** → 追加インストール不要。**内蔵の画像生成カード**（ただし NVIDIA GPU が要る）
- **3Dモデルを作りたい** → Hunyuan3D-2 のフォルダだけ自分で用意（GPU 必須）
- **Word や PDF を作りたい** → pandoc（PDF は LibreOffice のほうが手軽）
- **音楽サンプルを動かしたい** → Python だけ。プログラムはプロジェクトに同梱されている（§4）
- **C / Java / Python を書かせて動かしたい** → それぞれのコンパイラ・実行系

> **外部プログラムの名前は拡張子まで書くこと**（`python` ではなく `python.exe`）。
> TexoS は PATH のフォルダに名前をそのまま繋いで探すだけで、`.exe` を補わない。
> カードの設定ダイアログに「見つかりません」と出たら、まずここを疑う。

> **winget を使うと速い**（Windows 10/11 標準）。例: `winget install Gyan.FFmpeg`。
> 導入後は PATH の反映のために **TexoS を再起動**すること。

## 1. アプリが導入を支援

### Ollama — ローカルAI（AIチャット / AI変換フィルタ `builtin:"ai"`）
- **役割**: ローカルで動く LLM。AIカード（チャット／一発変換）のバックエンド。
- **TexoSでの扱い**: チャットパネルが起動状態を確認し、未導入なら winget で自動インストール＋既定モデル `gemma3` の取得まで案内する。OpenAI 準拠エンドポイント（LM Studio 等）に切り替えも可能。
- **入手先**: https://ollama.com/download ／ winget: `Ollama.Ollama`
- **ライセンス**: MIT（Ollama本体）。モデルは各モデルのライセンスに従う。

### Whisper（whisper.cpp）— 音声→テキスト
- **役割**: 録音や音声ファイルを文字起こしするフィルタ。
- **TexoSでの扱い**: whisper.cpp の Windows バイナリとモデル（`ggml-*.bin`）を GitHub / HuggingFace から自動ダウンロードし、`%APPDATA%\com.yoshi.texos\whisper\` で管理（Whisper セットアップダイアログ）。モデルは small / medium などを選択。
- **入手先**: アプリ内セットアップ推奨。手動なら https://github.com/ggerganov/whisper.cpp
- **ライセンス**: MIT。

### ffmpeg — 録音・音声変換（Whisper の前段）
- **役割**: マイク録音、および Whisper に渡す前の音声フォーマット変換。フィルタからは `name="ffmpeg.exe"` で利用。
- **TexoSでの扱い**: 存在を確認し、未導入なら winget で自動導入を案内（導入後は PATH 反映のため要再起動）。
- **入手先**: https://ffmpeg.org/download.html ／ winget: `Gyan.FFmpeg`
- **ライセンス**: LGPL または GPL（ビルド構成による）。再配布時は要確認。

### 画像生成（`builtin:"t2i"`）— テキスト→画像
- **役割**: プロンプトから画像を作るカード。**外部プログラムではなく TexoS 内蔵**で、
  裏で常駐する diffusers デーモン（`t2i_server.py`・ポート **8765** 固定）が動く。
- **TexoSでの扱い**: Python 環境も含めて**アプリが用意する**（設定の「Python環境」＝managed）。
  モデルは設定画面から取得（HuggingFace から pull）。手動で置く必要はない。
  - `sd1.5`（`stable-diffusion-v1-5/stable-diffusion-v1-5`）… 軽い。まずこれ
  - `dreamshaper`（`Lykon/dreamshaper-8`）… SD1.5系の絵作り違い
  - `sdxl`（`stabilityai/stable-diffusion-xl-base-1.0`）… 標準的な高品質
  - `flux-lite`（`Freepik/flux.1-lite-8B`）… 新しい系統。重い
- **要るもの**: **NVIDIA GPU（VRAM 6GB〜、SDXL は 8GB以上が快適）**。CPU でも動くが実用的でない。
  初回はモデルのダウンロードで数GB。
- **注意**: **ゲート付きモデル**（FLUX 系など）は、HuggingFace のモデルページで
  「Agree and access repository」を押したうえで、**設定に HF トークンを入れる**必要がある。
  トークンは https://huggingface.co/settings/tokens で作る（read 権限で足りる）。
- **入手先**: アプリ内から。モデルの素性は https://huggingface.co/models で確認できる。
- **ライセンス**: モデルごとに異なる（CreativeML Open RAIL・Apache-2.0 など）。**生成物の
  商用利用可否はモデルのライセンス次第**なので、配布前に各モデルページを確認すること。

### 3D生成（`builtin:"t23d"`）— 画像→3Dモデル(glb)
- **役割**: 1枚の画像から 3D メッシュ（glb）を作るカード。常駐デーモン
  （`t23d_server.py`・ポート **8766** 固定）が Tencent の Hunyuan3D-2 を呼ぶ。
- **TexoSでの扱い**: **エンジン本体だけは自分で用意する**（ここだけ他と違う）。
  Hunyuan3D-2 のリポジトリを取得し、`hy3dgen` フォルダがある場所を
  **設定「t23dエンジンの場所」に絶対パスで指定**する。モデルの取得と常駐管理はアプリがやる。
  - `hunyuan3d-2`（`tencent/Hunyuan3D-2`）… 標準。形状 1.1B ＋テクスチャ 1.3B
  - `hunyuan3d-2-turbo` … 蒸留版で速い
  - 軽量機なら `tencent/Hunyuan3D-2mini`（0.6B）
- **要るもの**: **NVIDIA GPU。形状のみで VRAM 6GB、テクスチャ付きは 16GB**。
- **入手先**: https://github.com/Tencent-Hunyuan/Hunyuan3D-2 ／
  モデル: https://huggingface.co/tencent/Hunyuan3D-2
- **注意**: 出来た glb は **metallic が既定 1.0** で、環境光のない場所では真っ黒に見える。
  TexoS の 3Dビューアは環境光を当てているので問題ないが、他のツールへ持っていくときは注意。
- **ライセンス**: Tencent Hunyuan 3D 2.0 のコミュニティライセンス。**地域・用途の制限があるので
  商用利用の前に必ず原文を読むこと**。

## 2. ユーザーが用意（外部プログラムフィルタ用）

> このグループのプログラムは「ユーザーが組むフィルタ」から呼ばれるため、**TexoS のソースコードには現れない**。コードに無いことは「使っていない」を意味しない（nkf・gcc・Python・pandoc は全てこの形）。

### gcc — C などのコンパイル
- **役割**: ソースをコンパイルする外部フィルタの代表例。AI が出力したコード（.md → コード抽出）を gcc へ渡す、分割ソースを集約してビルド、などのパイプラインを組める。
- **TexoSでの扱い**: 自動導入しない。フィルタの NAME に **`gcc.exe`**（PATH 解決）または同梱。
  ⚠️ **NAME は拡張子まで書くこと。** TexoS は PATH の各フォルダに NAME をそのまま繋いで
  ファイルの有無を見るだけで、`.exe` を補わない（`gcc` では見つからない）。
- **入手先**: MSYS2（https://www.msys2.org/ → `pacman -S mingw-w64-x86_64-gcc`）、または w64devkit / MinGW-w64。winget: `MSYS2.MSYS2`
- **ライセンス**: GPL（コンパイラ。生成物にはランタイム例外あり）。

### Python — スクリプトフィルタの実行系
- **役割**: Python で書いたフィルタを動かすインタプリタ。NAME=**`python.exe`**（または `py.exe`）、
  スクリプトは CMD の引数で渡す（Type=command。例: CMD=`"{in}" > "{out}"`）。
  ⚠️ ここも**拡張子まで書くこと**（`python` では解決に失敗する）。
- **TexoSでの扱い**: 自動導入しない。`lang` 指定で拡張子推定（`python`/`py` → `.py`）に対応。
- **入手先**: https://www.python.org/downloads/ ／ winget: `Python.Python.3.12`
- **ライセンス**: PSF（寛容）。

### ImageMagick（magick.exe）— 画像の細かい加工
- **役割**: 回転・トリミング・合成など、内蔵の `img_resize` / `img_convert` では届かない画像処理。
- **TexoSでの扱い**: 自動導入しない。NAME=`magick.exe`、Type=コマンド。
  設定例（実機）: CMD=`"{in}" -rotate 90 "{out}"`、出力拡張子 `jpg`。
- **入手先**: https://imagemagick.org/script/download.php ／ winget: `ImageMagick.ImageMagick`
- **注意**: v7 から**コマンドは `magick` に一本化**された（旧 `convert.exe` は Windows 標準コマンドと
  名前が衝突するので使わないこと）。
- **ライセンス**: ImageMagick License（Apache-2.0 互換）。

### Java（javac.exe / java.exe）— Java のコンパイルと実行
- **役割**: レシピ「多言語で実行」で使う。AI に書かせた Java を動かす、など。
- **TexoSでの扱い**: 自動導入しない。NAME=`javac.exe`、CMD にコンパイルと実行を `&&` で繋いで1枚にする。
  設定例: CMD=`-d "{out_noext}_cls" "{in}" && java -cp "{out_noext}_cls" Fib > "{out}"`
- **注意**: TexoS は入力を `in_<番号>.java` という一時ファイルで渡すので、
  **`public class` にするとファイル名と一致せず javac が落ちる**。`class Fib` のように public を外す。
- **入手先**: https://adoptium.net/ （Eclipse Temurin）／ winget: `EclipseAdoptium.Temurin.21.JDK`
- **ライセンス**: GPL+Classpath Exception（Temurin）。

### LibreOffice（任意）— PDF や Excel への変換
- **役割**: docx → PDF、csv → xlsx など。pandoc で PDF を出すには LaTeX が要るが、
  LibreOffice なら追加なしで PDF が出せる。
- **TexoSでの扱い**: 自動導入しない。NAME=`soffice.exe`、
  CMD 例=`--headless --convert-to pdf --outdir "<出力先>" "{in}"`。
  ⚠️ **`{out}` を使わない形**なので、出力フォルダ指定（`out_dir`）と組み合わせるか、
  変換後のファイルを「新規カードを登録」で拾う。
- **入手先**: https://ja.libreoffice.org/download/ ／ winget: `TheDocumentFoundation.LibreOffice`
- **ライセンス**: MPL-2.0。

### awk（日本語対応は gawk-mbcs / igawk.exe）— パターン処理プログラミング
- **役割**: awk（パターン＋アクションのテキスト処理言語）。内蔵の text_*（grep / cut / sort …）の
  組み合わせでは届かない「条件付きの集計・フィールド演算・整形」を1行〜数行のプログラムで書ける。
  ちょっとしたプログラミングとして細やかなことができる、内蔵フィルタの上の段。
- **⚠️ jgawk は断念（2026-07-12 実機知見）**: jgawk は 16bit 版しか存在せず開発も停止。
  現在配布されている日本語対応版は **`gawk-mbcs-win32-20051223.zip`**（32bit）で、
  同梱の **`igawk.exe` が日本語対応版（内部で `gawk.exe` を呼ぶ）**。gawk.exe / igawk.exe /
  awklib フォルダ等が一体なので、**フォルダごとプログラムフォルダに配置して PATH を通す**
  （単体 exe の「同梱⬇」には向かない）。開発停止の外部物のため導入支援はせず、この入手案内のみ。
- **TexoSでの扱い**: NAME=`igawk.exe`（PATH 解決）。コマンドラインはユーザーが独自に組む＝
  Type=**フィルタ**（stdin→stdout）で **CMD に awk プログラムを直接書く**のが基本
  （例: `"{ sum += $1 } END { print sum }" < "{in}" > "{out}"` で1列目の合計）。
  スクリプトが長ければ**実身カードとして持ち、2本目の入力 `{in2}` で渡す**形も組める
  （レシピの正本＝[ユーザーズチップス.md](ユーザーズチップス.md) Tip 6）。
  GNU gawk（MSYS2 / GnuWin）が未検出のときは、エラーとフィルタ設定ダイアログに💡入手のヒントが出る
  （v1.5.15 軽量導入支援・既知ヘルパー辞書 `filters.rs helper_hint()`。**この一覧が内容の正本** —
  新しいヘルパーを足したら辞書にも追記する）。
- **入手先**: Vector 等のアーカイブ（gawk-mbcs-win32）。UTF-8 で足りる場合は GNU gawk
  （MSYS2 / GnuWin）＋前段に内蔵 `text_convert` を挟む構成でも代替できる。
- **ライセンス**: GPL。⚠️ 配布物には同梱せず入手案内を添える。

### pandoc — ドキュメント相互変換
- **役割**: 文書フォーマットの相互変換。実際の使い方の例:
  - **docx → プレーンテキスト**: AI に渡す前処理。Word 文書をテキスト化して AI対話カードの「資料」にする。
  - **.md → PDF**: Markdown を配布用 PDF に書き出す。
  - ほか Markdown ↔ docx / HTML など、入出力の拡張子に応じて変換。
- **TexoSでの扱い**: ユーザー導入の外部フィルタ。設定例（実機）: NAME=`pandoc.exe`、Type=**コマンド**、CMD=`"{in}" -o "{out}"`。pandoc は **`{out}` の拡張子から出力形式を推定**するので、「出力拡張子」を `txt` にすればテキスト化、`pdf` にすれば PDF 化になる。
- **入手先**: https://pandoc.org/installing.html ／ winget: `JohnMacFarlane.Pandoc`
- **ライセンス**: GPL。PDF 出力には別途 LaTeX エンジン（例: MiKTeX / TinyTeX）が要ることがある。

## 3. 内蔵で外部不要

### grep
- TexoS は内蔵フィルタ **`text_grep`**（Rust の regex クレート）で正規表現抽出を提供する。**外部の grep バイナリは不要**。
- GNU grep 特有のオプション・挙動が必要なときだけ、別途 GNU grep（GnuWin / MSYS2）を用意して外部フィルタにする。

### nkf（→ 内蔵 `text_convert` で不要化）
- 文字コード変換（Shift_JIS / EUC-JP 等 → UTF-8）は内蔵フィルタ **`text_convert`** が提供する
  （自動判定＋明示指定。encoding_rs / chardetng クレート）。**外部の nkf バイナリは不要**。
- nkf 特有の機能（半角/全角変換・MIME デコード等）が要るときだけ、従来どおり
  Windows バイナリ（nkf32、OSDN ほか）を入手して外部フィルタにする。⚠️ 配布物には同梱せず入手案内を添える。

### head / tail / sort / uniq / wc / cut
- Unix 標準のテキストフィルタは内蔵で提供する（P1・[標準フィルタ充実検討.md](標準フィルタ充実検討.md) §3）:
  **`text_head`**（先頭N行）/ **`text_tail`**（末尾N行）/ **`text_sort`**（並べ替え・数値比較・重複除去=uniq相当）/
  **`text_count`**（行数・単語数・文字数）/ **`text_cut`**（列の取り出し。タブ/カンマ/空白区切り）。
- GNU coreutils 特有の挙動が要るときだけ外部バイナリ（MSYS2 等）を使う。

## 4. サンプルに同梱されるプログラム（入手不要）

自作のプログラムは**プロジェクトの中（`.texos\filters\<名前>\`）に丸ごと同梱して配る**。
受け取った人はフォルダを開くだけでよく、インストール作業は無い（`texos_flow.py` の
`bundle()` がこの形を作る）。**必要なのは Python 本体だけ**で、ライブラリは初回に自分で用意する。

> **可搬シムの規約** — 入口は `<名前>.cmd` の1本。置き場所に一切依存せず、
> Python も venv も実行時に探し、無ければ作る。**venv は本体フォルダの外に置く**
> （venv は作成時の絶対パスを焼き込むので、中に入れるとフォルダ移動で壊れる）。
> ログと進捗は stderr へ出し、stdout は出力データのために空けておく。

### ChillChordMaker — コード進行から和音の wav を書き出す
- **役割**: サンプル「簡易DTM」の素材づくり。進行を指定して `pad_*.wav` を一式生成する。
  GUI でも、カードからのヘッドレス実行でも使える。
- **使い方**: `ccm.cmd gui` で GUI、`ccm.cmd --progression "Two-Five-One" --outdir "<出力先>"` で書き出し。
  初回だけ `ccm.cmd setup`（numpy / scipy / sounddevice を用意。実行時に自動でも走る）。
- **要るもの**: Python 3.10 以降。GUI で試聴するときだけ sounddevice（setup が入れる）。

### wavmix — アレンジ表どおりに wav を重ねて曲にする
- **役割**: 素材の wav を「アレンジ表」（json の実身）に従ってミックスダウンし、1本の曲にする。
  **曲の正本はアレンジ表**で、素材とプログラムはその材料と道具、という組み方の手本。
- **使い方**: `wavmix.cmd --score arrange.json --dir . --out song.wav`。
  初回だけ `wavmix.cmd setup`（numpy / scipy）。
- **要るもの**: Python 3.10 以降。
- **注意**: カードの `--dir "."` は**プロジェクト直下**を指す（TexoS は外部プログラムを
  プロジェクトを作業フォルダにして起動する）。素材をサブフォルダに置くと見つからない。

### ARRANGE — アレンジ表エディタ
- **役割**: アレンジ表（json）を表形式で編集するランチャーカード。
- **要るもの**: Python 3.10 以降。

## 5. 開発だけで使うもの（配布物には不要）

リポジトリの `scripts/` を動かすときだけ要る。**TexoS を使う人には関係ない**。

- **Node.js** … `build_card_catalog.py` が `BuiltinFilterDialog.tsx` のスキーマ表を評価するのに使う。
- **Blender** … `make_sample_data.py` が見本の glb を書き出すのに使う（`--background` で起動）。
- **LibreOffice / pandoc / ImageMagick / ffmpeg** … 見本データ（PDF・docx・xlsx・画像・音・動画）の生成。
  無ければその形式を飛ばして続行する。

## メモ
- この一覧は「現在依存していると思われる」ものの棚卸し。新しい外部プログラムをフィルタに使ったら、ここに役割・入手先・ライセンス注意を追記する。
- アプリが導入支援するもの（1）は導入ガイドが UI に組み込まれている。ユーザー用意のもの（2）は、フィルタカードの NOTE 欄やマニュアルに「何を入手してどう設定するか」を書いて配るのが親切。
