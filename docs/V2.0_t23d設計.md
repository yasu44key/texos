# V2.0_t23d設計 — Image-To-3D カード（Hunyuan3D-2）（2026-07-20）

[生成カード群企画.md](生成カード群企画.md) §6 で決定した t23d 前倒し着手の詳細設計。
「V2.0」と冠するが v2.0 本体を待たず実装する（実装リビジョンは着手時に採番。v1.8 系想定）。

## 0. 決定事項サマリ

- エンジンは **Hunyuan3D-2 WinPortable**（`F:\Hunyuan3D2_WinPortable\Hunyuan3D2_WinPortable`）。
  自己完結の python_standalone を持ち、system Python を汚さない。
- **`t23d_server.py` を新作**（t2x 規約準拠）。同梱 api_server.py の抱き込みはしない
  （/health・/models・/pull・/cancel が無く規約に合わない。パイプライン呼び出しの参考実装として使う）。
- **生成カードは生成のみ**。表示は汎用 **3Dプレビューカード**（three.js・フロントエンドのみ）に分離。
- **サムネイルはプレビューカードの canvas から PNG 書き出し**（案1）。デーモンは関与しない。
- 出力 .glb は**プロジェクトフォルダに普通の実身として保存しカード化**（t2i の PNG 保存と同機構）。

## 1. 全体構成

```
TexoS (Rust)
  ├─ runtime/t23d.rs        … デーモン管理（起動・health照合・pull UI）。runtime/t2i.rs のミラー
  │    └─ 起動: <engine>\..\python_standalone\python.exe -s t23d_server.py --port 8766 --engine <engine>
  │         env: HF_HUB_CACHE=<engine>\..\HuggingFaceHub, PYTHONPYCACHEPREFIX=<engine>\..\pycache
  ├─ python/t23d_server.py  … include_str! で同梱 → app_data に書き出して実行（t2i と同方式）
  └─ フロント
       ├─ t23d カード（集約ノード・NodeKind 追加）… 画像実身＋パラメータ → glb
       └─ 3Dプレビューカード … glb 実身の汎用ビューア＋サムネイル書き出し
```

- `<engine>` = Hunyuan3D-2 リポジトリのフォルダ（hy3dgen がある場所）。**設定項目
  「t23dエンジンの場所」**として絶対パスで持つ（開発機は F: ドライブ。
  [V2.0_マルチプラットフォーム検討.md](V2.0_マルチプラットフォーム検討.md) の
  「絶対パスのトークン化」宿題の対象に追加）。
- ポートは **8766 固定**（t2i の 8765 の隣。接続先は環境非依存、の原則を踏襲）。
- t23d_server.py は `sys.path.insert(0, engine)` して `hy3dgen` を import。
  TexoS 本体は torch にも HF にも触らない。

## 2. デーモン仕様（t2x 規約準拠）

t2i_server.py（SERVER_VERSION 方式）を雛形に、規約 7 項目を同じ形で実装する。

- `GET /health` → `{ok, device, cuda, current_model, loaded, version}`。
  `SERVER_VERSION`（初版 "1"）を Rust 側 `T23D_SERVER_VERSION` と照合、古ければ再起動。
- `GET /models` → `{available, known, current}`。available は HF_HUB_CACHE 内の
  スナップショット診断（t2i_inspect 方式の t23d 版。config.json の有無等で完品判定）。
- `POST /pull {name}` → NDJSON 進捗ストリーム（huggingface_hub の snapshot_download）。
  ※ ポータブル版は主要モデルをダウンロード済みのはずなので、初期は available 表示だけでも成立する。
- `POST /generate` → **glb バイト列**。パラメータ:
  - `image`（base64 PNG・必須）… 主経路は t2i 出力画像。rembg（背景除去）はデーモン内で常時実施
  - `texture`（bool・**既定 false**）… shape のみ / テクスチャ込み
  - `steps`（既定 30）/ `guidance`（既定 5.5）/ `octree_resolution`（既定 256）/ `seed`（既定 1234）
  - `face_count`（texture 時の FaceReducer 上限・既定 40000）
- `POST /cancel` → shape 段は diffusers 系 step callback で**次ステップ境界で中断**
  （t2i と同方式）。texture 段はステージ境界（Remover/Reducer/paint の間）での
  best-effort 中断。部分出力は Rust 側で破棄＝既存契約どおり。
- 毎生成後 `torch.cuda.empty_cache()`。パイプラインは**遅延ロード**
  （初回 /generate 時に構築。texture パイプラインは texture=true が来るまでロードしない）。

### 生成パイプライン（api_server.py から移植）

```
image → rembg → shapegen(Hunyuan3DDiTFlowMatchingPipeline) → [texture=true なら
  FloaterRemover → DegenerateFaceRemover → FaceReducer(face_count) →
  texgen(Hunyuan3DPaintPipeline)] → trimesh export .glb
```

### known リスト（定番限定・POLICY 明記）

- `tencent/Hunyuan3D-2` … 標準（shape 1.1B ＋ paint 1.3B）。shape のみ VRAM 6GB・texture 込み 16GB
- `tencent/Hunyuan3D-2mini` … 軽量 0.6B。低 VRAM 機向け
- turbo（蒸留版・推論高速）は実測して有効なら追加。2mv（マルチビュー）は初版スコープ外
- **ライセンス**: Tencent Hunyuan 3D 2.0 Community License。商用可（月間 1 億アクティブユーザー
  未満）・**EU/英国/韓国では使用不可**・日本 OK。**生成物（Outputs）は Model Derivatives に
  含まれず自由に使える**。known 表示にこの旨を明記する。

## 3. Rust 側 — 規約確立の初戦

- `runtime/t23d.rs` を `runtime/t2i.rs` のミラーとして新設。**共通化できる部分
  （health 照合・version 突き合わせ・child 管理・pull 進捗中継）から `run_gen(kind, spec, inputs)`
  へ一般化**を始める。t2i は挙動不変のまま残す（企画 論点2 の決着どおり）。
- `job.t2i_active` → `job.gen_active(kind)` に一般化（cancel の宛先デーモン特定）。
- **GPU 資源ロック**: v1.5 の並行実行・資源機構に「GPU」資源を載せ、t2i / t23d の生成を
  直列化する（初版は「生成中だけロック」の粒度。VRAM 追い出し規則は複数デーモン常駐が
  現実になってから）。
- タイムアウト: shape 数十秒〜・texture 込みは分単位。既定は t2i の 300 秒より長めに
  （texture 時 900 秒程度から実測で調整）。

## 4. フロント — t23d カード

- t2i と同じ**集約ノード**（NodeKind を 1 つ追加）。入力ピン: 画像実身（必須）。
  テキストピンは付けない（text→3D はエンジン同梱の HunyuanDiT 経由になり品質・責務が
  曖昧になる。文→画は既存 t2i カードの仕事。**「文 →(ai)→ 画 →(t2i)→ →(t23d)→ 3D」の
  カード連結が正道**）。
- パラメータ UI: texture on/off・steps・guidance・octree_resolution・seed（t2i のパラメータ盤を踏襲）。
- 出力: `.glb` をプロジェクトフォルダへ実身保存 → カード化（t2i の PNG 出力と同機構）。

## 5. フロント — 3Dプレビューカード（汎用）

- **フロントエンドのみで完結**。three.js（npm）＋ GLTFLoader ＋ OrbitControls。
  Tauri の `convertFileSrc` で glb 実身を読み込む。GPU デーモン・Python 一切不要。
- **t23d 出力専用にしない** — glb 実身なら出所（Blender 書き出し・web_fetch 取得物）を
  問わず開ける汎用ビューア。生成と表示の分離がそのまま再利用性になる。
- **サムネイル（案1）**: ビューアの canvas を `toDataURL()` で PNG 化し実身の
  サムネイルとして保存する「サムネイル更新」ボタン。ユーザーが良い角度に回してから押す。
  カード面はこの PNG を表示（サムネイル未作成の glb はアイコン表示）。
- ライティングは環境光＋方向光の固定プリセットで開始（HDRI 等は将来）。

## 6. 実装フェーズ

- **Phase 1 — 生成の背骨**: t23d_server.py（shape のみ・health/models/generate/cancel）
  ＋ runtime/t23d.rs（起動管理・固定ポート 8766）＋ t23d カード＋ glb 実身保存。
  確認は Blender / 外部ビューアで。
  **→ 実装済み（2026-07-20）**。デーモン単体の実測（RTX 3090・標準モデル・30步/octree256）:
  初回（モデルロード込み）約6分・ウォーム約35秒・同一シードで同一バイト出力（決定性確認）・
  /cancel はステップ境界（送信後約1秒）で中断確認。known は標準＋turbo の2本
  （ポータブル同梱キャッシュに両方あり）。カード UI は BuiltinFilterDialog のスキーマフォーム
  （専用ダイアログは作らない＝t2i よりだいぶ軽い）。エンジン未設定時はカード作成時に
  場所を聞いて t23d_set_engine で保存。
- **Phase 2 — 見える化**: 3Dプレビューカード＋サムネイル書き出し。ここで
  「画 → 3D → その場で確認」が TexoS 内で閉じる。
  **→ 実装済み（2026-07-20・texture の後に実施）**。実装形態は「専用カード」ではなく
  **glb/gltf 実身カードのインラインプレビュー**（画像/PDF/Doc プレビューと同じ流儀＝
  ダブルクリックで展開・パネルはコーナーリサイズ・panel_w/h 永続化）。
  - GlbPreview.tsx（three.js＋GLTFLoader＋OrbitControls・遅延チャンク 630KB＝開いた時だけロード）。
    データは materialize_view → asset プロトコル（MediaPreview と同経路・base64 往復なし）。
  - **落とし穴（実測で発見）**: Hunyuan の glb は metallicFactor 未指定＝glTF 既定 1.0
    （完全金属）のため、ライトだけでは真っ黒に沈む。three 同梱の RoomEnvironment を
    scene.environment に設定して解決（<model-viewer> の既定と同じ・外部アセット不要）。
  - サムネイル（案1）: 「📷 サムネイル更新」→ canvas.toDataURL → 新コマンド
    save_card_thumbnail が画像カードと同じ .texos/thumbs/<real_id>.jpg へ保存 →
    カード面の表示は get_thumbnail 完全共用（glb 専用の表示コードなし）。
- **Phase 3 — 仕上げ**: texture 対応（texture=true・FaceReducer・タイムアウト調整）・
  /pull UI・known 整備（mini/turbo 実測）・GPU 資源ロックの本組み込み。

### 順序変更＋texture 実装（2026-07-20 追記）

実機 E2E（t2i → t23d → glb カード → 外部ビューア）成功を受け、**Phase 2（プレビューカード）
より texture を先行**することにした（外部ビューアで確認は回る＝パイプライン完成度が先）。
texture は同日実装済み（SERVER_VERSION="2"）:

- カードの「テクスチャ」セレクト（形状のみ/テクスチャ付き・既定=形状のみ）。spec キーは
  `texture:"on"`（select の値をそのまま保存するため文字列）・`face_count`（既定 40000・JSON編集で変更）。
- サーバー側は api_server.py と同手順（FloaterRemover → DegenerateFaceRemover →
  FaceReducer → Hunyuan3DPaintPipeline）。paint は初回 texture 要求で遅延ロード。
  **ポータブル版の texgen は mmgp オフロード前提で `.to(device)` がコメントアウトされている**
  ため、デーモンでは明示的に CUDA へ移して upstream 相当の常駐にした（要 VRAM 実測 16.5GB）。
- cancel は shape 段=ステップ境界、texture 段=ステージ境界（リダクション前後）。paint 内部
  （delight/6視点拡散/ベイク）には中断フックが無い（既知の制約）。
- タイムアウト既定: shape 600 秒・texture 900 秒。
- 実測（RTX 3090・標準モデル・30步/octree256/face_count40000）: 初回（shape＋paint
  ロード込み）約10分・**ウォーム約1分29秒**・出力 1.6MB glb（baseColorTexture 埋め込み・
  面数 4 万に削減済み）。white mesh より軽いのはリダクションのため。

## 7. 宿題・スコープ外

- エンジンパスのトークン化（マルチプラットフォーム宿題と合流）。
- ポータブル版が Hunyuan3D-**2.0** 系のため、2.1（PBR テクスチャ・3.0B）は対象外。
  エンジン側の更新で hy3dgen の API が変わったら SERVER_VERSION で吸収。
- 生成デーモン規約の正文書化（t23d で 2 例目が揃った時点で、規約だけを別ドキュメントに
  切り出す —「t2x 生成デーモン規約」）。
- t2v / t2a は本設計の規約・run_gen 共通部に乗せて後続（企画 §4 の順序どおり）。
