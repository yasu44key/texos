## 2. 設計メモ（実装上の判断）

- **保存形式**: `AppData/modules/<sanitize(名前)>/module.json` ＋ `blobs/`（CAS 形式
  `<先頭2桁>/<残り>`・内容アドレスで重複同梱なし）。単一 JSON への base64 埋め込みはしない
  （§10.1 Fable 導出のとおり）。
- **登録の範囲 = shapes.members（§8.1 ロックスナップショット）＋メンバー直結の IN/OUT**。
  M1 の modularize は members を書き換えなかったため、「ロック→モジュール化→登録」で口が
  漏れる穴があった。M2 で両側から塞いだ: ①モジュール化時にロック中なら IN/OUT を
  add_shape_member で所属へ追加（フロント）②登録時にもメンバーと flow 直結の IN/OUT を
  同伴（backend・既存データ救済）。
- **座標は図形左上からの相対**（§10.1）。展開時はクリック位置が図形の左上になる。
- **ID 全再割当**は send_selection_to_project の id_map 方式（window_of・矢印端点を貼替、
  モジュール外への window_of は NULL）。
- **展開カードは CAS 裏付けの authored コンテンツ**（committed も origin も無し）:
  blobs をプロジェクト CAS へ materialize（§10.2 の文言どおり）し、real_id=ハッシュで指す。
  lostOf の薄赤判定は origin/window を持つ窓カード限定なので、この形は正常表示になる
  （新規テキストカードと同型）。実身化したければ従来の「実身化」コマンドで。
- **プロジェクト参照カード（project_ref）は持ち出さない**（send_selection と同じ）。
  URL・フォルダ参照はそのまま運ぶ（フォルダの絶対パスは環境依存＝割り切り）。
- **タイマ/ウォッチャは paused=true・fired_count リセットで保存**（v1.5.5「停止状態で生成」の
  流儀を新環境展開にも適用）。IN/OUT・トリガは対象外（§9.4 発火しない静的 op／設置型▶）。
- **依存収集は preflight::inspect_dependencies と同じ走査**（collect_requires・cargo test 付き）:
  external/generator の name → programs・builtin:"ai" → provider/model/endpoint・
  t2i / whisper → builtins。展開時チェックは programs=resolve_program（オフライン）・
  ollama=到達のみ（タイムアウト3秒・ロックの外）・t2i=Python 環境・whisper=cli 存在。
  openai 準拠は未検査（preflight と同じ理由＝health 規約が違う）。
- **展開は undo に積まない**（modularize と同じ判断）。片付けはロック解除→削除。
- **巨大データ警告のしきい値 = 100MB**（§10.2 の例のまま。実測で調整可）。
- 配布 = プロジェクト zip（§10.1）: 専用機構は作らない。受け手は展開済みキャンバスから
  「ライブラリに登録」。個人ライブラリの持ち出しは「個人ライブラリをプロジェクトへ書き出し」
  （`ライブラリバックアップ/`）で明示的に。
