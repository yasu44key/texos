## 1. 目的（2026-10-23 ユーザー）

AI カードやフィルタカードは**静的なカード**で、誰かが ▶ を押さないと動かない。これを**声で動かし、声で返事が返る**ようにする。

**いちばんやりたいこと＝TexoS の中で、ローカル AI が問題解決のカードを並べること。**
いまは Python スクリプト（`texos_flow.py`）で別プロジェクトとして組めるが、**コンストラクタカード1枚**に
音声で「〜についてスクレイピングしてレポートにまとめるフローを構築して」と伝えると、
**いま開いているプロジェクトにカードがパラパラと並ぶ**、という形にしたい。

基本の考え方（ユーザー）:

- **音声カード＝振り分け役**。話を聞いて、状況（ユーザーの指示が主）に応じて**複数の AI カードへ別々にフローを流す**。
  会話だけの軽い AI（gemma3）はここで使う。
- **AI カード＝役割つきの働き手**。役割は付箋で渡す（role:"system"）。**モデルは1つでよい**（役割が替われば仕事が替わる）。
  AI カードは、普通の AI カードのほか、**TexoS を操作するカード**（コンストラクタ）、**限られた PC 操作**も動かせる。
- **ローカルで完結する**のが基本。並列にしたくなったら、AI カードの接続先を**別 PC の AI サーバー**に向ける
  （AI カードは接続先を設定できるので、仕組みはある）。Claude は TexoS の外から MCP で見る側（スーパーバイザー）。

```
                ┌─ 役割: プログラミング ─▶ [プログラミング AI] ─▶ ソースコード.txt
                ├─ 役割: スクレイピング ─▶ [スクレイピング AI] ─▶ 検索結果リスト.txt
 🎙 音声 ──req──┼─ 役割: 記録 ──────────▶ [データ整理 AI]   ─▶ 格納フォルダ
 （振り分け）   └─ 役割: カードフロー構築 ▶ [コンストラクタ]   ─▶ カードが並ぶ
```
（2026-10-23 ユーザーの画面の構成。役割の付箋 → AI カードは役割の矢印、音声 → AI カードはリクエスト矢印）

## 2. 決定事項（2026-10-23 ユーザー）

1. **音声カードは振り分け役に徹する**。話し相手の AI は gemma3（Ollama・GPU）。
2. **働き手は役割つきの AI カード**。役割は付箋。モデルは1つでよい。
3. **自動でモデルや役割を入れ替える仕組みは作らない**（ローカルの GPU 1枚では現実的でない）。
   役割の切り替えは「どの AI カードへ流すか」で表す。
4. **コンストラクタの設計図は JSON（ビルダーの呼び出し一覧）**。AI に任意の Python を書かせて実行はしない。
5. **検査の正本は `scripts/texos_flow.py` の `validate()`**。規約を Rust に移植しない（ルールを2か所に置かない）。
6. 実装の順番: **①発話をプロンプトとして渡す → ②役割の付箋で振り分け → ③結果の読み上げ → ④コンストラクタ**。
7. 窓口の応答用 AI と思考役（Strata）を GPU で分け合う: Strata の `vram_reserve_mib` 700 → 5000（§8）。

## 3. いまの音声カード（v1.10）で足りないもの（2026-10-23 コードで確認）

- **話した依頼が AI カードに届かない**。v1.10 は発話の中身を受け皿ファイル（`音声/発話.txt`）に書いてから発火する。
  AI カードがそのファイルを入力にしていないと、AI カードには役割の付箋しか入らない。→ ①
- **振り分けの説明に役割の付箋を使っていない**。窓口が見るのはカード名とカードのコメントの1行目だけ
  （`voice.rs targets_of` の `memo`）。→ ②
- **結果の中身を報告しない**。「○○、終わりました」だけ。→ ③

## 4. ① 発話をプロンプトとして渡す

- 音声カードが発火するとき、**発話の中身を、発火先カードへの入力として直接渡す**（受け皿ファイルを経由しない）。
- 仕組み: ジョブに「このカードへの依頼文」を持たせる（`Job.prompt`）。入力の収集（`flow_run.rs collect_input_edges`）で、
  そのカードの番が来たら差し込む。
  - 通常入力が無い → 依頼文が唯一の入力（`text/plain`）。
  - 通常入力がある（資料つきの AI カードなど）→ テキストの入力それぞれの頭に `【依頼】…【資料】` を付ける
    （入力を1本増やすと AI カードはファンアウトして2回走るため・規約 §3-1）。
  - 入力の中に依頼文と同じ中身がある（受け皿ファイルを入力にしている従来のフロー）→ 差し込まない（二重にしない）。
- 受け皿ファイルへの書き出しは従来どおり続ける（受け皿を読むフローを壊さない）。

## 5. ② 役割の付箋で振り分け ／ ③ 結果の読み上げ

**②** 窓口に渡す選択肢の説明 = カード名 ＋（カードのコメント、無ければ）**そのカードにつながる役割の付箋の冒頭**
（空行まで・最大 160 字）。付箋から音声カードへ矢印を引く必要はない。

**③** 発火したフローが終わったら、**出力の中身の冒頭を読み上げる**。
- 文面: 「○○、終わりました。」＋出力の最初の段落（Markdown の記号を除き、最大 120 字程度）。
- 出力がテキストでなければ「○○、終わりました。ファイル名 ×× を作りました」。
- 発話ログにも結果の冒頭とファイル名を残す。
- 設定 `report`: `fired`（既定・中身つき）/ `brief`（従来の「終わりました」だけ）/ `none`。

## 6. ④ コンストラクタ（カードフロー構築）

### 6.1 形

新しい内蔵カード **`builtin:"construct"`（🏗 コンストラクタ）**。AI カードと同じ接続先・モデルの設定を持つ1枚。

```
 🎙 音声 ─req─▶ [🏗 コンストラクタ] ─▶ 構築レポート.md
                    │ ① 依頼（①の差し込み／付箋／ファイル）＋ 役割の付箋（任意）
                    │ ② AI に設計図（JSON）を書かせる
                    │ ③ texos_flow.py の validate() で検査 → 違反は理由ごと AI に返して直させる（上限あり）
                    │ ④ いま開いているプロジェクトに、枠（図形）で囲んで1枚ずつ並べる
                    ▼
              ［カードが並ぶ］（UNDO 1回で全部消せる）
```

- ▶ を押す（または音声で発火する）ことが「作って」の意思表示。案だけ見たいときは設定 `apply:"draft"` で
  設計図と検査結果をレポートに出すだけにする。
- 並べたカードは**実行しない**（外部プログラムのカードも置くだけ）。試すのは人が ▶ を押してから。

### 6.2 設計図（JSON・ビルダーの呼び出し一覧）

`texos_flow.py` の `Project` のメソッドと同じ言葉。座標は書かせない（並べる側が自動で並べる）。

```json
{ "title": "Python のアナログ時計",
  "calls": [
    { "call": "note", "id": "req",  "text": "依頼\nPython と tkinter で円形のアナログ時計" },
    { "call": "note", "id": "role", "text": "役割：プログラマ\n完全な Python コードを ```python 1ブロックで出す" },
    { "call": "ai",   "id": "gen",  "label": "時計を書く", "prefix": "clock_src" },
    { "call": "builtin", "id": "code", "label": "コード取り出し", "name": "md_codeblock", "prefix": "clock" },
    { "call": "flow", "from": "req",  "to": "gen" },
    { "call": "flow", "from": "role", "to": "gen", "role": "system" },
    { "call": "flow", "from": "gen",  "to": "code" }
  ] }
```

- 受け付ける `call`: `note` `file` `ai` `cat` `builtin` `program` `tap` `ask` `loop` `op_in` `op_out` `flow`。
  **受け付けない**: `copy_file`・`bundle`・`launcher`（PC 上の任意のファイル・プログラムに触る）、発行系の op（タイマ等）。
- AI カードの `model` を省いたら、コンストラクタ自身の設定（`card_model`、無ければ自分のモデル）を使う。
- 実行役 = `python/texos_plan.py`（新規・TexoS に埋め込み、起動時に app_data へ書き出す）。設計図を `Project` の
  呼び出しに直し、`validate()` を呼び、通ればカード・矢印・設定（filter_ref の JSON）を JSON で返す。
  **`save()` は呼ばない**（DB には書かない）。`texos_flow.py` も同じく埋め込む（標準ライブラリだけで動く）。

### 6.3 AI に渡すもの

- **構築の要点**（新規 `python/construct_guide.md`・埋め込み）: 受け付ける `call` と引数、内蔵カードの一覧、
  配線の決まりの要点（ファンアウト・役割の矢印・案と実行の間に実身・外部プログラムは拡張子まで）。
  規約全文（約 15k トークン）は渡さない — 細かい違反は `validate()` が弾いて返す分担。
- 役割の付箋（つながっていれば）を要点の後ろに足す（作法をキャンバスで直せる）。
- 依頼文。
- 出力は JSON のみ（Ollama `format:"json"`／OpenAI 互換 `response_format:{type:"json_object"}`）。

### 6.4 並べ方

- 場所: いまあるカード全体の**下**（コンストラクタの x、全カードの最下端 ＋ 余白）。枠（図形）に設計図の `title`。
- 配置: 矢印の深さで列（左→右）、同じ深さは縦に。1枚ずつ少し間を置いて置く（`mcp:changed` で画面に出す）。
- UNDO: 置いたカード・付箋・矢印・枠を1回で消せるように、最後にまとめて積む。
- 置く処理は MCP と同じ `*_in(&Project)`（`create_filter_in` `create_note_in` `create_relation_in` `set_relation_attrs_in`
  `import_file_into` `create_shape`）。

### 6.5 規約との関係

規約 §5-2 は「開いているプロジェクトに外から直接書かない」（①面に出ない ②座標がぶつかる ③2回流すと二重）。
TexoS 自身が並べるので①は起きない。②は空いている下側に枠で囲んで置く。③は流すたびに新しい枠として置く
（消すのは UNDO）。規約に「TexoS 内のコンストラクタはこの例外」と書き足す。

### 10.2 ①〜④（2026-10-23）

- **①** `Job.prompt`（lib.rs）＋ `flow_run.rs inject_prompt`（`collect_input_edges` の最後）＋ `run_flow_with_prompt`。
  音声カードの発火（`voice.rs`）が `run_flow_for` → `run_flow_with_prompt(発火先, 中身)`。受け皿ファイルは従来どおり書く。
  差し込みはトレースに「音声からの依頼」として残る。テスト `inject_prompt_tests`（入力なし／資料つき／受け皿と同じ中身）。
- **②** `voice.rs role_note_of`（role:"system" の矢印でつながる付箋）・`describe`（見出しがカード名なら飛ばし、最初の段落を
  160 字まで）。カードのコメントがあればそちらを優先。
- **③** `voice.rs result_summary` / `speakable_head`（コードブロック・見出し・箇条書き記号・強調を落とし、最初の段落を
  120 字・句点で切る）。発話ログに「📄 ファイル名：冒頭」。`report:"brief"` で従来の「終わりました」だけ。
- **④** `construct.rs`（新規）＋ `python/texos_plan.py`（新規・訳し役）＋ `python/construct_guide.md`（新規・AI に渡す要点）。
  `texos_flow.py` も `include_str!` で埋め込み、実行時に `app_data/construct/` へ書き出して `python -I texos_plan.py` で検査。
  Python は管理 env（voice → t2i）→ システムの順（`find_system_python` を pub(crate) に）。
  AI 呼び出しは AI カードと同じ `flow::run_ai_chat_stream_rec`（接続先・モデル・思考の設定がそのまま効く）。
  並べ方: 全カードの最下端＋余白の下・コンストラクタの x。枠（shapes・label「🏗 題名」）。カード→矢印の順に置き、
  1枚ごとに `mcp:changed`（touched）、最後に UNDO をまとめて（deleteRelations / delete / deleteNotes / deleteShapes）。
  ファイルは同名があれば「名前 (2)」（人のファイルを上書きしない）。レポートの冒頭1文＝結果（③で読み上げられる）。
  設定キー: `provider` `model` `endpoint` `card_model` `apply`（place/draft）`max_retries`（既定3）`prefix`。
  UI: 「自動化カードを追加 → 生成（AI・画像生成）→ コンストラクタ」。カードの札「🏗 コンストラクタ」・ボタン「▶ 構築」。
  設定画面は **AI カードと同じ `AiSettingsDialog`（`variant="construct"`）**（2026-10-23 ユーザー: モデルの入れ替え・調整を
  AI カードと同じ使い勝手に）。サーバー選択・↻取得のモデル一覧（能力の印つき）・思考・温度・追加パラメータがそのまま使える。
  モード欄とログ名は出さず、「追加の作法」（spec.system → 構築の要点の後ろに足す）・並べる AI カードのモデル・
  実行したら（並べる／案だけ）・差し戻す回数・レポートの名前を足した。
- **実機FB①（2026-10-23）**: ▶ 構築で `Cannot drop a runtime in a context where blocking is not allowed` の panic・
  ジョブが「作成中」のまま残った（もう一度押すと2つ目も同じ）。`run_ai_chat_stream_rec` を tokio ワーカー上で直接呼んでいた
  （AI カードは `thread::scope` で素の OS スレッドに逃がしている）。→ `construct.rs ask_ai` で同じく逃がす。

### 10.3 音声カードの応答 AI を AI カードと同じに（2026-10-23）

- ユーザー: 「音声カードも同じにしてください」（モデルの入れ替え・調整を AI カードと同じ使い勝手に）。
- 設定画面: 音声カードの設定の右上「🤖 応答 AI の設定…」→ `AiSettingsDialog`（`variant="voice"`）。サーバー
  （Ollama / LM Studio / OpenAI 互換）・↻取得のモデル一覧（能力の印）・思考・温度・追加パラメータ。キーは `ai_` 接頭辞
  （`ai_provider` `ai_model` `ai_endpoint` `ai_think` `ai_temperature` `ai_extra_params`）。他の設定はそのまま残す。
  音声カードの設定画面からモデル名・アドレスの欄は外した（置き場所を1つに）。
- 本体（`voice.rs FrontAi` / `agent_turn_once`）: Ollama は従来どおり `/api/chat` の `format`。OpenAI 互換は
  `/chat/completions` に `response_format: json_schema（strict）`。`openai` には思考を `reasoning_effort` で送る（既定 off → "none"）。
  400 等なら `json_object`・思考指定なしでもう一度。先読み（warm_up）は Ollama だけ。
- 実測（振り分け 10 問 `voice_live_demo`・会話 `voice_live_agent_conversation`）:
  - gemma3（Ollama・GPU）: 振り分け 9/10・1 問約 0.9〜1.2 秒。**会話（メモの聞き取り）は弱い** —「以上」の前に実行する・
    英訳の依頼を会話にする（system の形を変えても変えなくても同程度＝モデルの力）。v1.10 の調整は gemma4 で行った。
  - Strata（OpenAI 互換・思考オフ）: 振り分け **10/10**。ただし**入力の読み込みが遅い**（約 800 トークンで 6.3 秒・
    出力は 0.3〜1 秒）。会話キャッシュは「前回の要求がそのまま次の要求の先頭」のときだけ効き、効けば 0.6〜0.8 秒。
    聞き取り中は system が毎ターン変わるので効かず 13〜16 秒。
  - system を固定して状態を発話の頭へ移す案は、Strata の2ターン目を 2 秒にしたが3ターン目は 10 秒に戻り、
    gemma3 の正確さは変わらなかった → **採らない**（system は従来の形のまま）。
  - 合図の言葉の格上げ（`promote_think`）は「実行／待つ」でもコマンド名が無ければ会話と同じ扱いにした
    （gemma3 が「…よく考えて教えて」を action=実行・command=なし で返した）。
- **未決**: 窓口の既定モデル。速さなら gemma3（会話は弱い）、正確さなら Strata（遅い・裏で考えている間は順番待ち）。
  gemma4 は Strata と同時に GPU に載らない。LM Studio の中型モデル（Strata を止めたとき）も候補。
