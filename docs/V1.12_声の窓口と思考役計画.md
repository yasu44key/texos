## 1. 目的（2026-10-23 ユーザー）

AI カードやフィルタカードは**静的なカード**で、誰かが ▶ を押さないと動かない。これを**声で動かし、
声で返事が返る**ようにする。目標の手触りは**アイアンマンのジャービス／ナイトライダーの KITT**。

1. **ふだんは質問に答えるだけ** — 軽い AI で足りる。
2. **開発のときは要件に合わせてカード構成を提案し、作る** — 重い AI が要る。
3. **1 と 2 が継ぎ目なくつながる** — 話し相手は1人。裏で重い AI が考えている間も、おしゃべりは続けられる。

**もう1つのテーマ＝ローカルで完結すること**。応答も思考も構築も、この PC の中のモデルで回るのが基本形。
クラウドの Claude は**最後の手段**。

**Claude の立ち位置＝外のスーパーバイザー**。Claude（Claude Code／アプリ）は音声入力なども含めて
すでに揃った環境として TexoS の**外**にいて、MCP 経由で TexoS を見て・直し・開発を指揮する側
（v1.11 の MCP 接続はこのための口）。TexoS の**中**の窓口・思考役・構築役の連鎖には、原則として入らない。

## 2. 決定事項

### 2.1 ユーザー合意（2026-10-23）

1. **応答用 AI と思考用 AI を分ける**。応答用＝**gemma3（Ollama・GPU）**、思考用＝**Strata**（裏で常駐）。
   「Strata はずっと陰で動いているけれども、おしゃべりは続けられる」。
2. **GPU を分け合う**: Strata の `vram_reserve_mib` を 700 → **5000** に変更済み（§3.2）。
3. **Strata が起動していないときの代替＝LM Studio**（思考役・構築役の頭の両方）。
4. **ローカル完結が基本。Claude は最後の手段**。頭の順番は **Strata → LM Studio → Claude**（§5.1）。
   Claude へ落ちるのは自動ではなく、人が明示したときだけ。
5. **Claude はスーパーバイザー**（§1）。TexoS の外から MCP で監督・開発する立場で、中の連鎖の常連ではない。

### 2.2 推奨・仮置き（相談では推奨を示したが、明示の回答はまだ — §10 で確認）

1. **新しいカードは作らない。v1.10 の音声カード（op:"voice"）を「声の窓口」へ育てる**。
   マイクは1本・話し相手も1人なので、窓口が2枚あると継ぎ目ができる。v1.10 の会話エージェント
   （振り分け・聞き取り中・調停・割り込み・発話ログ）をそのまま土台にする。
2. **構築役の道具立て＝Claude Code CLI を裏で起動し、頭はローカル**（Strata、無ければ LM Studio）。
   道具は TexoS の MCP ＋フロー構築規約だけ（§5）。CLI は接続先をローカルにし、不要な通信を切って動かす
   （`delegate.ps1` と同じ）。CLI を使うこと自体がローカル完結の方針に合うかは §10 で確認。
3. **声で構造を変える前に3つの関門**（要件・案・実行）。関門の言葉は LLM でなく文字判定（§6）。
4. **読み上げは切り替え式・VOICEVOX 既定**（無ければ Windows 標準へ落とす）。1文ずつ読む（§7）。

> v1.10 §3.2 の「出力（効果）は閉じた2つだけ・構造は書き換えない」を、**承認を条件に一段広げる**改訂になる。
> 権能の限定（`オペレーション層設計.md §1-2`）を崩さないため、構造を変えるのは常に「人が声かボタンで
> 承認した案」だけとする。

## 3. 実測（2026-10-23・RTX 3090 24GB・RAM 64GB・16 スレッド）

### 3.1 Strata（`http://127.0.0.1:8080`・engine 0.1.40）

- モデル `swift-1.5-iq2_xs`（Swift-Qwen3.8-Flash-Next・MoE・文脈 131k・画像入力あり・思考モデル）。
- **OpenAI 互換（`/v1/chat/completions`）と Anthropic 互換（`/v1/messages`）の両方**で応答する。
  TexoS の AI カードは `provider:"openai"` でそのまま向けられる。
- 思考オフ（Anthropic `thinking:{type:"disabled"}`）で短い返事 **約0.5秒**。`reasoning_effort:"low"` で約1.3秒。
  思考ありの既定では約2秒（短い問い）。
- 出力 毎秒約59〜64トークン（専門家キャッシュ命中率 約0.89）。
- **要求は1本ずつ順番待ち**: `/metrics` の `live.state`（idle／reading／generating）と `live.queued`。
- **会話キャッシュ4枠**（`conversation_cache_slots: 4`）。同じ書き出しの会話は読み直しが省かれる。
- Web UI に MCP 接続の欄があるが、**効くのは Web UI のチャット内だけ**（API 経由の要求には効かない）。
- 起動 = `C:\Strata\Strata-main\run-swift-iq2_xs.bat`（設定 `strata-swift-iq2_xs.json`）。起動〜使える状態まで約20秒。

### 3.1b LM Studio（代替の思考役）

- **LM Studio 0.4.26** を導入済み（`%LOCALAPPDATA%\Programs\LM Studio`・CLI `~/.lmstudio/bin/lms.exe`）。
  API サーバー（`http://127.0.0.1:1234`）は普段は止まっている。`lms server start` で起動（数秒・モデルは読み込まない）。

- OpenAI 互換の口（`/v1/chat/completions`）は TexoS の AI カードが `provider:"lmstudio"` で対応済み。
- **Anthropic 互換の口 `/v1/messages` はある**（2026-10-23 確認）。モデル未読み込みで叩くと

- **`/v1/messages/count_tokens` は無い**（`Unexpected endpoint`）。CLI がこれを使う場面で困るかは P3 で確かめる。
- **未確認: 実際に生成させての応答**。確認時は Strata が GPU を使っていたので、モデルを読み込まずに口の有無だけを見た。
  モデル未読み込みの要求で勝手に読み込む（JIT）ことはなかった（存在しないモデル名で試したため、実在名での挙動は未確認）。
- **代替に入るのは Strata が止まっているとき**なので、Strata の約19GB が丸ごと空く。gemma3（2.88GB）と並べても
  qwen3.8-27b・gpt-oss-20b は載る。gemma-4-31b-qat（18.85GB）は文脈の分を足すと際どい。

## 4. 構成

```
        🎙 声 ／ ⌨ 状態パネルの欄 ／ 📄 会話へ送るカード
                     │
        ┌────────────▼────────────┐
        │ 声の窓口（音声カード op:"voice"）│  応答用 gemma3（GPU・約0.2〜0.4秒）
        │  毎ターン action を1つ選ぶ        │  人に向かって話すのはここだけ
        └──┬──────┬──────┬──────┬──┘
           │      │      │      │
         答える   動かす   考える   作る
         その場で  矢印の先  思考役へ  構築役へ
         返す     を発火    頼む     頼む
                (v1.10)    │        │
                           ▼        ▼
        Strata（思考オン）       Claude Code CLI（頭＝Strata）＋ TexoS MCP
        止まっていれば LM Studio   止まっていれば頭＝LM Studio／Claude は人が明示したときだけ
                           │        │
                           └── 結果 ─┘ → 付箋／ファイルに全文 → 窓口が要約して声で報告
```

### 4.1 窓口の action を増やす

v1.10 の action（コマンドを実行／続きを待つ／会話／読み上げを止める／実行を中止する／会話をリセットする）に2つ足す:

- **考える**（`think`）: その場で答えるには重い問い（資料を読み込む・比較する・設計を考える）。
  窓口は「考えておきます」と返し、Strata に頼む。結果は付箋に全文、声では要約。
- **作る**（`build`）: カード構成を作ってほしいという依頼。§5 の構築の流れに入る。

「どちらに回すか」を決めるのも窓口（gemma3）。迷ったら「答える」に倒し、人が「ちゃんと考えて」と言えば「考える」へ。

### 4.2 窓口は Strata の混み具合を見て話す

- Strata は1本ずつ処理するので、構築中に「考える」を頼むと**後ろに並ぶ**。
  窓口は頼む前に `/metrics` の `live.state` と `live.queued` を読み、「前の件を考え中です。2件待ちです」と言える。
- 状態パネルに Strata の状態（待機中／読み込み中／生成中／順番待ち N 件）を出す。黙っている理由が人に見える。
- **Strata が止まっている**（`/health` が応答しない）とき: **LM Studio**（`/v1/models` が応答する）へ回す。
  窓口は「いまは LM Studio で考えます」と一言添える（遅さや質の違いの理由が人に分かる）。
- **両方とも止まっている**とき: 「考える」「作る」は受け付けず、「思考役が止まっています」と答える。
  Claude へは**自動では落とさない**（人が「Claude で」と言ったときだけ・§5.1）。
  「答える」「動かす」は gemma3 だけで続く。
- LM Studio のサーバーが止まっていてもアプリが入っていれば、`lms server start` で起こせる（P3 で検討・勝手に起動するかは §10）。

### 4.3 会話の文脈の渡し方

- 窓口の会話履歴（v1.10: 直近 6,000 字）は窓口のもの。Strata へは**依頼文＋要件メモ＋必要な抜粋**だけを渡す
  （履歴を丸ごと渡すと、会話キャッシュが毎回外れて遅くなる）。
- 窓口のシステムプロンプトと履歴の**先頭を毎ターン同じに保つ**（Ollama 側もキャッシュが効く）。

## 5. 構築役（作る）

### 5.1 誰が組むか

- **Claude Code CLI をヘッドレスで起動**する（`claude -p`）。`C:\Users\yoshi\dev\strata\delegate.ps1` と同じ形で、
  `ANTHROPIC_BASE_URL=http://127.0.0.1:8080` と各 `ANTHROPIC_*_MODEL` に Strata のモデル名を入れ、
  `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` などで外への通信を切る。
- **頭の順番＝Strata → LM Studio → Claude**（カード設定 `builder_backend: "auto" | "strata" | "lmstudio" | "claude"`・既定 auto）。

  | 順 | 頭 | 条件 | 接続先 |
  |---|---|---|---|
  | 1 | Strata | `/health` が loaded | `http://127.0.0.1:8080` |
  | 2 | LM Studio | Strata が止まっている・`/v1/models` が応答 | `http://127.0.0.1:1234`（`/v1/messages` あり・§3.1b） |
  | 3 | Claude | **人が明示したときだけ**（「Claude で作って」・設定 `claude`） | 環境変数を差し替えずに起動 |

  auto は 1 → 2 までしか自動で選ばない。**ローカルで完結しないときは、窓口が「ローカルの思考役が使えません。
  Claude で作りますか？」と聞き、関門と同じく文字判定かボタンで承認**されたときだけ 3 へ進む。
- LM Studio にも Anthropic 互換の口があるので、**Strata と LM Studio のどちらでも同じ CLI 起動で済む**（接続先とモデル名だけ違う）。
  CLI を使わずに **TexoS 内で道具呼び出しのループを回す**（OpenAI 互換の tools で MCP と同じ関数 `*_in(&Project)` を直接呼ぶ）案は、
  CLI がローカル完結の方針に合わないと決まった場合（§10-9）の代わりとして残す。
- 規約と MCP はエージェント向けに整備済み（v1.11）なので、構築の作法を新たに書く必要はない。
  規約 §2-2 の「案を作る終端と実行する終端のあいだに実身を挟む」もそのまま当てはまる。

### 5.2 権限を絞る

- `--mcp-config` で `scripts/texos_mcp.py` だけを渡す。`--allowedTools` は **TexoS の MCP の道具＋規約を読む Read** のみ。
  **Bash・任意のファイル書き込み・Web は許可しない**。`--max-turns` で上限。
- MCP 側の削除は `disconnect`（ソフト削除・UNDO で復活）だけ。MCP での変更は UNDO に積まれる。

### 5.3 構築の流れ

1. **聞き取り**: 窓口（gemma3）が要件を聞き、**要件メモの付箋**に書き出す（v1.10 の「聞き取り中」と同じ仕組み）。
   → **関門①**「この内容で案を作ります。よろしいですか」。
2. **案を作る**: 構築役は**まだカードを置かない**。案（カードの種類・名前・矢印・設定）を**案の付箋**に書くだけ。
   → 窓口が「カード3枚、○○→△△→□□で作ります。作りますか？」と要約して読み上げる → **関門②**。
3. **組む**: 承認されたら、案の付箋どおりに MCP で組む（要件メモ・案の付箋と同じ場所の近くに置く）。
4. **試す**: 試し実行（dryrun）。結果を窓口が報告。外部プログラム・Web を含むフローの本番実行は **関門③**。
5. **直す・戻す**: 「戻して」＝UNDO。「○○を変えて」＝案の付箋を直して 2 からやり直し。

- 進み具合は `--output-format stream-json` を読み、状態パネルに出す。報告は v1.10 の調停（通常＝話の切れ目）。
  構築の途中経過は**低い優先度**（溜めておき、聞かれたら話す・v1.10 §3.4 の未着手分をここで作る）。
- 作業記録: 1回の構築ごとに `app_data/voice/builds/<日時>/`（依頼文・stream-json・最終結果）。人が読む要約は発話ログへ。

## 6. 承認の仕方

- **関門の判定は LLM に任せない**。v1.10 のスーパーバイザー語と同じく**決まった言葉の文字判定**
  （「作って」「OK」「お願い」／「やめて」「待って」）。設定で登録・変更できる。
- **同じ判断をボタンでも**: 状態パネルに［作る］［やめる］。声が聞き取れなくても進められる。
- **返事が無ければ進めない**: 案の付箋は下書きのまま残る（タイムアウトで破棄もしない）。
- **何を承認したかを記録**: 発話ログに「関門②承認：案の付箋 ○○（版）」。承認後に案の付箋が書き換わっていたら組まない。

## 7. 読み上げ

- **1文ずつ読む**: 応答のストリームを「。！？」と改行で区切り、区切れた文から `say` に回す。最初の文は1秒前後で話し始める見込み。
- **読み上げの常駐化**: 今は1回ごとに PowerShell を起動している（`voice_server.py` の `SPEAK_PS1`）。
  1文ずつ呼ぶと起動待ちが積み重なるので、音声プロセスの中で常駐させる。
- **エンジン切り替え**: `tts_engine: "voicevox" | "windows"`。VOICEVOX はこのマシンに導入済み
  （`%LOCALAPPDATA%\Programs\VOICEVOX`）。エンジン（既定 `localhost:50021`）が起動していなければ Windows 標準へ落とす。
  VOICEVOX は GPU 版だと VRAM を使うので、**CPU 版で動かす**前提（§8）。
- **割り込み**: 読み上げ中に人が話し始めたら、読み上げを止める（v1.10）に加えて**生成も取り消す**。
  会話履歴には**実際に読み上げた所までだけ**を残す（聞いていない内容を話した前提で会話が進むのを防ぐ）。

## 9. 段階

- **P1**: 窓口の応答用を gemma3（GPU）に、`think`（考える）action を足して Strata へ。Strata の状態を状態パネルに表示。
  Strata が止まっているときの言い方。

  手本プロジェクトで「規約どおりに組めるか」を確かめる（iq2_xs と LM Studio の候補モデルで質が足りるか）。
  Claude は最後の手段なので、質の基準は**ローカルの頭で通ること**に置く。
- **P4**: 低い優先度の報告（溜めて聞かれたら話す）・構築役の頭を声で選ぶ・案の差分表示。
