## 0. V2.0 着手前に決めておくこと（2026-06-12 整理）

確定済みの前提: 転送の3層モデル・エクスポート＝コミット原則・サブプロジェクトの意味論は
`docs/サブプロジェクト検討結果.md`、オートフローは `docs/V1.3後半_オートフロー設計.md` の
★確定方針。残っている構造判断は以下の6点。

1. **グループ／コンテナ／サブプロジェクトの棲み分け** — **決定済み（2026-06-12）**:
   論理グループを「グループカード（kind='group'）＋ relations kind='group' エッジ」で導入。
   図形グループは視覚専用として現状維持。詳細 → `docs/カード統一モデル検討結果.md` §2
2. **付箋（notes）の最終形** — **決定済み（2026-06-12）**: 付箋テーブルは廃止し、
   カードの派生（kind='note'）に統合。notes.id を vid として維持し relations 無変更で移行。
   図形は当面維持・V2.0で再判断。詳細 → `docs/カード統一モデル検討結果.md` §1
3. **マルチプラットフォーム方針** — **決定済み（2026-06-12）**: プロトコル指向・
   構造単純化を設計原則に明文化（実身・仮身・関係の3概念）。Win32 依存は1モジュール境界に
   隔離。データはプロジェクト自己完結（.texos内）優先。詳細 → 同 §3
4. **ストレージ衛生の先行実施** — **決定済み（2026-06-12）**: 正規化ツールは
   **付箋廃止（カード統一移行）の後に**作成する。運用3日でデータが僅少のため、
   付箋移行に凝った移行ツールは作らない（旧データは手動削除 or 正規化ツールでの
   強制削除も許容）。順序: 付箋移行 → 正規化ツール → trash 掃除・削除ブラウズ
5. **git スナップショット** — **決定済み（2026-06-12）: 保留に降格**。
   個人ユースは兄弟プロジェクトのフォークで十分。CAS（実身の内容履歴）＋
   ソフトデリート＋UNDO永続化で安全網は既に三重にある。
   将来、研究用途等で「キャンバスの時間旅行」（DB側の履歴）が必要になったら、
   「DBのテキストダンプを .texos/history に保存しローカル git に自動コミット」方式で再検討
   （SQLite バイナリを直接 git に入れない。CAS は不変なので履歴管理の対象外でよい）
6. **OSS公開・プラグイン基盤** — **方針決定（2026-06-12）**: 商標は問題なし（確認済み）。
   順序: ①個人で使い倒す → ②知り合いに使ってもらう → ③評判が良ければ OSS 化を検討。
   ソースの GitHub アップ（次セッション①の git init が起点）を済ませておけば、
   OSS 化時の作業はほぼドキュメント（Note 記事）のみ。
   サンドボックス／配布形式／JSON Schema フォームは③の判断時点で着手すれば足りる

## 1. ピックアップ操作（アイデアメモ 9, 10）

キャンバスから他アプリへのドラッグアウト、およびキャンバス内の他カードへのドロップ。

> **2026-06-12 更新**: サブプロジェクト検討の結果、本項目は**先行実装に昇格**。
> 方針は `docs/サブプロジェクト検討結果.md` §7（エクスポート＝コミット原則で
> TEMP孤児問題を解消。クリップボード持ち出し→OLEドラッグアウトの順）。

- **v1.2 での代替**: 仮身の右クリック→「コミットしてプロジェクトフォルダで表示」
  （実身化して Explorer でフォーカス。既定のアプリ／アプリを選択に次ぐ第3の開き方）。
  実身は既存の「フォルダで表示」。そこから先のドラッグは Windows 任せ。
  ユーザーの手間は増えるが安全・確実で、TEMPへの孤児コピーも作らない。
- **本実装する場合**:
  - OLE ドラッグソース（`DoDragDrop` + `IDataObject` の CF_HDROP 実装）が必要
  - 通常ドラッグはカード移動に割り当て済みのため、長押しドラッグ等の操作設計が必要
  - 渡すパスは「コミット済みなら実ファイル、仮身なら一時実体化したコピー」
  - 10（カードへのドロップ）はアプリ内で完結するので、ピックアップ状態（持ち上げ→
    別カードへ落とす）の UI を作れば OLE は不要。リンク作成 or 添付の意味論を要設計

## 2. カードのグループ化／コンテナ（アイデアメモ 1）

- 「コンテナ＝名前のある入れ物」は内包プロジェクトと概念が重複する。
  整理してから着手する: 見た目だけの軽量グループか、ナビゲーション単位か。
- 有力案: relations の `kind='group'`（スキーマに予約済み）でグループ関係を表現し、
  まとめドラッグ（v1.2 実装済み）をグループ単位の永続選択に拡張する。
- コンテナオブジェクト（ドラッグインでグループ化）を作るなら、
  プロジェクトカードとの見た目・操作の差別化が必須。

## 3. キャンバス内実行アプリ／ウィジェット環境（アイデアメモ 将来案）

- Python ライクな言語または Wasm でミニアプリ（時計・電卓・ミニブラウザ・
  スコープ等）をカードとして埋め込む。
- 既存の `codec_ref`（Wasm コーデック）構想と方向性が整合。
  ui_contract の公開 API 化（V1.1 候補 7）はこの布石。
- 前提課題: サンドボックス（セキュリティ）、開発環境、配布形式。
