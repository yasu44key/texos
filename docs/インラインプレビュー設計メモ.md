# インラインプレビュー拡充 設計メモ（v1.4.x「UI仕上げ」予定）

起票: 2026-06-20 / ユーザー承認のロードマップ。**今回は未実装、次回以降の覚書。**
背景: v1.3.9 で「ダブルクリック＝閲覧（非破壊）」に統一した結果、Word/Excel/その他
ファイルもキャンバス内でプレビューしたくなった（エクスプローラのプレビューペイン相当）。

## 方針（確定）

TexoS の既存インラインプレビュー（画像・PDF・動画・テキスト）は **DOM に描画し、カードと
一緒に動く**のが強み。この路線を保つ。**タイプ別レンダラのレジストリ**にして、必要な形式から
都度足す（「特殊カードは都度作成」の方針どおり）。すべて**読取専用・非破壊**（`read_view_text`
同様に id で中身を取得、コミットしない）。

### 採用ロードマップ：**まず HTML 化 → 次に PDF 化**（ユーザー決定）

1. **第1階層＝DOM に直接描く（HTML 化・本命。カードと一緒に動く）**
   - docx → mammoth.js（docx→HTML）
   - xlsx/csv → SheetJS（→HTML テーブル）
   - markdown → レンダリング
2. **第2階層＝PDF に変換して既存の PDF パネル（MediaPreview）で見る（広く薄くカバー）**
   - pptx/odt/doc 等 → LibreOffice headless（`soffice --convert-to pdf`）→ MediaPreview に流す
   - LibreOffice 未導入なら **一時的閲覧にフォールバック**
3. **最終フォールバック** = 既存の「一時的閲覧」（既定アプリで読取専用・閉じると破棄）

### 不採用：IPreviewHandler（エクスプローラのプレビューそのまま）
忠実度は最高だが**ネイティブ子ウィンドウ**に描くため、無限キャンバスのズーム・パン・カード追従・
z 順と喧嘩する。統合コストが高く、DOM 路線の利点（カードと一緒に動く）を失う。よって見送り。

## 実装メモ（着手時）

- レンダラ選択は MIME/拡張子で分岐（既存 ObjectCard の expanded 分岐に追加）。
- 中身取得は id ベースの非破壊コマンド（テキストは `read_view_text` を流用、バイナリは
  `get_media_data_url` 等の既存経路、または新規 `read_view_bytes`）。
- 第2階層の変換結果は temp（`texos_view/preview`）にキャッシュし、mtime 比較で再利用
  （materialize_view と同じイディオム）。CAS には焼かない（プレビューは ephemeral）。
- JS ライブラリ（mammoth / SheetJS）はフロント依存に追加。バンドルサイズに注意。
- 最初の一手は docx（mammoth）か xlsx（SheetJS）のどちらか1形式で感触を見る。
