## 1. 目的（2026-10-11 ユーザー）

TexoS に**リアルタイムの反射神経**を入れる。常に何かを監視し、イベントに対して適切な反応を
即座に出す仕組み。**音声認識**と**タイミングの良い音声による報告**はその最初の一例。

対応表の空き枠を埋める位置づけ:

- 海馬 = 空間キャンバス（記憶・世界モデル）
- 動機系 = pull（要求駆動）
- 前頭前野 = リクエスタ（計画・2.0）
- **脳幹・脊髄 = 反射層（今回）** — 大脳（pull フロー）を通らずに即応する経路

反射は「考えない」。判断が要るものは反射で**フローを起動して大脳へ回す**だけ。

## 2. 決定事項（2026-10-11 ユーザー合意）

1. **裏に回る常駐型（カード無しで常時動く反射層）は 2.0 以降**。
2. 今の実験は**カードを置く方式**。**カード上でオン／オフ**できる。
3. **プロジェクトごとに置く／置かないを決められる**（置かなければ反射は無い）。

→ 既存の op カード（タイマ／ウォッチャ）と同じ流儀に乗る: kind='op'・センチネル実身・
**停止状態で生成し「▶ 稼働開始」で動く**（`paused`）。プロジェクトを閉じたら止まる
（op スケジューラが現在のプロジェクトしか見ないのと同じ原則）。

## 3. 構成

### 3.1 音声カード（新 op 種別 `op:"voice"`）

- 稼働開始 = TexoS が**音声プロセス**（`python/voice_server.py`・後述）を子プロセスとして起動。
  停止／カード削除／プロジェクトを閉じる／アプリ終了 = プロセスを止める。
- **マイクは排他**（`v1.5_並行実行・資源・プロセス通信設計.md` の「音声入力デバイス=セマフォ1」）。
  稼働中の音声カードはアプリ全体で1枚。2枚目の稼働開始は理由つきエラー。
- カード表示: 状態（停止／待機／聞き取り中／文字起こし中／報告中）・入力レベル・直近の発話。

### 3.2 感覚器 → 効果器（反射弓）

- **入力（感覚）**: 発話テキスト（`utterance`）・ユーザーが話し中か・TexoS のジョブ完了／失敗
  （既存の `job:done` / `job:failed` イベント。`flow_run.rs` で発行済み・現在は画面向けのみ）。
- **出力（効果）は閉じた2つだけ**: ①**発火**（req 矢印の先を終端に run_flow＝ジョブ台帳に乗る）
  ②**声で報告**。構造は書き換えない（オペ層 §1-2 権能の限定）。
- ~~反射弓に LLM を挟まない~~ → **改訂（2026-10-11 ユーザー方針）: コマンドの判定は LLM に任せる**。
  文字照合は「メモ“を”して」「目もして（聞き違い）」で外れる。VoiceAssistantAgent と同じく全文を
  ローカル LLM に渡し、**選択肢を閉じた enum（矢印の先のカード名＋none）で1つ選ばせ、中身も返させる**。
  実測（gemma4:latest・載せたまま）0.5〜0.9 秒・実機の発話ログ6文で外れ0。
  **スーパーバイザー語（止める言葉）だけは文字判定のまま**（速さと確実さが要る＝ここは反射）。

### 3.3 音声コマンド = req 矢印に付ける言い回し

- 音声カードから出る **req 矢印の attrs に `say: ["要約して", "まとめて"]`**。
  省略時は**発火先カードの名前**が言い回しになる。
- 照合は VoiceAssistantAgent の流儀（空白と `、。！？!?` を除去）で**含む一致**。
  複数一致は最長一致、どれにも一致しなければ何もしない（反射は黙る）。
- ＝**音声コマンドの語彙はキャンバス上に見える**（構築時に人が用意した選択肢から選ぶだけ）。

### 3.4 タイミングの良い報告（調停）

報告は即座に話すのではなく、優先度で出しどころを決める:

- **緊急**: すぐ割り込む（読み上げ中でも差し替え）。既定 = 発火したフローの失敗。
- **通常**: ユーザーの発話が終わり、一定時間静かになってから話す。既定 = 発火したフローの完了。
- **低**: 溜めておき、聞かれたら話す（「報告は？」等）— Phase 3 以降。

報告中にユーザーが話し始めたら読み上げを止める（VoiceAssistantAgent の割り込みをそのまま使う）。
**話す主体とマイクの持ち主を音声プロセス1つに揃える**のは、調停に「話し中」を使うため
（既存 builtin `speak` は投げっぱなしで調停できないので、報告には使わない。フロー内の読み上げ用に残す）。

報告範囲は spec の `report: "fired"(既定) | "all" | "none"`。文面はフローのラベルから
（「要約、終わりました」「要約で失敗しました」＋エラー先頭）。結果テキストの読み上げは後回し。

### 3.5 TexoS ⇄ 音声プロセスの取り決め（標準入出力の JSON 行）

ポートを開けず、子プロセスのパイプで通す（イベントは押し込み＝見回り不要）。

- 音声プロセス → TexoS: `ready` / `state{state}` / `speech_start` / `utterance{text}` / `level{rms}`（間引き）/
  `speaking{id, text}` / `spoken{id, interrupted}` / `error{message}`
- TexoS → 音声プロセス: `say{id, text, priority}` / `hush` / `pause` / `resume` / `stop`
  （しきい値などの設定変更は音声プロセスを起動し直して反映する）

VoiceAssistantAgent の CLAUDE.md §7 が「まだ IPC 契約になっていない」としていた部分の答え。

### 3.6 音声プロセス（`python/voice_server.py`）

- 中身は VoiceAssistantAgent の `record()`（無音区切り・割り込み検出・冒頭保持）・`stop_playback()`・
  faster-whisper・`speak.ps1`。**`conversation.py`（会話）は使わない**（会話は大脳側＝AI カード）。
- Whisper は起動時に1回ロード。人向けの print は stderr へ、stdout は JSON 行専用。
- Python 環境は本体外（可搬シム規約）。

## 4. 段階

- **P1**: 音声カード（op:"voice"）＋稼働／停止＋音声プロセス起動・終了＋発話をカードに表示。
- **P2**: req 矢印の `say` 照合 → 発火。
- **P3**: ジョブ完了／失敗の報告＋優先度による調停。
- **P4**: しきい値・無音時間・入力デバイスをカードの設定で調整（実行中に反映）。

## 5. 決定（2026-10-11 ユーザー回答）

1. **音声コマンドの発火回数に制限なし**: 音声カードの `max_fires` 既定 = 0（無制限）。
   暴走止めは `min_interval` だけ残す（人が話す速さなら当たらない）。
2. **発話の中身を発火先のフローに渡す**: 「メモして ○○」「要約したカードを作って」のように、
   言い回し（コマンド）＋中身（引数）で使う。発話全文と、言い回しを除いた残り（中身）を渡す。
   渡し方 = 音声カードの書き出し先ファイル（プロジェクト相対・固定名上書き。既定 `音声/発話.txt`）
   を発火の直前に書き、フロー側はそのファイルの窓カードを入力にする（既存の仕組みだけで済む）。
3. **Python 環境は TexoS に完全に組み込む**: VoiceAssistantAgent とは切り離す。プログラムは
   `python/voice_server.py`（TexoS リポジトリ内・t2i と同じくビルドに埋め込み、起動時に app_data へ
   書き出す）。環境は uv 管理 env `runtime/envs/voice`（faster-whisper・sounddevice・numpy。torch 不要）。
   Whisper モデルは `app_data/voice/models` に初回自動取得。
4. **マイク競合は録音カードを優先**: 録音ジョブが始まったら音声プロセスはマイクを手放し（一時停止）、
   録音が終わったら再開する。
5. **スーパーバイザー語（矢印なしで常に効く言葉）を持つ**: 既定「止めて」（読み上げ中断）など。
   一覧はカードの設定で**登録・変更できる**ようにする。
