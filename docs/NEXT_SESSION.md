## v1.3.4（2026-06-14）クリップボード持ち出し（CF_HDROP）— 実装済み・実機未確認
方針: v1.3.3 のオートフロー実機確認を進めつつ、ユーザー最優先機能としてクリップボードの
「出す側」を先行実装。実験的リビジョンとして刻む（HDROP=v1.3.4 → 画像DIB=v1.3.5 →
安定したら v1.4 確定）。
- 新規 `src-tauri/src/clipboard_out.rs`: 生 Win32 で CF_HDROP を書き込む `set_clipboard_files`
  （DROPFILES + ダブルNUL終端のワイド文字パス列）。`Win32_System_DataExchange` feature 追加。
- `copy_objects_to_clipboard(ids)` コマンド: 各IDを実ファイルパスに解決し HDROP へ。
  未コミット仮身は `commit_object_inner(false)` で実体化（エクスポート＝コミット原則）。
  URL/フィルタ/ドロップは警告スキップ、folder/project は実フォルダパスを採用。
- フロント: 選択カードに **Ctrl+C**（テキスト編集中は奪わない）＋右クリック
  「クリップボードにコピー（ファイル）」、バルクメニューにも追加。コミットで signal が
  変わるため `refresh()`。スキップ/エラー時のみ結果ダイアログ、全件成功は無音。
- 検証済み: cargo check / tsc 通過。**実機確認は未実施**。
- **内部ペースト（Ctrl+V でファイル）は案内ダイアログのみ**（2026-06-14 決定）:
  クリップボードがファイル（CF_HDROP）のとき内部に取り込まない。理由は「実身のコピーは
  実身になる」という一般原則と仮身モデルの衝突＋複雑さ。`clipboard_out::clipboard_has_files`
  ＋ `paste_clipboard` が kind="files" を返し、フロントは「D&D で仮身化を」「外部へは
  Ctrl+C」の案内を出すだけ。画像/テキスト/URL の貼り付けは従来どおり優先。
  （仮身複製として貼る案は概念に反するため不採用）
- 次（v1.3.5）: 画像カードに CF_DIB を併設して他アプリへ画像として直貼り（同一 Win32
  セッションで HDROP と複数形式を同時セット）。

  `resolve_view_conn` が ①own committed → ②兄弟committed（同real_idの生きた実身）→
  ③origin_path → ④CAS → ⑤フォーク元チェーン の順で解決し、種別を `view_source` として
  list_objects が返す。**薄赤シグナル**: 仮身で origin があるのに CAS フォールバック

  （タイムマシン、従来どおり）。CASへのmaterializeはCASチェーンからのみ（ハッシュ整合維持）。
  ※10番の「同フォルダ実身の仮身複製→編集で別バージョン」は②の兄弟解決で自然に成立。
- **④ クリップボード貼り付け** → 対応済み（arboard）。Ctrl+V（ビューポート中央）と
