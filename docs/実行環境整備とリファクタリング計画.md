## WS2: Python 実行環境の TexoS 管理化（v1.4.27）

### 背景・問題
- 現状 `detect_python()`（旧 lib.rs:6914）は PATH の `python`/`py`/`python3` を試すだけ。
  torch/diffusers が無いと「pip install してください」とユーザー任せ＝**個々のPC環境依存**。
- 開発時は venv を使わず開発機のシステム Python に直接入れた（ディスク肥大の懸念から）。
  これを一般化し、**TexoS が自前で環境を構築・所有**する。

### 設計判断: uv を採用する
**TexoS が uv（Astral製・MIT/Apache-2.0・単一exe）を自動ダウンロードし、uv に
Python本体の取得と venv 構築・パッケージ導入をさせる。**

理由:
- システム Python 不要（python-build-standalone の CPython を uv が取得）＝ Windows バージョンや
  ユーザーの Python 事情から独立。**Ollama の自動導入と同じ「アプリが面倒を見る」思想**。
- uv のグローバルキャッシュはハードリンク共有なので、将来 env が増えても**ディスク肥大しない**
  （venv を避けた当初の懸念に直接答える）。
- 単一バイナリ（~35MB）で導入が単純。winget 不要、`%APPDATA%` 配下に置くだけ。
- WS3（可搬性）: uv は mac/Linux 同一コマンド体系。OS依存を uv の下に隠せる。

### ディレクトリ構成（`%APPDATA%\com.yoshi.texos\` 配下・既存 whisper/t2i と同居）
```
runtime/
  bin/uv.exe            … TexoS が GitHub Releases からDL（バージョン固定）
  python/               … uv管理の CPython（UV_PYTHON_INSTALL_DIR）
  cache/                … UV_CACHE_DIR（ハードリンク共有の要）
  envs/
    t2i/                … torch+diffusers 等（現 t2i デーモン用）
    （将来 envs/<用途> を追加。キャッシュ共有で増分は小さい）
```

### 実装（runtime/python.rs 新設）
1. `ensure_uv()` — uv.exe が無ければDL（進捗イベント発行・whisper導入UIの流儀を踏襲）。
2. `ensure_env("t2i", requirements)` — `uv python install 3.12` → `uv venv` →
   `uv pip install`（torch は WS3 のスペック判定で index-url を切替: cu124 / cpu）。
3. `detect_python()` の解決順を変更:
   **① runtime/envs/t2i の管理env** → **② 従来のシステムPython（依存が揃っている場合のみ）**
   → ③ どちらも無ければ t2i 設定UIに「環境を構築する」ボタンを出す。
   ②を残すのは**開発機や既存構築済みPCを壊さないため**（ユーザー指示「すでに構築した環境を
   確認して整える」）。config.json に `python_env: "managed" | "system"` を追加し明示切替も可。
4. t2i_ensure_server / T2iSetupDialog を新解決順に対応（「pip install してください」という
   エラー文言は「ワンクリック構築」ボタンに置き換える）。

### 環境の要件定義はコードに埋める
`runtime/envs.rs`（または python.rs 内の定数）に用途→requirements のテーブルを持つ:
```rust
("t2i", &["torch", "diffusers", "transformers", "accelerate", "safetensors", "pillow", "huggingface_hub"])
```
t2i_server.py 側の import と一致させること（現 detect_python のチェック内容が正）。

## WS3: PCスペック検出と推奨構成（v1.4.28）—「動かす」を優先

### 方針
初回構築時にスペックを検出し、**確実に動く構成**を既定で選ぶ。上位構成は「選べる」が既定にしない。

### 検出（runtime/spec.rs 新設）
- **GPU**: `nvidia-smi --query-gpu=name,memory.total --format=csv,noheader` が成功→NVIDIA
  （VRAM MB取得）。失敗→GPUなし扱い（AMD/Intel は当面 CPU 扱い＝動くことを優先）。
- **RAM**: sysinfo クレート（または GlobalMemoryStatusEx）。
- 検出結果は t2i 設定画面と AI 設定画面に表示（ユーザーが根拠を見られるように）。

### 推奨テーブル（初期値・実測で調整）
| 判定 | torch | 既定モデル | 備考 |
|---|---|---|---|
| NVIDIA VRAM ≥ 12GB | cu124 | SDXL | SD1.5も選択可 |
| NVIDIA VRAM 6–12GB | cu124 | SD1.5 fp16（実機検証済 ~2GB） | SDXLは注意書き付きで選択可 |
| NVIDIA VRAM < 6GB / GPUなし | cpu | SD1.5（低ステップ既定） | 「時間がかかります」表示 |

- Ollama 側の推奨モデル（gemma3 系のサイズ選択）も同じ spec.rs を参照して提示（努力目標）。
- torch の index-url 切替は WS2 の `ensure_env` に spec 判定を渡すだけ。

### 可搬性（将来のOS非依存・ユーザー指示3項）
- **今号で実装はしない**が、以下を守って書く:
  - OS 分岐は `runtime/` 内に閉じ込める（`#[cfg(windows)]` を runtime の外に漏らさない）。
  - パスは全て app_data 起点の相対構成（システムディレクトリ・レジストリに書かない）。
  - uv / nvidia-smi の呼び出しはコマンド名を定数化（mac/Linux 対応時に差し替え点が一目で分かる）。
